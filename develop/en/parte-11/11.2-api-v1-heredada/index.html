    API v1 (legacy)¶

    The Pandora ITSM 1.0 API is still alive for compatibility. It is not a REST API: it is an HTTP call to include/api.php with an operation (op) and a list of comma-separated parameters. It returns CSV by default, XML on request and, in some calls, JSON.

    If you are starting an integration, use the API v2 in chapter 11.1. This API is only maintained for old scripts and integrations that already speak its dialect. The source of truth is include/api.php and include/functions_api.php; whatever is not in the dispatcher does not exist, no matter how much old documentation mentions it.

    What it is and how to call it¶

    The base URL is the console URL followed by include/api.php:

    https://<Console_web_URL>/pandoraitsm/include/api.php?<parameters>

    The common parameters are:

    Parameter Required What it does
    user Yes Pandora ITSM user running the call and subject to ACLs.
    user_pass Yes, except bearer token User password.
    pass Only if api_password is configured API-specific password.
    op Yes Operation to run.
    params Depends on the operation Operation parameters, separated by token.
    token No Separator for params; comma (,) by default.
    return_type No csv (default), xml or json depending on the operation.
    info No info=version returns the version without authentication.

    The information call needs no user, password or authorised IP:

    …/include/api.php?info=version

    It returns a string similar to:

    Pandora ITSM Enterprise Edition 5.0.109 Build 260603 MR109

    An unknown operation does not return a descriptive error: the dispatcher sleeps for 15 seconds and ends without a body. If a script hangs, check the op name first.

    Authentication¶

    API 1.0 chains several checks. Every call except info=version goes through the IP list and user authentication.

    IP list¶

    The list is configured under Setup → Setup → General setup, field List of IP with access to API (token api_acl). By default it only allows 127.0.0.1.

    It accepts addresses separated by commas, spaces or line breaks, and an asterisk as a wildcard: 192.168.7.* or *. The code uses a regular expression, so the wildcard can also match part of an address. Opening the API to * is convenient for testing and a bad idea in production.

    API password¶

    If api_password is not empty, it must be sent in the pass parameter. If it is empty, the check is skipped.

    The password travels unencrypted. If you use this method, the call must go over HTTPS; over HTTP anyone listening on the network can see it.

    User and password¶

    user and user_pass are required in every call that does not use a bearer token. There is no way to disable this check: the API password is a second factor, not a replacement.

    Bearer token¶

    You can also authenticate with the HTTP header:

    Authorization: Bearer <token>

    The token is compared with the api_key field of the user named in user. The IP list still applies. If the header is present, the API does not use user_pass or pass; if the token does not match, the response is 401.

    Example with curl:

    curl -k \
  -H "Authorization: Bearer $PITSM_API_TOKEN" \
  "https://192.0.2.10/pandoraitsm/include/api.php?user=admin&op=get_groups&return_type=xml"

    If authentication fails, the API responds 401 with no body. There is no different error message for a missing user, a wrong password or an unauthorised IP.

    Call format¶

    params is an ordered list. The default separator is a comma, but it can be changed with token:

    …&op=create_workunit&params=1,Description,0.5,0,1,1
…&op=create_workunit&token=|&params=1|Description|0.5|0|1|1

    Two conventions recur in ticket calls:

    • A comma inside a value is written as :::.
    • A space is encoded as %20 in the URL.

    For example, Doe, John is sent as Doe:::%20John. Not every function reverses the substitution; those that support it apply it to the title, description or name, depending on the case.

    return_type accepts csv (default), xml and, only in calls that implement it, json: tickets, work units, statuses, groups, users, priorities, fields, types and ticket count.

    Successful responses are not always 1: many calls return the created identifier, a 0 or a -1. ACLs are checked inside each function and may log an audit entry before exiting without a body.

    Functions¶

    Each call has its own entry. Parameters are shown in the exact order of params; a parameter marked as required must always be present, even if the format allows it to be empty.

    get_login¶

    Checks that credentials are valid. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_login

    Returns: 1 if authentication is correct. On failure, the call has already returned 401 before reaching here.

    create_user¶

    Creates a user and assigns a group and profile. Parameters: user (required), group (required), profile (required), email (optional), password (optional; if empty, the calling user's name is used), description (optional), real name (optional), external (0 or 1).

    …/api.php?user=admin&user_pass=adminpass&op=create_user&params=jorge,3,4,jorge@example.com,userpass,description,Jorge%20Surname,1

    Returns: 1 on success, 0 on failure. Requires UM permission. external=1 creates level -1 (Standalone); external=0 creates level 0 (grouped).

    get_incidents¶

    Lists tickets visible to the user. Parameters: search string, status, group (required; 1 for all), priority, inventory, owner, creator, ticket id and Pandora inventory id.

    …/api.php?user=user&user_pass=userpass&op=get_incidents&params=day,-10,1,-1,0,admin,user1

    Statuses: 0 all, 1 new, 2 unconfirmed, 3 assigned, 4 reopened, 5 pending closure, 6 pending third party, 7 closed, -10 all except closed. Priorities: 10, 0, 1, 2, 3, 4, -1.

    Returns: CSV, XML or JSON. Internal limit of 5,000 tickets. A non-administrator only sees tickets they own or created.

    user_exists_in_group¶

    Checks whether a user belongs to one or more groups. Parameters: user, group1, group2…

    …/api.php?user=user&user_pass=userpass&op=user_exists_in_group&params=test,4,5

    Returns: 1 or 0. An administrator returns 1 without checking groups.

    get_incident_details¶

    Returns ticket details. Parameter: ticket id.

    …/api.php?user=user&user_pass=userpass&op=get_incident_details&params=2

    Returns: CSV or XML with the ticket fields.

    create_incident¶

    Creates a ticket. Parameters: title (required), group (required), priority, description, inventories separated by :, ticket type, email copy, owner, parent ticket, status (required), extra_data, resolution, extra_data2, extra_data3, extra_data4 and the type custom fields from position 15.

    …/api.php?user=user&user_pass=userpass&op=create_incident&params=Title,2,1,Description%20of%20the%20incident,1:2:3,1,copy@example.com,admin,0,1

    Returns: the created ticket id or -1 on failure. Requires IW permission. An empty title aborts the call. A comma in the title or description is sent as :::.

    update_incident¶

    Updates a ticket. Parameters: id, title, description, epilogue, group, priority, resolution, status, owner, parent, type, extra_data, extra_data2, extra_data3, extra_data4 and custom fields from position 15.

    …/api.php?user=user&user_pass=userpass&op=update_incident&params=4,new%20title,new%20description,new%20epilog,4,2,1,3,admin,0,6

    Returns: update result. If the ticket is closed, the resolution is stored; otherwise it is forced to 0. Only the owner, creator or an administrator can modify it.

    delete_incident¶

    Deletes a ticket. Parameter: ticket id.

    …/api.php?user=user&user_pass=userpass&op=delete_incident&params=3

    Returns: 1. Requires access to the ticket.

    add_inventory_to_ticket¶

    Links an inventory object to a ticket. Parameters: ticket id, inventory id.

    …/api.php?user=user&user_pass=userpass&op=add_inventory_to_ticket&params=1,2

    Returns: 1 or 0. Requires VW permission.

    get_incident_tracking¶

    Returns the ticket tracking history. Parameter: ticket id.

    …/api.php?user=user&user_pass=userpass&op=get_incident_tracking&params=2

    Returns: CSV or XML with tracking records.

    get_incidents_resolutions¶

    Returns the resolution catalogue. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_resolutions

    Returns: CSV or XML with id and name for each resolution.

    get_incidents_status¶

    Returns the status catalogue. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_status

    Returns: CSV, XML or JSON with id and name for each status.

    get_incident_priorities¶

    Returns the priority catalogue. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_incident_priorities

    Returns: CSV, XML or JSON with id and name for each priority.

    get_incident_fields¶

    Returns the custom fields for a ticket type and, when a ticket is given, its values. Parameters: type id, ticket id (optional).

    …/api.php?user=user&user_pass=userpass&op=get_incident_fields&params=4,32

    Returns: CSV, XML or JSON with the fields. Without a ticket, it only returns the type definition.

    get_types¶

    Returns the ticket type catalogue. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_types

    Returns: CSV, XML or JSON with id and name for each type.

    get_tickets_count¶

    Counts tickets grouped by a column and period. Parameters: column, maximum days.

    …/api.php?user=user&user_pass=userpass&op=get_tickets_count&params=id_grupo,30

    Returns: JSON with the count by group. It is the only call that always returns JSON, even if another return_type is requested.

    get_incident_workunits¶

    Lists the ticket work units. Parameter: ticket id.

    …/api.php?user=user&user_pass=userpass&op=get_incident_workunits&params=3

    Returns: CSV, XML or JSON with the work units.

    create_workunit¶

    Adds a work unit to a ticket. Parameters: ticket id, description, hours, cost (0 or 1), public (0 or 1), profile id.

    …/api.php?user=user&user_pass=userpass&op=create_workunit&params=1,Description,0.5,0,1,1

    Returns: 0 or an error message. It does not accept closed tickets or duplicate a work unit with the same description on the same ticket.

    get_incident_files¶

    Lists the ticket attachments. Parameter: ticket id.

    …/api.php?user=user&user_pass=userpass&op=get_incident_files&params=1

    Returns: CSV or XML with the attachments.

    download_file¶

    Downloads an attachment. Parameter: attachment id.

    …/api.php?user=user&user_pass=userpass&op=download_file&params=32

    Returns: file content in Base64.

    attach_file¶

    Attaches a file to a ticket. Parameters: ticket id, name, size, description, Base64 content.

    …/api.php?user=user&user_pass=userpass&op=attach_file&params=1,example.txt,234,File%20of%20example,aW50ZWdyaWEgcm9ja3M=

    Returns: 0 on success, -1 if it cannot write. If the file already exists on the ticket, it returns 0 without duplicating it.

    delete_file¶

    Deletes an attachment. Parameter: attachment id.

    …/api.php?user=user&user_pass=userpass&op=delete_file&params=32

    Returns: 0 on success, -1 if the permission check fails, -2 if it cannot delete the physical file.

    validate_user¶

    Checks user and password. Parameters: user, password.

    …/api.php?user=user&user_pass=userpass&op=validate_user&params=jorge,jorge_pass

    Returns: 1 if correct, 0 if the user does not exist or is disabled, -1 if the password is wrong.

    delete_user¶

    Deletes a user. Parameter: user.

    …/api.php?user=user&user_pass=userpass&op=delete_user&params=pepe

    Returns: 1 or 0. It does not allow deleting admin. Requires UM permission.

    user_exists¶

    Checks whether a user exists. Parameter: user.

    …/api.php?user=user&user_pass=userpass&op=user_exists&params=pepe

    Returns: 1 or 0.

    get_users¶

    Lists users visible to the caller. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_users

    Returns: CSV, XML or JSON with the identifiers.

    get_groups¶

    Lists visible groups. Optional parameter: params=1 to include group 1.

    …/api.php?user=user&user_pass=userpass&op=get_groups
…/api.php?user=user&user_pass=userpass&op=get_groups&params=1

    Returns: CSV, XML or JSON with id and name for each group.

    get_stats¶

    Returns a ticket metric. Parameters: metric, string, status, user, group, company, inventory, priority.

    …/api.php?user=user&user_pass=userpass&op=get_stats&params=sla_compliance
…/api.php?user=user&user_pass=userpass&op=get_stats&params=opened,,1

    Metrics: total_incidents, opened, closed, avg_life, sla_compliance, avg_scoring and avg_worktime. If no group is given, group 1 is used.

    Returns: a CSV or XML value.

    get_incidents_summary¶

    Returns the summary by status. Optional parameter: new, unconfirmed, assigned, reopened, verified, pending_third_person, closed, not_closed or total.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_summary
…/api.php?user=user&user_pass=userpass&op=get_incidents_summary&params=not_closed

    Returns: every counter or only the requested field, in CSV or XML.

    get_last_cron_execution¶

    Returns the minutes since the last cron run. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_last_cron_execution

    Returns: minutes, or -1 if there is no record.

    get_previous_cron_execution¶

    Returns the minutes since the previous cron run. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_previous_cron_execution

    Returns: minutes, or -1 if there is no record.

    get_num_queued_emails¶

    Returns pending emails in the queue. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_num_queued_emails

    Returns: number of emails.

    get_last_invoice_id¶

    Returns the last bill_id of a submitted invoice. It takes no parameters.

    …/api.php?user=user&user_pass=userpass&op=get_last_invoice_id

    Returns: the identifier or an empty value.

    get_invoice¶

    Returns invoice data. Parameter: bill_id.

    …/api.php?user=user&user_pass=userpass&op=get_invoice&params=140601_0071

    Returns: CSV or XML with the invoice.

    create_invoice¶

    Creates an invoice. Parameters: user, task, company, bill_id, concept, amount, tax, currency, description, locked, locking user, creation date, payment date, status, reference, internal note, type (Submitted or Received), language.

    …/api.php?user=user&user_pass=userpass&op=create_invoice&params=admin,,1,140601_0082,paso,3.00,,EUR,,,,,,paid,,,Submitted,

    Returns: status and message, for example 1,"invoice created" or 0,"invalid billing id". Requires CW permission.

    create_company¶

    Creates a company. Parameters: name, address, tax id, role, country, manager, parent company.

    …/api.php?user=user&user_pass=userpass&op=create_company&params=Artica,AlbertoAguilera,12312312,1,Spain,admin,0

    Returns: the created company id. Requires CW permission; the manager must exist or be empty.

    mark_created_incident¶

    Marks the ticket creation record with extra information. Parameters: ticket id, text.

    …/api.php?user=user&user_pass=userpass&op=mark_created_incident&params=10,External%20origin

    Returns: raw update result, without CSV or XML.

    mark_updated_incident¶

    Marks the ticket update record. Parameters: ticket id, text.

    …/api.php?user=user&user_pass=userpass&op=mark_updated_incident&params=10,Updated%20by%20API

    Returns: raw update result.

    ovo_manager¶

    Specific OVO integration. Parameters: title, group, priority, description, inventory, type, extra information, group message.

    …/api.php?user=user&user_pass=userpass&op=ovo_manager&params=Title,2,2,Description,10626,10,extra,msg

    It uses group 11 and user ovo in a fixed way. Returns: a variable result depending on the updates it applies. It is not a general call.

    reset_double_factor¶

    Resets two-factor authentication. Parameter: encrypted hash in the console format (for administrators).

    …/api.php?user=admin&user_pass=adminpass&op=reset_double_factor&params=<hash>

    Returns: JSON with status. A normal user can only reset their own factor.

    Extending the API¶

    API 1.0 has no automatic router. Adding a call requires two pieces:

    1. A function in include/functions_api.php that receives $return_type and the parameters, and returns or prints the result.
    2. A case in the switch ($op) of include/api.php that invokes it.

    The minimum skeleton is:

    function api_my_call($return_type, $user, $params)
{
    // ACL checks and validation.
    $result = 1;

    switch ($return_type) {
        case 'xml':
            echo xml_node($result);
            break;
        default:
            echo $result;
            break;
    }
}

    And in the dispatcher:

    case 'my_call':
    $params = explode($token, $params);
    echo api_my_call($return_type, $user, $params);
    break;

    Keep the output format and ACL checks inside the function. API v1 does not provide any of that for you.

    MCP (Model Context Protocol)¶

    Pandora ITSM publie un serveur MCP pour qu'un agent d'IA puisse consulter des tickets, des entreprises, des contacts, des deals, des notes, des courriels, des agendas et du web tracking sans quitter la console. Ce n'est pas un chatbot : c'est une couche de lecture qui parle le protocole standard des clients MCP et qui s'authentifie avec OAuth 2.1.

    L'idée est simple : l'agent cesse de copier-coller des données de la console et interroge directement. Le serveur répond avec les mêmes ACL, la même piste d'audit et les mêmes limites que l'API v2. La différence est l'interlocuteur, qui est désormais un modèle et non un script.

    Ce chapitre couvre le serveur MCP de Pandora ITSM : quels outils il expose, comment l'activer, comment un client s'authentifie, ce que renvoie chaque outil et où l'accès s'arrête. L'API v2 reste la voie pour écrire et pour intégrer des applications ; MCP est une façade en lecture seule pour les agents.

    Ce que c'est et ce que cela permet¶

    MCP (Model Context Protocol) est un protocole ouvert qui permet à un client (Claude Code, Cursor, OpenCode, Codex, un connecteur web) de découvrir des outils et de les appeler sur un serveur. Pandora ITSM implémente le côté serveur sur HTTP, avec JSON-RPC 2.0 et une authentification OAuth 2.1.

    Un serveur en lecture seule¶

    Tous les outils du catalogue déclarent readOnlyHint: true. Le serveur ne crée, ne modifie et ne supprime aucun ticket, aucune entreprise ni aucun autre objet. Il ne joint pas de fichiers et n'envoie pas de courriel non plus. Si l'agent doit écrire, il devra utiliser l'API v2 avec un token d'API et les ACL correspondantes.

    Le catalogue est regroupé en sept domaines :

    Domaine Outils Rôle
    Entreprises company_search, company_get, activity_feed Chercher des comptes, lire leur fiche et voir l'activité récente.
    Tickets ticket_search, ticket_get Trouver des tickets et lire leur état, leur description, leur suivi et leurs unités de travail.
    Contacts contact_search, contact_get Chercher des personnes d'une entreprise et lire leur fiche.
    Deals deal_search, deal_get Consulter le pipeline, la prévision et le détail d'une opportunité.
    Notes, courriels et agendas note_list, email_list, schedule_list Lire des notes, des métadonnées de courriel et des tâches, réunions ou rappels.
    Web tracking webtracking_summary Compter les contacts attribués par source, catégorie, campagne ou mois.
    Référence reference_data Traduire les identifiants et les énumérations, et découvrir les filtres autorisés.

    Ce que l'on peut demander¶

    Quelques exemples réels de ce qu'un agent peut résoudre avec ces outils :

    • « Quel est l'état du ticket 4321 et que s'est-il passé dans les dernières réponses ? »
    • « Résume l'activité de l'entreprise Acme sur la dernière semaine. »
    • « Quels deals le commercial jlopez a-t-il déplacés ce trimestre et quelle est la prévision pondérée ? »
    • « Combien de contacts attribués à Google Ads sont arrivés ce mois-ci ? »
    • « Donne-moi les tickets fermés du groupe Support entre le 1er et le 15 novembre. »

    L'agent enchaîne les recherches et les lectures : il résout d'abord les identifiants avec reference_data, cherche ensuite avec *_search et ouvre enfin le détail avec *_get.

    Ce qu'il ne fait pas¶

    • Il n'écrit pas. Il n'existe aucun outil de création, de modification ou de suppression.
    • Il ne renvoie pas le corps des courriels ni les destinataires ; seulement les métadonnées.
    • Il ne renvoie pas l'adresse électronique ni le téléphone dans les recherches d'entreprises et de contacts. Pour les obtenir, il faut demander le détail d'un contact précis.
    • Il ne remplace ni l'API v2 ni la console. C'est une vue en lecture seule pour les agents.
    • Il ne partage pas les tokens avec l'API v2 : un token OAuth émis pour MCP n'est valable que sur /mcp.

    Prérequis¶

    Prérequis Détail
    HTTPS Les clients MCP dans le cloud exigent HTTPS. Les redirections OAuth n'acceptent que HTTPS ou HTTP en loopback (localhost, 127.0.0.1, [::1]).
    URL publique Public MCP URL doit être une URL absolue HTTPS terminée par /mcp. Sans elle, MCP ne peut pas être activé et les métadonnées OAuth ne peuvent pas être publiées.
    ACL de l'API La liste List of IP with access to API (api_acl) s'applique aussi à /mcp et aux endpoints OAuth. Elle doit inclure les IP de sortie des clients. Avec des clients dans le cloud, ajoutez leurs plages ou ouvrez la liste à * ; le contrôle réel devient alors la politique MCP et OAuth.
    Utilisateur et permissions L'utilisateur qui autorise l'accès doit être actif, inclus dans la politique MCP et disposer des permissions produit exigées par chaque outil.
    Client compatible Le client doit prendre en charge les serveurs MCP distants par HTTP et OAuth 2.1 avec enregistrement dynamique et PKCE.

    Activation et configuration¶

    La configuration se trouve dans Setup → Setup → MCP setup. Seuls les administrateurs peuvent l'ouvrir et l'enregistrer. La page est organisée en onglets : Status, Discovery, Connect, Access policy, Runtime settings et Authorizations.

    L'interrupteur général¶

    Enable MCP server allume ou éteint le serveur. Tant qu'il est éteint, l'endpoint renvoie une erreur de politique et les clients ne peuvent utiliser aucun outil. Lorsqu'il est activé, la page affiche les autres onglets et le guide de démarrage :

    1. Activer MCP.
    2. Choisir qui peut l'utiliser et configurer l'URL publique.
    3. Vérifier l'ACL de l'API.
    4. Connecter le client ; la première connexion ouvre la page de consentement.

    MCP ne peut pas être activé sans Public MCP URL. Le serveur a besoin d'une URL de confiance pour construire l'émetteur OAuth et les documents de découverte, et il ne les dérive jamais de l'en-tête Host.

    État et liste de vérification¶

    L'onglet Status affiche l'endpoint et cinq contrôles :

    Contrôle Signification
    MCP enabled L'interrupteur général est actif.
    Access policy Au moins un utilisateur ou un groupe est autorisé, ou la politique autorise tout le monde.
    HTTPS La console est servie en HTTPS.
    Public MCP URL L'URL publique est configurée.
    API ACL L'ACL de l'API n'est pas limitée à 127.0.0.1 ou localhost.

    Un point rouge ne bloque pas forcément l'enregistrement, mais il explique pourquoi un client ne se connecte pas. Le contrôle API ACL est celui que l'on oublie le plus souvent : si la liste n'autorise que le loopback, un client qui arrive d'une autre IP reçoit 401 avant même que la danse OAuth ne commence.

    Découverte OAuth¶

    L'onglet Discovery affiche les deux URL qu'un client consulte avant de s'authentifier :

    https://<host>/.well-known/oauth-protected-resource
https://<host>/.well-known/oauth-authorization-server

    Les deux documents doivent être publiés à la racine du domaine. Si Pandora ITSM vit dans un sous-répertoire ou derrière un proxy, le serveur web doit réécrire ou aligner ces chemins ; dans ce cas, l'URL de découverte ajoute le chemin de la ressource. L'onglet Discovery affiche les deux URL exactes de l'installation et propose un bouton Check qui lance une requête réelle et marque le résultat.

    Configuration Apache¶

    L'API v2 sert les documents dans /pandoraitsm/api/v2/.well-known/..., mais le client les cherche à la racine du domaine. Ces chemins doivent être réécrits dans le virtual host HTTPS. Ajoutez les règles à votre virtual host 443 ; le bloc ci-dessous montre le contexte minimal. Avec l'installation dans /pandoraitsm et l'URL publique https://itsm.example.com/pandoraitsm/api/v2/mcp :

    <VirtualHost *:443>
    ServerName itsm.example.com
    DocumentRoot /var/www/html

    RewriteEngine On

    # Ressource protégée (RFC 9728)
    RewriteRule ^/\.well-known/oauth-protected-resource/pandoraitsm/api/v2/mcp$ \
        /pandoraitsm/api/v2/.well-known/oauth-protected-resource [PT,L]

    # Serveur d'autorisation (RFC 8414)
    RewriteRule ^/\.well-known/oauth-authorization-server/pandoraitsm/api/v2$ \
        /pandoraitsm/api/v2/.well-known/oauth-authorization-server [PT,L]

    # Repli lorsque le client demande la racine sans le chemin de la ressource
    RewriteRule ^/\.well-known/oauth-protected-resource$ \
        /pandoraitsm/api/v2/.well-known/oauth-protected-resource [PT,L]

    RewriteRule ^/\.well-known/oauth-authorization-server$ \
        /pandoraitsm/api/v2/.well-known/oauth-authorization-server [PT,L]
</VirtualHost>

    Remplacez pandoraitsm par le répertoire réel de la console. Si l'installation est à la racine, remplacez /pandoraitsm/api/v2 par /api/v2 et supprimez pandoraitsm des chemins. Les deux premières règles traitent le chemin canonique avec le path de la ressource ; les deux dernières couvrent les clients qui demandent seulement /.well-known/.... [PT,L] laisse Apache transmettre la requête au front controller de l'API sans changer l'URL vue par le client.

    Vérifiez que mod_rewrite est actif et que les règles sont dans le virtual host 443, pas dans un fichier .htaccess (si vous les mettez dans .htaccess, supprimez la barre oblique initiale des motifs). Rechargez ensuite Apache :

    # RHEL, AlmaLinux, Rocky Linux
sudo systemctl reload httpd

# Debian, Ubuntu
sudo systemctl reload apache2

    Testez les deux URL depuis une IP autorisée dans api_acl :

    curl -s https://itsm.example.com/.well-known/oauth-protected-resource | python3 -m json.tool
curl -s https://itsm.example.com/.well-known/oauth-authorization-server | python3 -m json.tool

    La première doit renvoyer resource avec l'URL publique et authorization_servers ; la seconde, issuer et les endpoints. Si vous obtenez le HTML de la console ou un 404, la règle ne s'applique pas : vérifiez le ServerName, le DocumentRoot et que mod_rewrite est chargé. S'il y a un proxy inverse devant, il doit transmettre /.well-known/oauth-* à cet Apache.

    Le document de ressource protégée déclare la ressource, l'émetteur et la portée itsm.read. Le document du serveur d'autorisation déclare les endpoints d'autorisation, de token, d'enregistrement et de révocation, le flux authorization_code, le rafraîchissement, PKCE S256 et la méthode d'authentification client none.

    Politique d'accès¶

    L'onglet Access policy décide quels utilisateurs peuvent utiliser MCP. Il y a quatre listes et deux interrupteurs de récursion :

    • Allowed users et Blocked users.
    • Allowed groups et Blocked groups.
    • Include child groups for allowed groups.
    • Include child groups for blocked groups.

    L'évaluation est cumulative et le blocage gagne :

    1. Si MCP est désactivé, tout est refusé.
    2. Si l'utilisateur est désactivé, c'est refusé.
    3. Si l'utilisateur est dans Blocked users, c'est refusé.
    4. Si l'utilisateur appartient à un groupe bloqué, c'est refusé.
    5. Si la politique autorise tous les utilisateurs ou tous les groupes, ou si l'utilisateur est dans Allowed users, c'est autorisé.
    6. Si l'utilisateur appartient à un groupe autorisé, c'est autorisé.
    7. Dans tous les autres cas, c'est refusé.

    L'interface n'affiche plus les interrupteurs « autoriser tout le monde » ; l'API les conserve pour compatibilité. S'ils sont activés par API, la politique résultante autorise tout le monde et les listes de blocage restent prioritaires.

    Réglages d'exécution¶

    L'onglet Runtime settings contrôle le comportement du serveur :

    Réglage Ce qu'il fait Valeur par défaut Plage
    Maximum rows per tool call Plafonne le nombre de lignes qu'un outil peut renvoyer en un appel. Le schéma de chaque outil autorise déjà jusqu'à 50 ; ce réglage peut le réduire. Si le client demande plus de lignes que permis, il obtient la valeur configurée. 50 1–50
    Requests per minute and token Fixe le nombre de requêtes que chaque token peut faire par minute. En cas de dépassement, la réponse est 429 avec Retry-After. 0 désactive la limite. 60 0–1000
    Audit retention (days) Décide combien de jours les appels sont conservés dans l'audit avant d'être purgés. 90 1–3650
    Public MCP URL URL publique de l'endpoint. Elle sert à construire l'émetteur OAuth et les documents de découverte ; sans elle, MCP ne peut pas être activé. Elle doit utiliser HTTPS et se terminer par /mcp. vide URL HTTPS
    Authorization lifetime (days, 0 = unlimited) Fixe la durée maximale d'une autorisation à partir du moment où l'utilisateur approuve le consentement. À l'expiration, le client doit autoriser à nouveau. 0 la rend illimitée. 90 0–3650
    Allowed redirect hosts Décide vers quels hôtes un client peut rediriger après consentement. Un hôte par ligne ; *.exemple.com inclut les sous-domaines ; vide autorise n'importe quel hôte. claude.ai, chatgpt.com, localhost, 127.0.0.1 Jusqu'à 50

    Public MCP URL n'accepte ni identifiants, ni query string, ni fragment. Si l'installation est derrière un proxy, l'URL doit être celle que voit le client, pas l'URL interne du serveur.

    Autorisations¶

    L'onglet Authorizations liste les applications que chaque utilisateur a autorisées : nom du client, hôtes de redirection, utilisateur, dernière IP, date d'autorisation, dernier usage, expiration et bouton de révocation. Révoquer une autorisation supprime les tokens de cet utilisateur pour ce client ; cela n'affecte pas les autres utilisateurs du même client.

    Chaque utilisateur peut consulter et révoquer ses propres autorisations depuis l'onglet MCP applications de sa fiche utilisateur.

    Configuration par API¶

    La politique peut aussi être lue et écrite avec l'API v2, à l'aide d'un token d'administrateur. Ces endpoints n'acceptent pas les tokens OAuth de MCP.

    GET /api/v2/mcp/permission
PUT /api/v2/mcp/permission

    Le PUT accepte les champs de la politique et laisse inchangés ceux qui sont omis :

    {
  "enabled": true,
  "allowedUsers": ["admin", "support"],
  "blockedUsers": ["temporary"],
  "allowedGroups": [1, 26],
  "blockedGroups": [],
  "allUsersAllowed": false,
  "allGroupsAllowed": false,
  "allowedGroupsRecursion": true,
  "blockedGroupsRecursion": false
}

    La réponse renvoie la politique enregistrée. Un 400 indique une valeur invalide ; un 403, que le token n'appartient pas à un administrateur.

    Connecter un client MCP¶

    L'onglet Connect propose l'URL, un prompt prêt à coller dans l'agent et l'alternative pour les chats web. Le prompt est en anglais parce qu'il est consommé par l'agent, pas par l'utilisateur.

    Le prompt pour l'agent¶

    Connect yourself to the Pandora ITSM MCP server.

Server
- Name: itsm
- Transport: Streamable HTTP (remote MCP server)
- URL: https://itsm.example.com/pandoraitsm/api/v2/mcp
- Authentication: OAuth 2.1 with dynamic client registration and PKCE. The server publishes
  its metadata under /.well-known/oauth-protected-resource. Do not ask me for an API key or
  a client secret.

Steps
1. Identify which MCP client you are (Claude Code, Cursor, OpenCode, Codex, VS Code...) and add
   the server with that client's official method: its CLI command if it has one, otherwise its
   MCP configuration file. Use the user-level scope unless I say otherwise.
2. Keep the existing configuration: add or update only the "itsm" entry, and show me the change
   before writing any file.
3. Start the authorization (for example, /mcp in Claude Code). A Pandora ITSM page opens in the
   browser: I will sign in and approve the access myself. Never ask for my password.
4. Once connected, list the available tools and show them to me. They are read-only.

If the URL is not reachable or its certificate is not trusted, stop and tell me the exact error.
Do not disable TLS verification. If you cannot configure MCP servers yourself (for example, a web
chat), tell me to add a custom connector with the URL above instead.

    OpenCode¶

    OpenCode ajoute le serveur avec sa CLI et enregistre la configuration au niveau utilisateur :

    opencode mcp add itsm --url https://itsm.example.com/pandoraitsm/api/v2/mcp --global
opencode mcp list

    Ensuite, dans l'interface, ouvrez /mcps, sélectionnez itsm et terminez l'autorisation dans le navigateur.

    Claude Code¶

    claude mcp add --transport http itsm https://itsm.example.com/pandoraitsm/api/v2/mcp --scope user
claude mcp list

    Dans Claude Code, /mcp affiche le serveur et permet de se connecter. Le token est stocké et rafraîchi automatiquement.

    Cursor et autres clients avec fichier de configuration¶

    De nombreux clients lisent une entrée mcpServers avec l'URL du serveur :

    {
  "mcpServers": {
    "itsm": {
      "type": "http",
      "url": "https://itsm.example.com/pandoraitsm/api/v2/mcp"
    }
  }
}

    Le nom exact du champ de transport change selon le client (type, transport, streamable-http). Si le client ne prend pas en charge les serveurs distants HTTP ou ne sait pas faire OAuth avec enregistrement dynamique, il ne pourra pas se connecter : utilisez le prompt de l'agent ou un client compatible.

    Claude.ai et ChatGPT¶

    Les chats web ne peuvent pas se configurer seuls. Dans Settings → Connectors → Add custom connector, collez l'URL publique du serveur et terminez le consentement. L'application apparaît ensuite dans la liste des autorisations.

    Vérifier la connexion¶

    Une connexion correcte renvoie le catalogue de 14 outils avec tools/list. Si le client affiche zéro outil, vérifiez dans cet ordre : URL, certificat, ACL de l'API, Public MCP URL, politique MCP et permissions de l'utilisateur.

    Comment appeler un outil¶

    {
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "ticket_search",
    "arguments": {
      "freeSearch": "imprimante",
      "status": "ASSIGNED",
      "size": 10
    }
  }
}

    Les arguments doivent être un objet. Un nom d'outil inconnu renvoie -32601 ; un argument absent du schéma renvoie -32602/isError.

    Paramètres communs¶

    Seuls les outils de liste partagent ces paramètres. Les *_get ne paginent ni ne trient.

    Pagination¶

    Paramètre Type Par défaut Rôle
    page entier ≥ 0 0 Page, à partir de zéro.
    size entier 1–50 20 Lignes par page. webtracking_summary utilise 50 par défaut.

    La réponse inclut :

    {
  "pagination": {
    "total": 3252,
    "page": 0,
    "size": 20,
    "totalPages": 163,
    "nextPage": 1
  }
}

    nextPage vaut null sur la dernière page. Maximum rows per tool call réduit size sous le maximum de 50 autorisé par le schéma.

    Tri¶

    Paramètre Type Rôle
    sortField chaîne Champ de tri. Chaque outil publie sa liste.
    sortDirection ascending ou descending Sens du tri.
    sortMultipleFields objet Jusqu'à trois champs avec leur sens. Ne se combine pas avec sortField/sortDirection.

    Exemple :

    {
  "sortMultipleFields": {
    "priority": "descending",
    "startDate": "ascending"
  }
}

    Filtres génériques¶

    Les outils d'entreprises, de contacts, de deals, d'agendas, de notes, de courriels et d'activité acceptent fieldConditions : jusqu'à 10 conditions sur des colonnes réelles. jsonPath et les alias dérivés ne sont pas pris en charge.

    {
  "fieldConditions": [
    { "field": "createdAt", "operator": ">=", "value": "2026-01-01" },
    { "field": "country", "operator": "in", "value": ["ES", "FR"] }
  ]
}

    Opérateurs pris en charge :

    Opérateur Usage
    =, !=, <>, >, <, >=, <= Comparaison simple.
    like, not_like Correspondance de texte.
    in, not_in Liste de 50 valeurs maximum.
    between, not_between Plage de deux valeurs.
    is_null, is_not_null Nul ou non nul.
    is_empty, is_not_empty Vide ou non vide.

    ticket_search n'accepte pas fieldConditions ; utilisez ses filtres nommés (status, priority, idGroup, idUser, dates). Pour savoir quels champs et opérateurs chaque outil accepte, appelez reference_data avec types: ["filter_fields"].

    Dates¶

    Les dates sont envoyées au format YYYY-MM-DD. Le serveur accepte aussi une date et une heure ISO 8601 et conserve la date. Dans les plages, la borne supérieure inclut la journée complète lorsque l'outil le déclare (createdTo, lastActivityTo). Une date invalide renvoie isError avec le nom du champ.

    Identifiants et référence¶

    Les identifiants sont ceux de la console. Ils ne s'inventent pas et ne se déduisent pas du nom. Avant de filtrer par état, priorité, groupe, pipeline ou étape, demandez les tables à reference_data :

    {
  "jsonrpc": "2.0",
  "id": 4,
  "method": "tools/call",
  "params": {
    "name": "reference_data",
    "arguments": {
      "types": ["ticket_statuses", "ticket_priorities", "groups"]
    }
  }
}

    Permissions, audit et limites¶

    Politique MCP et ACL produit¶

    La politique MCP décide qui peut entrer. Ensuite, chaque outil applique l'ACL du produit :

    Outil Permission vérifiée
    company_search CR
    company_get CM
    activity_feed CR
    ticket_search ACL de groupes de la liste des tickets.
    ticket_get IR plus l'ACL de groupes du ticket.
    deal_search CR
    deal_get CR
    contact_search CM
    contact_get CM
    note_list CR
    email_list CR
    schedule_list CRM
    webtracking_summary CM
    reference_data CR

    Un utilisateur autorisé dans MCP mais sans la permission produit reçoit un tools/call avec isError: true et le message ACL. Il n'existe aucun moyen de contourner l'ACL de groupes des tickets : la liste et le détail l'appliquent.

    Limite de requêtes¶

    La limite est par token et par minute. Par défaut, 60 requêtes par minute. Tous les appels comptent, pas seulement tools/call. En cas de dépassement, la réponse est 429 avec Retry-After et une erreur JSON-RPC -32002.

    Le compteur est stocké dans tmcp_rate_limit et nettoyé de façon opportuniste. Une valeur 0 désactive la limite ; ne le faites pas sur une installation exposée.

    Audit¶

    Chaque appel d'outil est enregistré dans tmcp_audit avec :

    Champ Contenu
    id_user Utilisateur qui a autorisé le token.
    token_uuid UUID du token.
    tool Nom de l'outil.
    arguments Arguments, avec secrets masqués et textes longs tronqués.
    rows_returned Lignes renvoyées.
    duration_ms Durée.
    status ok, error ou denied.
    error_code, error_message Motif de l'échec, le cas échéant.
    ip IP d'origine.
    mcp_session Identifiant de la requête.
    created_at Date.

    Les arguments sont masqués si la clé contient pass, token, secret, authorization, cookie ou session ; les textes sont coupés à 500 caractères et la structure à trois niveaux et 50 clés. Les appels d'outils refusés ou limités sont également enregistrés.

    Les administrateurs peuvent voir les appels dans Setup → Audit log → MCP, un onglet qui n'apparaît que lorsque MCP est actif. La rétention par défaut est de 90 jours.

    Confidentialité et troncature¶

    Outil Ce qui est tronqué
    company_search, contact_search Ne renvoient ni courriel ni téléphone.
    contact_get Avec detail=true, renvoie le courriel, le téléphone et le mobile.
    email_list Ne renvoie ni corps ni destinataires.
    ticket_get Description et épilogue à 4000 caractères ; suivi et unités de travail à 2000.
    note_list Texte à 1000 caractères.
    schedule_list Description à 1000 caractères.

    Ces limites ne sont pas configurables par outil. Le but est d'éviter qu'un agent déverse la moitié de la base dans le contexte du modèle.

    Problèmes fréquents¶

    Symptôme Cause probable Solution
    Le client ne découvre pas OAuth (404 sur /.well-known/...). Les documents ne sont pas publiés à la racine du domaine ou le proxy ne les réécrit pas. Vérifier l'onglet Discovery et la réécriture du serveur web.
    401 avant l'ouverture du navigateur. L'IP du client n'est pas dans api_acl. Ajouter l'IP ou la plage dans Setup → Setup → General setup.
    403 à l'activation de MCP. Public MCP URL manque ou la licence n'est pas valide. Configurer l'URL HTTPS terminée par /mcp et vérifier la licence.
    503 sur les métadonnées. Public MCP URL est vide. La configurer ; l'émetteur OAuth n'est jamais dérivé de Host.
    Le consentement est redemandé sans cesse. L'autorisation a expiré (Authorization lifetime) ou le rafraîchissement a échoué. Autoriser de nouveau ou prolonger la durée de l'autorisation.
    429 avec Retry-After. Limite par token dépassée. Attendre ou augmenter Requests per minute and token.
    Le client voit zéro outil. Utilisateur sans politique MCP, sans permissions produit ou client sans OAuth. Vérifier la politique, l'ACL et la compatibilité du client.
    size renvoie moins de lignes que demandé. Maximum rows per tool call réduit la taille sous la valeur demandée. Augmenter le réglage jusqu'à 50 ou paginer.
    size supérieur à 50 renvoie une erreur d'argument. Le schéma limite size à 50. Demander 50 ou paginer.
    Unknown argument. Le client envoie un paramètre absent du schéma. Consulter tools/list ou reference_data.
    Les tickets d'un groupe n'apparaissent pas. ACL de groupes de l'utilisateur. Vérifier les groupes de l'utilisateur ; MCP ne contourne pas l'ACL.

    Relation avec l'API v2¶

    MCP et l'API v2 partagent la base, l'authentification, l'ACL et la licence, mais ce ne sont pas la même chose :

    • L'API v2 est la voie d'écriture et d'intégration générale.
    • MCP est une façade en lecture seule pour les agents, avec des outils et des schémas conçus pour un modèle.
    • Un token OAuth de MCP n'est valable que sur /mcp.
    • Un token d'API v2 est aussi valable sur /mcp, mais ce n'est pas le flux recommandé pour les agents.
    • La référence OpenAPI de l'API v2 inclut les routes /mcp, /mcp/permission et les endpoints OAuth ; elle sert à générer des clients et à vérifier les codes de réponse.

    Si vous devez créer des tickets, mettre à jour des entreprises ou lancer des actions, utilisez l'API v2 du chapitre 11.1 avec un token d'API et les permissions de l'utilisateur. MCP n'écrit pas.

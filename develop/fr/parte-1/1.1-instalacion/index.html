    Installation¶

    Installer Pandora ITSM comporte une partie simple et une partie qui se complique dès que quelqu'un décide d'improviser. Le script officiel fait presque tout : il installe les dépendances, crée la base de données, charge le schéma et laisse la console prête. Ce qu'il ne fait pas, c'est deviner si le serveur manque de mémoire, si la base de données se trouve ailleurs ou si quelqu'un va conserver le mot de passe par défaut jusqu'au jour de l'audit.

    La thèse de ce chapitre est simple : les installations échouent rarement à cause du logiciel ; elles échouent à cause de la précipitation. Avec deux gigaoctets de RAM, dix gigaoctets de disque et une décision claire sur la base de données, le reste consiste à suivre l'ordre. Sans cela, le script s'arrête, et il a raison de le faire.

    L'installation par défaut est l'installation en ligne : un script officiel exécuté en root qui installe les dépendances, crée la base de données, charge le schéma et les données initiales et laisse la console à l'adresse http://<IP-ou-FQDN>/pandoraitsm. Pour les environnements sans accès à Internet, il existe l'installation hors ligne.

    Ce qui est installé¶

    L'installateur laisse ces composants sur le serveur :

    • Console web dans /var/www/html/pandoraitsm.
    • Serveur web Apache et PHP-FPM.
    • Base de données MySQL ou Percona, locale ou externe.
    • Schéma et données initiales de Pandora ITSM.
    • Cron toutes les cinq minutes pour les tâches internes.
    • Serveur de chat et ses dépendances Node.js.
    • Configuration dans include/config.inc.php.

    Ce n'est ni un service géré ni une installation de bureau. Tout le produit s'utilise depuis le navigateur, et le serveur reste sous la responsabilité de celui qui l'administre : les correctifs, les sauvegardes et la supervision ne sont pas inclus dans le paquet.

    Avant de commencer¶

    Avant d'exécuter l'installateur, vérifiez ces points :

    • Vous disposez d'un accès root ou sudo sur le serveur.
    • Le serveur a un nom d'hôte ou un FQDN résolvable.
    • Le fuseau horaire est correct ; l'installateur le définit avec TZ.
    • Il y a un accès à Internet et à packages.pandorafms.com.
    • Les ports 80 et 443 sont libres. Si la base de données est externe, le port 3306 doit aussi être accessible depuis le serveur.
    • SELinux et le pare-feu autorisent le trafic web.
    • Vous avez décidé si la base de données sera locale ou externe.
    • Si vous avez décidé d'installer la base de données en externe, vous avez ses mots de passe prêts et ils respectent la politique de MySQL.
    • Si vous réinstallez, vous avez une sauvegarde ou un instantané de la machine.

    L'installateur s'arrête s'il trouve des paquets Pandora ITSM, le répertoire /var/www/html/pandoraitsm ou une base de données du même nom. Il ne nettoie pas une installation précédente de lui-même. Si votre plan était « on verra », l'installateur en a un autre : s'arrêter.

    Installation en ligne¶

    L'installation en ligne se lance avec une seule commande, quelle que soit la distribution. Exécutez-la en root :

    curl -SsL https://pfms.me/deploy-pandora-itsm | bash

    Le script détecte le système et télécharge l'installateur correspondant. Le reste de ce chapitre explique ce qu'il fait, quelles variables il accepte et comment vérifier le résultat.

    Prérequis système¶

    Matériel¶

    Prérequis Minimum Recommandé
    Processeur 2,4 GHz, double cœur Quatre cœurs ou plus selon les utilisateurs simultanés
    RAM 2 GB 4 GB
    Disque 10 GB libres 20 GB ou plus, selon l'historique et les pièces jointes
    Réseau 100 Mbps 1 Gbps

    L'installateur vérifie la mémoire et l'espace disque avant de modifier quoi que ce soit. Sur EL9 et EL10, il exige 9 GB libres dans /var et 1 GB dans /usr. Si le serveur ne respecte pas le minimum, le script s'arrête. Ce n'est pas une suggestion : c'est une condition.

    Systèmes d'exploitation¶

    Système Versions prises en charge
    RHEL, Rocky Linux ou AlmaLinux EL 9 et EL 10
    Ubuntu Server 22.04 et 24.04

    Logiciels¶

    Composant Version
    PHP 8.2 ou 8.4
    MySQL ou Percona 8.0 ou 8.4 selon la distribution
    Serveur web Apache avec PHP-FPM
    Navigateur Chrome, Edge, Firefox ou Safari à jour ; résolution minimale 1280 × 720

    EL10 n'accepte que MySQL/Percona 8.4. EL9 et Ubuntu acceptent 8.0 et 8.4. L'installateur définit les versions de PHP et de MySQL avec les variables PHPVER et MYVER. Il n'y a pas de récompense pour utiliser la version qui n'est plus prise en charge.

    Extensions PHP¶

    La console a besoin des extensions mysqli, gd, session, mbstring, ldap, gettext, imap, phar et zip. L'installateur les ajoute avec les paquets PHP ; si vous installez manuellement, vérifiez qu'elles sont actives avant d'ouvrir la console. Une erreur d'extension se déguise en écran blanc, et un écran blanc n'annonce jamais une bonne nouvelle.

    Base de données¶

    Pandora ITSM a besoin d'une base de données MySQL ou Percona. Elle peut se trouver sur le même serveur ou sur un serveur dédié. Une base de données partagée est valide, mais les performances dépendent de la capacité du serveur et du volume d'historique : les tickets, leurs pièces jointes et l'audit augmentent avec l'usage.

    Si la base de données est externe, préparez d'abord l'hôte, le port, l'utilisateur et les permissions. L'installateur peut créer la base de données et l'utilisateur, ou utiliser des éléments existants avec SKIP_DATABASE_INSTALL=1.

    Modes d'installation¶

    Mode Quand l'utiliser Nécessite Internet
    En ligne Nouvelle installation sur un serveur avec accès Internet Oui
    Hors ligne Serveurs isolés ou à accès restreint Non
    Installateur web manuel Débogage ou installation pièce par pièce avec install.php Selon le cas

    L'installateur web manuel n'est pas la voie recommandée pour la production. Il aide à comprendre chaque étape et convient aux environnements très contrôlés ; le script en ligne est la procédure prise en charge. Ne confondez pas « je peux le faire à la main » avec « je dois le faire à la main ».

    Installation en ligne pas à pas¶

    Exécuter le script¶

    Le script générique lit sa configuration dans des variables d'environnement et détecte le système pour télécharger l'installateur correspondant. Voici les valeurs que vous pouvez ajuster :

    Variable Valeur par défaut Rôle
    TZ Europe/Madrid Fuseau horaire du système
    MYVER 84 Version de MySQL/Percona : 80 ou 84
    PHPVER 8.4 Version de PHP : 8.2 ou 8.4
    DBHOST 127.0.0.1 Hôte de la base de données
    DBNAME pandoraitsm Nom de la base de données
    DBUSER pandoraitsm Utilisateur de la base de données
    DBPASS P4ndor4.itsm Mot de passe de l'utilisateur de la base de données
    DBPORT 3306 Port MySQL
    DBROOTPASS P4ndor4.itsm Mot de passe de root MySQL
    DBROOTUSER root Utilisateur administrateur MySQL
    SKIP_PRECHECK 0 Ignore la vérification d'une installation précédente
    SKIP_KERNEL_OPTIMIZATIONS 0 Ignore les réglages du noyau
    SKIP_DATABASE_INSTALL 0 Utilise une base de données déjà créée
    POOL_SIZE Calculé selon la RAM Taille du pool PHP-FPM

    Remplacez toujours les mots de passe d'exemple. Si vous utilisez MySQL 8 avec la politique de mots de passe active, P4ndor4.itsm peut ne pas respecter les exigences ; choisissez un mot de passe plus long avec majuscules, minuscules, chiffres et symboles. La commodité d'aujourd'hui est l'incident de demain.

    Exemple pour EL10¶

    env TZ='Europe/Madrid' \
    MYVER='84' \
    PHPVER='8.4' \
    DBHOST='127.0.0.1' \
    DBNAME='pandoraitsm' \
    DBUSER='pandoraitsm' \
    DBPASS='ChangezCeMotDePasse' \
    DBPORT='3306' \
    DBROOTPASS='ChangezCeMotDePasseRoot' \
    DBROOTUSER='root' \
    SKIP_PRECHECK=0 \
    SKIP_KERNEL_OPTIMIZATIONS=0 \
    SKIP_DATABASE_INSTALL=0 \
    bash itsm_deploy_enterprise_entrypoint.sh

    Le script générique détecte EL10 et télécharge l'installateur EL10. Pour utiliser PHP 8.2, changez PHPVER='8.2'. Sur EL10, l'installateur n'accepte que MYVER=84 ; sur EL9, vous pouvez utiliser MYVER='80' si votre base de données est MySQL 8.0.

    Ce que fait le script¶

    1. Vérifie le système d'exploitation, la mémoire, le disque et les permissions.
    2. Ajoute les dépôts Pandora et Remi pour PHP.
    3. Installe Apache, PHP-FPM, MySQL ou Percona, Node.js et les extensions.
    4. Crée la base de données et l'utilisateur, ou réutilise des éléments existants.
    5. Charge integria_db.sql et integria_dbdata.sql.
    6. Écrit include/config.inc.php avec les paramètres de connexion.
    7. Configure la tâche cron integria_cron.php toutes les cinq minutes.
    8. Installe et démarre le serveur de chat.
    9. Applique des réglages au noyau et à PHP-FPM.
    10. Affiche l'URL d'accès et les identifiants initiaux.

    Le script écrit le détail dans /tmp/pandoraitsm-deploy-enterprise-el9-AAAA-MM-JJ.log (ou le nom correspondant à votre système). En cas d'échec, ce journal est la première chose à lire. Deviner l'erreur coûte plus cher que d'ouvrir le fichier.

    Résultat¶

    À la fin, le script affiche une adresse semblable à :

    http://192.0.2.10/pandoraitsm

    et les identifiants initiaux. Ouvrez cette adresse depuis un navigateur ayant accès au serveur.

    Installation hors ligne¶

    L'installation hors ligne utilise un paquet avec les dépendances et un script local. Le déroulement est le suivant :

    1. Téléchargez le paquet de dépendances et le script de votre distribution.
    2. Copiez-les sur le serveur isolé.
    3. Décompressez le paquet.
    4. Exécutez itsm_deploy_enterprise_local_el10.sh en root, avec les mêmes variables que pour l'installation en ligne.

    L'installation hors ligne n'est pas prise en charge sur Ubuntu avec les scripts actuels.

    Premier accès¶

    URL de la console¶

    La console est disponible à l'adresse :

    http://<IP-ou-FQDN>/pandoraitsm

    Si vous avez configuré TLS, utilisez https://. Le chemin /pandoraitsm est celui que l'installateur écrit dans config.inc.php ; ne le changez pas sans mettre à jour la configuration Apache.

    Licence et connexion¶

    Si vous utilisez l'installateur web manuel, le premier écran demande d'accepter la licence. Avec le script en ligne, le premier accès est directement l'écran de connexion.

    Les identifiants initiaux sont :

    Utilisateur Mot de passe
    admin pandoraitsm

    Changez le mot de passe au premier accès

    Le compte admin est un utilisateur d'installation. Changez son mot de passe avant de connecter la console au réseau de production et créez ensuite vos propres utilisateurs. Ne partagez pas le compte admin entre plusieurs personnes.

    Un mot de passe par défaut est une bienvenue, pas une politique de sécurité. Plus tôt il disparaît, mieux c'est.

    Changer le mot de passe¶

    Connectez-vous avec admin, ouvrez le menu utilisateur et changez le mot de passe. Créez ensuite un utilisateur à votre nom, attribuez-lui le profil et le groupe nécessaires et réservez admin aux tâches d'administration.

    Données initiales et « Reset all data »¶

    L'installation charge integria_dbdata.sql, qui contient des données d'exemple : entreprises, contacts, tickets et autres enregistrements qui permettent de voir la console avec du contenu dès le premier jour.

    Si vous voulez démarrer avec un système propre :

    1. Ouvrez Setup → Setup → Old data maintenance.
    2. Cliquez sur Reset all data.
    3. Confirmez deux fois dans les boîtes de dialogue.

    Reset all data supprime les données et les pièces jointes

    L'option supprime les données de la base et les fichiers joints. Elle conserve l'utilisateur admin actuel et certains réglages de configuration. Il n'y a pas de retour en arrière : faites une sauvegarde si vous devez conserver quelque chose.

    Les données d'exemple sont parfaites pour une démonstration et un passif en production. Le bouton existe pour que vous n'ayez pas à les supprimer à la main, table par table.

    Vérification et après-installation¶

    Services¶

    Vérifiez que le serveur web, PHP-FPM et la base de données sont actifs :

    # RHEL, Rocky Linux et AlmaLinux
systemctl status httpd php-fpm mysqld

# Ubuntu
systemctl status apache2 php8.4-fpm mysql

    Adaptez le nom de PHP-FPM à la version installée (php8.2-fpm ou php8.4-fpm). Un service que vous ne vérifiez pas est un service qui tombe le lundi.

    Cron¶

    L'installateur laisse trois tâches planifiées, toutes les cinq minutes :

    */5 * * * * root php /var/www/html/pandoraitsm/include/integria_cron.php
*/5 * * * * php /var/www/html/pandoraitsm/include/crm_cron.php
*/5 * * * * php /var/www/html/pandoraitsm/include/campaign_cron.php

    Chacune a son rôle :

    Tâche Rôle
    integria_cron.php Cœur : vérifications quotidiennes (calendrier, projets, tâches, changements, autowu, clôture automatique des tickets, nettoyage et notifications), file de courriel, rappels des tâches CRM et inventaire, cron Enterprise, SLA et règles de workflow du temps.
    crm_cron.php CRM : Gmail envoyé et reçu, workflows des contacts et des opportunités, échéances des planifications, courriels des tâches dues, notifications d'activité, transcriptions Google Meet et appels Zadarma.
    campaign_cron.php Campagnes : exécute les campagnes en attente et vérifie les rebonds de courriel.

    L'inventaire dispose aussi de son propre script, inventory_cron.php : il synchronise l'inventaire des nœuds Pandora FMS, expire les planifications en retard et nettoie les objets orphelins. L'installateur actuel ne l'ajoute pas à /etc/crontab ; ajoutez son entrée si vous en avez besoin :

    */5 * * * * php /var/www/html/pandoraitsm/include/inventory_cron.php

    Vérifiez que les tâches sont actives et que les fichiers existent :

    grep pandoraitsm /etc/crontab
ls -l /var/www/html/pandoraitsm/include/*_cron.php

    Si une tâche manque, vérifiez /etc/crontab et le journal de l'application. Un cron qui ne s'exécute pas ne prévient pas ; il cesse simplement de faire son travail.

    Journaux¶

    Journal Contenu
    /var/www/html/pandoraitsm/pandora_itsm.log Erreurs de l'application
    /var/log/php-fpm/www-error.log Erreurs de PHP et PHP-FPM
    /tmp/pandoraitsm-deploy-enterprise-<système>-AAAA-MM-JJ.log Installation

    Si PHP ne démarre pas ou si la console renvoie une erreur 500, commencez par /var/log/php-fpm/www-error.log : l'erreur réelle s'y trouve, pas dans le message générique affiché par le navigateur.

    Sécurité minimale¶

    • Changez le mot de passe de admin.
    • Créez vos propres utilisateurs et supprimez ou désactivez ceux de démonstration.
    • Décidez si vous conservez les données d'exemple.
    • Vérifiez le pare-feu : seuls 80/443 doivent être ouverts vers Internet.
    • Configurez TLS si la console est accessible hors du réseau interne.
    • Assurez-vous que la base de données n'est pas exposée à Internet.
    • Programmez des sauvegardes avant de charger des données réelles.

    Réinstallation et nettoyage¶

    L'installateur n'écrase pas une installation existante. S'il trouve des paquets, /var/www/html/pandoraitsm ou la base de données, il s'arrête. Pour réinstaller depuis zéro, retirez d'abord :

    • Les paquets Pandora ITSM.
    • Le répertoire /var/www/html/pandoraitsm.
    • La base de données et l'utilisateur de la base de données.
    • L'entrée cron.
    • La configuration Apache et PHP-FPM si vous l'avez personnalisée.

    Il n'y a pas de désinstalleur automatique. Si vous voulez seulement repartir de zéro avec les données, utilisez Reset all data au lieu de réinstaller. Si vous devez conserver quelque chose, sauvegardez la base de données et les pièces jointes avant de supprimer.

    Problèmes fréquents¶

    Symptôme Cause probable Vérification
    Le script dit que le système n'est pas pris en charge Distribution ou version autre que EL9, EL10 ou Ubuntu 22.04/24.04 Vérifiez /etc/os-release et utilisez le bon script
    La vérification de mémoire ou de disque échoue Moins de 2 GB de RAM ou moins de 10 GB libres Augmentez le serveur ou libérez de l'espace
    Impossible de joindre packages.pandorafms.com Pas d'accès Internet ou problème DNS Testez ping et vérifiez le proxy
    PHP ou MySQL non pris en charge Version hors de 8.2/8.4 ou 8.0/8.4 Ajustez PHPVER et MYVER
    MySQL refuse le mot de passe Politique de mots de passe de MySQL 8 Utilisez un mot de passe plus fort
    L'installateur détecte une installation précédente Paquets, répertoire ou base de données existants Nettoyez ou utilisez une autre machine
    La console ne répond pas après le script Apache, PHP-FPM ou SELinux Vérifiez les services et les journaux
    La console s'ouvre mais ne charge pas les données Base de données ou configuration Vérifiez config.inc.php et le journal de l'application

    Si le problème n'est pas dans ce tableau, consultez la Partie 14 (FAQ) et joignez le journal d'installation à votre demande. Un « ça ne marche pas » sans journal est une conversation qui commence mal.

    Étapes suivantes¶

    Avec la console opérationnelle, l'ordre recommandé est :

    1. Vérifiez la licence et la politique de versions (1.3 et 1.4).
    2. Configurez les utilisateurs, groupes et profils (Partie 02).
    3. Configurez le courriel (Partie 03).
    4. Programmez les sauvegardes et vérifiez la configuration avancée (Partie 12).
    5. Une fois la version stabilisée, planifiez la mise à jour (1.2).

    Installer est le début, pas la fin. L'installation met le moteur en route ; la suite dépend de la façon dont vous le configurez et du respect que vous accordez aux données qu'il va stocker.

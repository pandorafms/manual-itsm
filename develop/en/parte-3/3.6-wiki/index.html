    Wiki¶

    The internal wiki is the team's shared notebook: procedures, runbooks, minutes, links and that explanation someone wrote once and everyone consults every month. It is not an incident knowledge base, even if it looks like one; the knowledge base answers "how is this problem solved", the wiki answers "how does this work internally".

    Pandora ITSM includes a simple wiki with permissions by profile and by page. That simplicity is a virtue: it does not try to be Confluence, but it does not force you to set up a separate server to document day-to-day work either.

    The 3.5 Knowledge base is meant for incident solutions; the wiki is for procedures and internal documentation.

    Read and write permissions¶

    General access is controlled by profile bits:

    • WR: read permission.
    • WW: write permission.
    • WM: wiki administration, including access lists.
    • Super administrator: can do everything, as in the rest of the product.

    There is also an extended ACL per page. In Wiki → Wiki, inside each page, Read ACL and Write ACL decide which users can read or edit it.

    The most frequently forgotten rule: if the ACL list is empty, the page is accessible to everyone. When a user is added, only that user —and wiki administrators— have access. An empty ACL does not mean "nobody"; it means "everybody".

    Other particularities:

    • A user can be added to an ACL without having the profile's WR/WW permissions; in that case the ACL is useless to them.
    • A user can appear several times in a list; to exclude them, delete every occurrence.
    • Pandora ITSM does not warn when an ACL locks someone out. Documentation is no substitute for testing with the real user.

    Wiki menu¶

    In Wiki → Admin pages you manage pages, including the special side_menu page that defines the side menu.

    To add a link to an internal page, use the page name and a URL such as:

    index.php?sec=wiki&sec2=operation/wiki/wiki&page=Office

    For an external link, the URL must include http:// or https://. The link opens in the same window, so warn anyone using it: leaving the console by accident is a deeply rooted tradition.

    Menu links can be deleted from Admin pages. After saving, re-enter to see the changes. If they do not appear, it is not black magic: it is menu cache.

    Basic syntax¶

    The full syntax is in Wiki → Syntax. The essentials:

    Headers¶

    !Heading H2
!!Heading H3
!!!Heading H4
!!!!Heading H5

    The more exclamation marks, the lower the level. They must be at the start of the line. After saving, each heading has a button to edit only that section.

    Lists¶

    * Fruit
** Apple
*** Granny smith
** Orange
* Vegetables

    Numbered lists use #, ##, ### with the same logic.

    Styles¶

    '''bold'''
''italic''
'__underlined__'
'--strikethrough--'

    Links¶

    [Sample page|sample subpage]
[External page|https://www.example.com/]
[http://www.example.com/]

    Relative links must start with ./; otherwise they are interpreted as internal wiki pages.

    Images¶

    Internal images are uploaded in Wiki → Upload and referenced like this:

    [./wiki_data/upload/image_name.png]
[./wiki_data/upload/dir1/image_name.png]

    External images can also be linked, although hosting them on the server is better. Useful options:

    [http://example.com/image.jpg|link=http://example.com/|center|title=Example image]

    Table of contents, code and formatting¶

    • {TOC} generates a table of contents from the headings.
    • {{ ... }} shows code without formatting.
    • ---- inserts a horizontal line.
    • ^ escapes special characters.
    • {html}...{/html} inserts raw HTML. A heading inserted this way will not have a section edit button.
    • {br} inserts a line break.

    Best practices¶

    • Use the wiki for stable procedures, not for a ticket's day-to-day work.
    • Define an index page and a side menu with the important pages.
    • Assign an owner to each page and review it when the product changes.
    • Do not paste passwords, tokens or personal data.
    • If a page needs ten subpages to explain a procedure, the procedure may need simplifying.
    • Test ACLs with an unprivileged user before trusting them.

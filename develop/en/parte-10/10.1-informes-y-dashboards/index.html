    Reports and dashboards¶

    A report is not meant to fill a meeting: it is meant to answer a question. Pandora ITSM gathers people, support, project and SQL reports under Reports, and adds dashboards so you can see what matters without opening five different screens. The problem is never a lack of data; the problem is mistaking a pretty chart for a well-informed decision.

    This chapter explains how dashboards are built, how reports are scheduled and what each report measures. Project reports stay here, next to the rest, because they share the menu, templates and scheduler.

    Where reports live¶

    The Reports menu groups:

    • Dashboards → Manage Dashboard: visual boards.
    • Report manager: templates, scheduling and report library.
    • People management: time, vacations, people and team performance.
    • Support: support, tickets, resolutions, operators and customers.
    • Project management: project reports.
    • Custom SQL report: custom queries.

    Permissions are based on the Report Reader (RR) and Report Manager (RM) profile bits, plus group visibility. A user may be able to view a report but not create one, or create a SQL query but not see another group's data.

    Dashboards¶

    Dashboards are command boards. Each user can have their own and choose which one appears at login.

    In Reports → Dashboards → Manage Dashboard you list dashboards, search by keyword and create them with Create. Each one has Update to change its name and group, and Delete to remove it. The Default dashboard includes every available widget and serves as a demonstration.

    Creating and editing¶

    When creating a dashboard you set a unique Name, with no leading or trailing spaces, and a Group. The name can be changed later with Update.

    To edit the content, open the dashboard and enable the edit switch. Add cell adds a cell and New widget lets you choose the widget type. Each widget is configured with the gear icon and deleted with the bin icon. You can drag it by its title and resize it from the edges.

    Widgets¶

    Customized links¶

    Adds a working link that opens in the same window or a new tab. The URL must start with http:// or https://; otherwise it is treated as an internal link. An image is also required: both fields are mandatory.

    Example of an internal link to the change list:

    • URL: changes/operation/changes/changes_list
    • Open new tab: enabled
    • Image: ticket.svg

    The remaining fields —text, title, font and colours— are optional.

    Message board¶

    A rich text editor for embedding tables, links, images, lists or complete documents. It starts with a welcome message that disappears when you add your own content.

    Predefined links¶

    Adds internal links with a label and icon:

    • Knowledge base.
    • Downloads.
    • Create ticket.
    • Wiki.
    • Time tracker.
    • My tickets.

    Search box¶

    Adds a keyword search box. Select at least one area: knowledge base, Wiki, tickets, projects, people, contacts, contracts, companies, invoices or leads.

    Support Activity Graph¶

    Shows an activity chart across one or more calendars from a saved ticket filter. Each user can only choose their own filters.

    Support Evolution Graph¶

    Shows opened and closed tickets from a saved filter, with a configurable refresh rate. It also uses only the user's own filters.

    Support SLA¶

    With a saved filter, shows a pie chart with the percentage of met and breached SLA.

    Support statistics¶

    Groups tickets from a saved filter by priority, status, type or general statistics. You must choose an option in Statistic.

    Ticket list¶

    Shows a paginated ticket list —five per page by default— with the fields and order you choose. It uses a saved filter and a refresh period to keep information current.

    Report manager¶

    In Reports → Report manager you create templates and schedules. Scheduled reports are stored in the library and can be sent by email. The system cron must be active; without cron there is no magic, only a queue waiting.

    Report templates¶

    In Reports → Report manager → Templates you define the cover, header and footer of PDF reports. The cover supports images, links, formatting and margins. Available macros:

    • _fullname_: user generating or requesting the report.
    • _date_: generation date.
    • _time_: generation time.
    • _reportname_: report name.

    The macros also work in the header, where the logo can be changed. Cover, header and footer can be disabled separately.

    Report scheduler¶

    In Reports → Report manager → Report schedule you schedule a report to run once, weekly or monthly. Choose a template, store it in the library and optionally send a notification or the report itself by email.

    Assigning a company to the scheduled report lets that company's users see and edit it. Depending on the report type, its filters appear; Custom SQL only shows the SQL reports already created. You can create as many schedules as needed.

    Report library¶

    In Reports → Report manager → Report library you browse generated reports and search by report type or name.

    People reports¶

    Pandora ITSM can track working time, breaks, remote or on-site work and vacations. Reports in this area can be scheduled weekly or monthly.

    Time tracking¶

    Reports → People management → Time tracking shows daily, weekly or monthly activity recorded by a user with the Time tracker. There are preset periods —this week, this month, the last three months— and you can request a custom one.

    At least one daily record must exist for the report to show data; the remaining days appear empty. Exports to CSV, full screen and PDF.

    The three vacation reports share a menu but not permissions: the detailed report requires HR and, in practice, UM to reach it from the menu; the calendar and export depend on access to Reports.

    Detailed vacation report¶

    Reports → People management → Detailed vacation report presents the report in two modes: Show vacation report and the work unit report. The filters are user, group and creation date (Created from and Created to); they are applied when you click Search.

    The result shows users, total vacation days, days taken and days remaining. It can be viewed full screen or exported to PDF. If the work unit report is selected, it adds unjustified days, justified non-working days due to illness, vacation and extra vacation. Exports to full screen and PDF; not CSV.

    General vacation calendar¶

    Reports → People management → General vacation calendar shows approved vacations in monthly, weekly or daily view. You can move forward and backward by month and return to today with Today. The user search limits the calendar to one person and non-working days are highlighted. It is screen-only.

    People report¶

    Reports → People management → People report selects the current user and the last three months of all projects by default, with a ticket summary. It shows project activity and percentage, ticket charts by group and creator group, a ticket table —if Show only summary is disabled— and a summary of tickets and time worked.

    Exports to CSV, full screen and PDF.

    People monthly WU¶

    Reports → People management → People monthly WU shows all users for the current month with total hours and average rating. You can change month and filter by user.

    Each user's report button opens a dialog to edit their work units, one by one or in bulk. Only task work units (Work Unit Tasks) support bulk editing. Depending on privileges, each unit can be edited, deleted or blocked.

    Detailed user report¶

    Reports → People management → Detailed user report requires start and end dates. It offers three options:

    • Project: groups by user and project.
    • Role and task: groups by user and task.
    • Role and task (details): adds descriptions and ticket, hour and cost totals.

    Select user, period, roles, tasks and projects. It does not export to CSV, full screen or PDF.

    Vacation report¶

    Reports → People management → Vacation report selects all active users by default. Choose group, users and dates (Date from and Date to); dates are mandatory. View shows the table on screen and Export downloads the result. Name filtering is applied when you click View, not while typing. Exports to CSV, but not full screen or PDF.

    Team performance¶

    Reports → People management → Team performance shows the weekly performance of a company's staff. Filter by group, date and Pandora ITSM area: projects, support, changes or time tracking.

    With default values it returns no data, and that is normal:

    • The main filter is the company.
    • The filter interface opens with Ctrl + f.
    • The week start day comes from general configuration; Monday by default.

    Exports to full screen, PDF and Microsoft Excel; not CSV.

    Support reports¶

    Support reports are based on recorded ticketing. They help evaluate cost, quality, time, effort, staff profiles and customer profiles.

    Support report¶

    Reports → Support → Support report generates a PDF with dozens of charts, summaries, lists and parameters. To choose filters quickly, start from a saved custom ticket search.

    The report has two parts:

    • Show statistics: statistical information with charts.
    • Show list: tabular ticket information.

    Select one or both. Issue fields chooses the table fields without affecting the charts. It includes eight general pie charts with Top-N groupings —most active tickets, most active customers, operators, opened, closed— plus trend lists and charts.

    Exports to full screen and PDF; not CSV.

    Detailed ticket report¶

    Reports → Support → Detailed ticket report shows every detail of a ticket: dates, participants, description, custom fields, SLA and, optionally, work units, files, tracking and statistics.

    Type at least two letters in Select issues, choose the ticket and click Report. Additional options:

    • Stats: general statistics, work unit statistics, activity by user and by status, group, owner and company.
    • Tracking: ticket changes, filterable by user.
    • Files: attached files.
    • Work Units: work units, with the option to edit time.

    User privileges limit what can be seen and edited. Exports to full screen and PDF; not CSV.

    Resolution report¶

    Reports → Support → Resolution report lists closed tickets and shows the impact on time, dead pauses, people involved and resolution, including customer feedback. Filter by creation and closing date, creator and company. Exports to full screen and PDF.

    Ticket type report¶

    Reports → Support → Ticket type report groups tickets by company and type over a time interval. Filter by creator, company and group. Exports to CSV, full screen and PDF.

    Operator report¶

    Reports → Support → Operator report measures support quality per operator: time spent, average resolution time, customer feedback and total tickets. Filter by company, user, status and time range.

    Exports to CSV, full screen and PDF.

    Customer tickets reports¶

    Reports → Support → Customer tickets shows created, resolved and in-progress tickets grouped by user, year and month. Company is mandatory; Users lets you select one or more users from that company.

    Options:

    • Show section state: status table by month and user.
    • Show section type tickets: type table by month and user.
    • Show section total: global total.
    • Created from Pandora FMS: separates tickets created from Pandora FMS and from Pandora ITSM.

    Exports to full screen and PDF; not CSV.

    Project reports¶

    Project reports are in Reports → Project management. They help plan time and cost and see project evolution through the hours booked by the people involved.

    General project report¶

    Reports → Project management → General project report → Select project shows a selected project. Opening it without a project shows an error message; this is normal and does not indicate a failure.

    Options:

    • Show project: basic information, people, work and cost summary, task distribution, workload, activity and task summary.
    • Show task activity: for selected tasks, hours, costs, estimates and distribution and activity charts.
    • Show task work unit: date, duration, people and description of each work unit for the selected tasks.
    • Show in table: all tasks according to date, milestone or people filters.

    You can filter by milestones, tasks, dates, people and related company. Exports to CSV, full screen and PDF.

    All projects report¶

    Reports → Project management → All projects report filters by text in name or description, owner, people involved, date, group, archived projects and project custom fields.

    The list shows identifier, group, name, owner, people involved and task progress. Exports to CSV, full screen and PDF.

    Project expense report¶

    Reports → Project management → Project expense report shows last month's projects. Filter by start or end date and completion percentage. Show task breakdown details each task. Selecting a project lets you filter by milestones. Exports to CSV, full screen and PDF.

    Project bundle of hours report¶

    Reports → Project management → Project bundle of hours report selects a project and a month. It shows a summary by task and tickets, with consumed and remaining hours. You can filter by company and related contracts. Exports to full screen and PDF; not CSV.

    Custom SQL report¶

    Reports → Custom SQL report lets you create your own queries that return a table exportable to a spreadsheet or PDF.

    Only a super administrator or a user with RM permission can create, modify and delete SQL reports. Viewing them requires RR and membership in the report's group.

    A simple query:

    SELECT id, name, country FROM tcompany ORDER BY country;

    Fields can be renamed with aliases:

    SELECT
  id AS `Identification number`,
  name AS Name,
  country AS `Country origin`
FROM tcompany ORDER BY country;

    For security, DELETE, DROP, ALTER, TRUNCATE, CREATE, UPDATE, INSERT INTO, EXEC and MERGE are forbidden. Exports to CSV, full screen and PDF.

    Custom SQL tips¶

    • In templates, _reportname_ can be replaced with the real SQL report name and custom images can be inserted.
    • New SQL reports are assigned to the None group; assign a specific group.
    • To discover tables and fields, create reports with SHOW TABLES; and DESCRIBE <table_name>;. This avoids creating database users: the ACL is managed in Pandora ITSM.

    Best practices¶

    • Define the question before choosing the report.
    • Save reusable ticket searches for dashboards.
    • Review RR/RM permissions and group visibility before publishing.
    • Keep cron active if you use the scheduler.
    • Use templates to make PDFs readable, not to hide data.
    • Do not turn a dashboard into an ownerless chart album.
    • Document which report answers each question and who reviews it.

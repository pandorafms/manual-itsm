    Instalación¶

    Instalar Pandora ITSM tiene una parte sencilla y otra que se complica justo cuando alguien decide improvisar. El script oficial hace casi todo: instala las dependencias, crea la base de datos, carga el esquema y deja la consola lista. Lo que no hace es adivinar si el servidor se quedó corto de memoria, si la base de datos está en otro sitio o si alguien va a dejar la contraseña por defecto hasta el día de la auditoría.

    La tesis de este capítulo es simple: la instalación no suele fallar por el software, sino por la prisa. Con dos gigas de memoria, diez gigas de disco y una decisión clara sobre la base de datos, el resto es seguir el orden. Sin eso, el script se detiene, y hace bien.

    La instalación por defecto es la instalación en línea: un script oficial que se ejecuta como root, instala las dependencias, crea la base de datos, carga el esquema y los datos iniciales y deja la consola en http://<IP-o-FQDN>/pandoraitsm. Para entornos sin salida a Internet está la instalación offline.

    Qué se va a instalar¶

    El instalador deja en el servidor estas piezas:

    • Consola web en /var/www/html/pandoraitsm.
    • Servidor web Apache y PHP-FPM.
    • Base de datos MySQL o Percona, local o externa.
    • Esquema y datos iniciales de Pandora ITSM.
    • Cron cada cinco minutos para las tareas internas.
    • Servidor de chat y sus dependencias de Node.js.
    • Configuración en include/config.inc.php.

    No es un servicio gestionado ni una aplicación de escritorio. Todo se consume desde el navegador, y el servidor sigue siendo responsabilidad de quien lo administra: parchear, copiar y vigilar no vienen incluidos en el paquete.

    Antes de empezar¶

    Antes de ejecutar el instalador, comprueba estos puntos:

    • Tienes acceso root o sudo en el servidor.
    • El servidor tiene un nombre de host o FQDN resoluble.
    • La zona horaria es la correcta; el instalador la fija con TZ.
    • Hay salida a Internet y acceso a packages.pandorafms.com.
    • Los puertos 80 y 443 están libres. Si la base de datos es externa, el 3306 también debe estar accesible desde el servidor.
    • SELinux y el cortafuegos permiten el tráfico web.
    • Has decidido si la base de datos será local o externa.
    • Si has decidido instalarla de forma externa, tienes las contraseñas de la base de datos preparadas y cumplen la política de MySQL.
    • Si vas a reinstalar, tienes una copia de seguridad o una instantánea de la máquina.

    El instalador aborta si detecta paquetes de Pandora ITSM, el directorio /var/www/html/pandoraitsm o una base de datos con el mismo nombre. No intenta limpiar una instalación anterior por su cuenta. Si tu plan era «ya veremos», el instalador tiene otro: parar.

    Instalación en línea¶

    La instalación en línea se lanza con un único comando, sea cual sea la distribución. Ejecútalo como root:

    curl -SsL https://pfms.me/deploy-pandora-itsm | bash

    El script detecta el sistema y descarga el instalador correspondiente. El resto de este capítulo explica qué hace, qué variables acepta y cómo comprobarlo.

    Requisitos del sistema¶

    Hardware¶

    Requisito Mínimo Recomendado
    CPU 2,4 GHz, doble núcleo Cuatro núcleos o más según usuarios concurrentes
    RAM 2 GB 4 GB
    Disco 10 GB libres 20 GB o más, según histórico y adjuntos
    Red 100 Mbps 1 Gbps

    El instalador comprueba la memoria y el espacio antes de tocar nada. En EL9 y EL10 exige 9 GB libres en /var y 1 GB en /usr. Si el servidor no cumple el mínimo, el script se detiene. No es una sugerencia: es una condición.

    Sistemas operativos¶

    Sistema Versiones admitidas
    RHEL, Rocky Linux o AlmaLinux EL 9 y EL 10
    Ubuntu Server 22.04 y 24.04

    Software¶

    Componente Versión
    PHP 8.2 o 8.4
    MySQL o Percona 8.0 o 8.4 según la distribución
    Servidor web Apache con PHP-FPM
    Navegador Chrome, Edge, Firefox o Safari actualizados; resolución mínima 1280 × 720

    En EL10 solo se admite MySQL/Percona 8.4. En EL9 y Ubuntu se admiten 8.0 y 8.4. El instalador configura la versión de PHP y de MySQL con las variables PHPVER y MYVER. No hay premio por usar la versión que ya no se soporta.

    Extensiones PHP¶

    La consola necesita las extensiones mysqli, gd, session, mbstring, ldap, gettext, imap, phar y zip. El instalador las instala con los paquetes de PHP; si haces una instalación manual, compruébalas antes de abrir la consola. Un error de extensión se disfraza de pantalla en blanco, y la pantalla en blanco nunca da buenas noticias.

    Base de datos¶

    Pandora ITSM necesita una base de datos MySQL o Percona. Puede estar en el mismo servidor o en uno dedicado. Una base de datos compartida es válida, pero el rendimiento depende de la capacidad del servidor y del volumen de histórico: los tickets, sus adjuntos y la auditoría crecen con el uso.

    Si la base de datos es externa, prepara antes el host, el puerto, el usuario y los permisos. El instalador puede crear la base de datos y el usuario, o usar unos ya existentes con SKIP_DATABASE_INSTALL=1.

    Modos de instalación¶

    Modo Cuándo usarlo Necesita Internet
    En línea Instalación nueva en un servidor con salida a Internet Sí
    Offline Servidores aislados o con acceso restringido No
    Web manual Depuración o instalación pieza a pieza con install.php Depende

    La instalación web manual no es el camino recomendado para producción. Sirve para mirar bajo el capó y para entornos muy controlados; el script en línea es el procedimiento soportado. No confundas «puedo hacerlo a mano» con «debería hacerlo a mano».

    Instalación en línea paso a paso¶

    Ejecutar el script¶

    El script genérico acepta la configuración por variables de entorno y detecta el sistema para descargar el instalador correspondiente. Estos son los valores que puedes ajustar:

    Variable Valor por defecto Para qué sirve
    TZ Europe/Madrid Zona horaria del sistema
    MYVER 84 Versión de MySQL/Percona: 80 u 84
    PHPVER 8.4 Versión de PHP: 8.2 u 8.4
    DBHOST 127.0.0.1 Host de la base de datos
    DBNAME pandoraitsm Nombre de la base de datos
    DBUSER pandoraitsm Usuario de la base de datos
    DBPASS P4ndor4.itsm Contraseña del usuario de la base de datos
    DBPORT 3306 Puerto de MySQL
    DBROOTPASS P4ndor4.itsm Contraseña de root de MySQL
    DBROOTUSER root Usuario administrador de MySQL
    SKIP_PRECHECK 0 Omite la comprobación de instalación previa
    SKIP_KERNEL_OPTIMIZATIONS 0 Omite los ajustes de kernel
    SKIP_DATABASE_INSTALL 0 Usa una base de datos ya creada
    POOL_SIZE Calculado según la RAM Tamaño del pool de PHP-FPM

    Las contraseñas de ejemplo deben sustituirse siempre. Si usas MySQL 8 con la política de contraseñas activa, P4ndor4.itsm puede no cumplir los requisitos; elige una contraseña más larga y con mayúsculas, minúsculas, números y símbolos. La comodidad de hoy es la incidencia de mañana.

    Ejemplo para EL10¶

    env TZ='Europe/Madrid' \
    MYVER='84' \
    PHPVER='8.4' \
    DBHOST='127.0.0.1' \
    DBNAME='pandoraitsm' \
    DBUSER='pandoraitsm' \
    DBPASS='CambiaEstaClave' \
    DBPORT='3306' \
    DBROOTPASS='CambiaEstaClaveRoot' \
    DBROOTUSER='root' \
    SKIP_PRECHECK=0 \
    SKIP_KERNEL_OPTIMIZATIONS=0 \
    SKIP_DATABASE_INSTALL=0 \
    bash itsm_deploy_enterprise_entrypoint.sh

    El script genérico detecta EL10 y descarga el instalador de EL10. Para usar PHP 8.2, cambia PHPVER='8.2'. En EL10 el instalador solo admite MYVER=84; en EL9 puedes usar MYVER='80' si tu base de datos es MySQL 8.0.

    Qué hace el script¶

    1. Comprueba el sistema operativo, la memoria, el disco y los permisos.
    2. Añade los repositorios de Pandora y de Remi para PHP.
    3. Instala Apache, PHP-FPM, MySQL o Percona, Node.js y las extensiones.
    4. Crea la base de datos y el usuario, o reutiliza los existentes.
    5. Carga integria_db.sql y integria_dbdata.sql.
    6. Escribe include/config.inc.php con los datos de conexión.
    7. Configura el cron de integria_cron.php cada cinco minutos.
    8. Instala y arranca el servidor de chat.
    9. Aplica ajustes de kernel y de PHP-FPM.
    10. Muestra la URL de acceso y las credenciales iniciales.

    El script guarda el detalle en /tmp/pandoraitsm-deploy-enterprise-el9-AAAA-MM-DD.log (o el nombre correspondiente a tu sistema). Si algo falla, ese log es lo primero que hay que leer. Adivinar el error cuesta más que abrir el fichero.

    Resultado¶

    Al terminar, el script muestra una dirección similar a:

    http://192.0.2.10/pandoraitsm

    y las credenciales iniciales. Abre esa dirección desde un navegador con acceso al servidor.

    Instalación offline¶

    La instalación offline usa un paquete con las dependencias y un script local. El flujo es:

    1. Descarga el paquete de dependencias y el script de tu distribución.
    2. Cópialos al servidor aislado.
    3. Descomprime el paquete.
    4. Ejecuta itsm_deploy_enterprise_local_el10.sh como root, con las mismas variables que en la instalación en línea.

    La instalación offline no está soportada en Ubuntu con los scripts actuales.

    Primer acceso¶

    URL de la consola¶

    La consola queda en:

    http://<IP-o-FQDN>/pandoraitsm

    Si has configurado TLS, usa https://. La ruta /pandoraitsm es la que escribe el instalador en config.inc.php; no la cambies sin actualizar la configuración de Apache.

    Licencia y login¶

    Si usas el instalador web manual, la primera pantalla pide aceptar la licencia. Con el script en línea, el primer acceso es directamente la pantalla de login.

    Las credenciales iniciales son:

    Usuario Contraseña
    admin pandoraitsm

    Cambia la contraseña en el primer acceso

    La cuenta admin es un usuario de instalación. Cámbiale la contraseña antes de conectar la consola a la red de producción y crea después tus propios usuarios. No compartas la cuenta admin entre varias personas.

    Una contraseña por defecto es una bienvenida, no una política de seguridad. Cuanto antes desaparezca, mejor.

    Cambio de contraseña¶

    Entra con admin, abre el menú de usuario y cambia la contraseña. A continuación, crea un usuario con tu nombre, asígnale el perfil y el grupo que necesite y reserva admin para tareas de administración.

    Datos iniciales y «Reset all data»¶

    La instalación carga integria_dbdata.sql, que incluye datos de ejemplo: empresas, contactos, tickets y otros registros que sirven para ver la consola con contenido desde el primer día.

    Si quieres empezar con el sistema limpio:

    1. Abre Setup → Setup → Old data maintenance.
    2. Pulsa Reset all data.
    3. Confirma dos veces en los diálogos.

    Reset all data borra datos y adjuntos

    La opción elimina los datos de la base de datos y los ficheros adjuntos. Conserva el usuario admin actual y algunos ajustes de configuración. No hay vuelta atrás: haz una copia antes si necesitas conservar algo.

    Los datos de ejemplo son estupendos para una demostración y un pasivo en producción. El botón existe para que no tengas que borrarlos a mano tabla por tabla.

    Verificación y posinstalación¶

    Servicios¶

    Comprueba que están activos el servidor web, PHP-FPM y la base de datos:

    # RHEL, Rocky Linux y AlmaLinux
systemctl status httpd php-fpm mysqld

# Ubuntu
systemctl status apache2 php8.4-fpm mysql

    Ajusta el nombre de PHP-FPM a la versión instalada (php8.2-fpm o php8.4-fpm). Un servicio que no compruebas es un servicio que falla el lunes.

    Cron¶

    El instalador deja tres tareas programadas, todas cada cinco minutos:

    */5 * * * * root php /var/www/html/pandoraitsm/include/integria_cron.php
*/5 * * * * php /var/www/html/pandoraitsm/include/crm_cron.php
*/5 * * * * php /var/www/html/pandoraitsm/include/campaign_cron.php

    Cada una tiene su responsabilidad:

    Tarea Qué hace
    integria_cron.php Núcleo: comprobaciones diarias (calendario, proyectos, tareas, cambios, autowu, cierre automático de tickets, limpieza y notificaciones), cola de correo, recordatorios de tareas de CRM e inventario, cron Enterprise, SLA y reglas de workflow de tiempo.
    crm_cron.php CRM: Gmail enviado y recibido, workflows de contactos y oportunidades, vencimiento de planificaciones, correos de tareas pendientes, avisos de actividad, transcripciones de Google Meet y llamadas de Zadarma.
    campaign_cron.php Campañas: ejecuta las campañas pendientes y comprueba los rebotes de correo.

    El inventario tiene además su propio script, inventory_cron.php: sincroniza el inventario de los nodos de Pandora FMS, caduca las planificaciones vencidas y limpia objetos huérfanos. El instalador actual no lo añade a /etc/crontab; si lo necesitas, añade su entrada:

    */5 * * * * php /var/www/html/pandoraitsm/include/inventory_cron.php

    Comprueba que las tareas están activas y que los ficheros existen:

    grep pandoraitsm /etc/crontab
ls -l /var/www/html/pandoraitsm/include/*_cron.php

    Si una tarea no aparece, revisa /etc/crontab y el log de la aplicación. Un cron que no se ejecuta no avisa; simplemente deja de hacer su trabajo.

    Logs¶

    Log Contenido
    /var/www/html/pandoraitsm/pandora_itsm.log Errores de la aplicación
    /var/log/php-fpm/www-error.log Errores de PHP y PHP-FPM
    /tmp/pandoraitsm-deploy-enterprise-<sistema>-AAAA-MM-DD.log Instalación

    Si PHP no arranca o la consola devuelve un error 500, empieza por /var/log/php-fpm/www-error.log: ahí aparece el error real, no el mensaje genérico que ve el navegador.

    Seguridad mínima¶

    • Cambia la contraseña de admin.
    • Crea usuarios propios y elimina o desactiva los de ejemplo.
    • Decide si conservas los datos de ejemplo.
    • Revisa el cortafuegos: solo 80/443 deben estar abiertos al exterior.
    • Configura TLS si la consola va a salir de la red interna.
    • Comprueba que la base de datos no está expuesta a Internet.
    • Programa copias de seguridad antes de cargar datos reales.

    Reinstalación y limpieza¶

    El instalador no sobrescribe una instalación existente. Si detecta paquetes, /var/www/html/pandoraitsm o la base de datos, se detiene. Para reinstalar desde cero hay que retirar antes:

    • Los paquetes de Pandora ITSM.
    • El directorio /var/www/html/pandoraitsm.
    • La base de datos y el usuario de la base de datos.
    • La entrada de cron.
    • La configuración de Apache y PHP-FPM si se ha personalizado.

    No hay un desinstalador automático. Si solo quieres volver a empezar con los datos, usa Reset all data en lugar de reinstalar. Si necesitas conservar algo, haz una copia de la base de datos y de los adjuntos antes de borrar. La reinstalación es el último recurso, no el primero.

    Problemas frecuentes¶

    Síntoma Causa probable Comprobación
    El script dice que el sistema no es compatible Distribución o versión distinta de EL9, EL10 o Ubuntu 22.04/24.04 Revisa /etc/os-release y usa el script correcto
    Falla la comprobación de memoria o disco Menos de 2 GB de RAM o menos de 10 GB libres Amplía el servidor o libera espacio
    No conecta con packages.pandorafms.com Sin salida a Internet o DNS Prueba ping y revisa el proxy
    PHP o MySQL no admitidos Versión fuera de la ventana 8.2/8.4 o 8.0/8.4 Ajusta PHPVER y MYVER
    MySQL rechaza la contraseña Política de contraseñas de MySQL 8 Usa una contraseña más fuerte
    El instalador detecta una instalación previa Paquetes, directorio o base de datos existentes Limpia o usa otra máquina
    La consola no responde tras el script Apache, PHP-FPM o SELinux Revisa servicios y logs
    La consola abre pero no carga datos Base de datos o configuración Revisa config.inc.php y el log de la aplicación

    Si el problema no está en esta tabla, consulta la Parte 14 (FAQ) y adjunta el log de instalación al abrir una incidencia. Un «no funciona» sin log es una conversación que empieza mal.

    Siguientes pasos¶

    Con la consola operativa, el orden recomendado es:

    1. Revisa la licencia y la política de versiones (1.3 y 1.4).
    2. Configura usuarios, grupos y perfiles (Parte 02).
    3. Ajusta el correo (Parte 03).
    4. Programa las copias de seguridad y revisa la configuración avanzada (Parte 12).
    5. Solo cuando tengas una versión estable, planifica la actualización (1.2).

    Instalar es el principio, no el final. La instalación deja el motor en marcha; lo que venga después depende de cómo lo configures y de cuánto respetes los datos que va a guardar.

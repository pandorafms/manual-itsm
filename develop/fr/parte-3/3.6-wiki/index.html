    Wiki¶

    Le wiki interne est le carnet partagé de l'équipe : procédures, runbooks, comptes rendus, liens et cette explication que quelqu'un a écrite une fois et que tout le monde consulte chaque mois. Ce n'est pas une base de connaissance d'incidents, même si cela y ressemble ; la base de connaissance répond à « comment résout-on ce problème », le wiki répond à « comment cela fonctionne-t-il à l'intérieur ».

    Pandora ITSM inclut un wiki simple, avec des permissions par profil et par page. Cette simplicité est une vertu : il ne cherche pas à être Confluence, mais il n'oblige pas non plus à monter un serveur séparé pour documenter le quotidien.

    La 3.5 Base de connaissance est destinée aux solutions d'incidents ; le wiki, aux procédures et à la documentation interne.

    Permissions de lecture et d'écriture¶

    L'accès général est contrôlé par les bits du profil :

    • WR : permission de lecture.
    • WW : permission d'écriture.
    • WM : administration du wiki, y compris les listes d'accès.
    • Superadministrateur : peut tout, comme dans le reste du produit.

    Il existe aussi un ACL étendu par page. Dans Wiki → Wiki, à l'intérieur de chaque page, Read ACL et Write ACL décident quels utilisateurs peuvent la lire ou la modifier.

    La règle la plus souvent oubliée : si la liste ACL est vide, la page est accessible à tous. Quand on ajoute un utilisateur, seul cet utilisateur —et les administrateurs du wiki— y ont accès. Un ACL vide ne signifie pas « personne » ; il signifie « tout le monde ».

    Autres particularités :

    • Un utilisateur peut être ajouté à un ACL sans avoir les permissions WR/WW du profil ; dans ce cas, l'ACL ne lui sert à rien.
    • Un utilisateur peut apparaître plusieurs fois dans une liste ; pour l'exclure, il faut supprimer toutes ses occurrences.
    • Pandora ITSM ne prévient pas lorsqu'un ACL exclut quelqu'un. La documentation ne remplace pas un test avec l'utilisateur réel.

    Menu du wiki¶

    Dans Wiki → Admin pages, on gère les pages, y compris la page spéciale side_menu qui définit le menu latéral.

    Pour ajouter un lien vers une page interne, on utilise le nom de la page et une URL comme :

    index.php?sec=wiki&sec2=operation/wiki/wiki&page=Office

    Pour un lien externe, l'URL doit inclure http:// ou https://. Le lien s'ouvre dans la même fenêtre ; prévenez donc ceux qui l'utilisent : quitter la console par accident est une tradition bien ancrée.

    Les liens du menu peuvent être supprimés depuis Admin pages. Après enregistrement, il faut revenir pour voir les changements. S'ils n'apparaissent pas, ce n'est pas de la magie noire : c'est le cache du menu.

    Syntaxe de base¶

    La syntaxe complète se trouve dans Wiki → Syntax. L'essentiel :

    En-têtes¶

    !Heading H2
!!Heading H3
!!!Heading H4
!!!!Heading H5

    Plus il y a de points d'exclamation, plus le niveau est bas. Ils doivent être au début de la ligne. Après enregistrement, chaque titre a un bouton pour modifier uniquement cette section.

    Listes¶

    * Fruit
** Apple
*** Granny smith
** Orange
* Vegetables

    Les listes numérotées utilisent #, ##, ### avec la même logique.

    Styles¶

    '''gras'''
''italique''
'__souligné__'
'--barré--'

    Liens¶

    [Page d'exemple|sample subpage]
[Page externe|https://www.example.com/]
[http://www.example.com/]

    Les liens relatifs doivent commencer par ./ ; sinon, ils sont interprétés comme des pages internes du wiki.

    Images¶

    Les images internes se téléversent dans Wiki → Upload et se référencent ainsi :

    [./wiki_data/upload/image_name.png]
[./wiki_data/upload/dir1/image_name.png]

    Les images externes peuvent aussi être liées, mais mieux vaut les héberger sur le serveur. Options utiles :

    [http://example.com/image.jpg|link=http://example.com/|center|title=Example image]

    Table des matières, code et formatage¶

    • {TOC} génère une table des matières à partir des en-têtes.
    • {{ ... }} affiche du code sans formatage.
    • ---- insère une ligne horizontale.
    • ^ échappe les caractères spéciaux.
    • {html}...{/html} insère du HTML brut. Un en-tête inséré ainsi n'aura pas de bouton d'édition de section.
    • {br} insère un saut de ligne.

    Bonnes pratiques¶

    • Utiliser le wiki pour les procédures stables, pas pour le quotidien d'un ticket.
    • Définir une page d'index et un menu latéral avec les pages importantes.
    • Attribuer un responsable à chaque page et la réviser quand le produit change.
    • Ne pas coller de mots de passe, de jetons ou de données personnelles.
    • Si une page a besoin de dix sous-pages pour expliquer une procédure, la procédure doit probablement être simplifiée.
    • Tester les ACL avec un utilisateur non privilégié avant de leur faire confiance.

    Autenticación y seguridad¶

    Autenticarse no es rellenar un formulario: es demostrar quién eres antes de que el producto te deje hacer nada. En Pandora ITSM esa puerta se puede quedar en casa, delegarse en un directorio o compartirse con Pandora FMS. Elegir mal el método no rompe la consola el primer día; la deja abierta o deja fuera a quien debería entrar.

    La tesis de este capítulo es sencilla: la autenticación se configura una vez y se revisa cada vez que cambia la organización. Un directorio que ya no existe, una política de contraseñas que nadie recuerda y un 2FA que depende del correo son formas muy eficaces de quedarse fuera de la propia herramienta.

    Cómo se entra en Pandora ITSM¶

    El acceso tiene dos capas que conviene no mezclar:

    • Autenticación: quién eres. La resuelve el método configurado.
    • Autorización: qué puedes hacer. La resuelven los grupos y perfiles de 2.1.

    Un usuario puede autenticarse correctamente y no tener permisos para nada. O al revés: tener un perfil enorme y no poder entrar porque su directorio no responde. La primera capa está aquí; la segunda, en 2.1.

    Los superadministradores son la excepción: siempre se autentican de forma local en Pandora ITSM, aunque el resto de usuarios use AD, LDAP o Pandora FMS. Es una decisión deliberada para que un fallo del directorio no deje el producto sin llave maestra.

    Método de autenticación¶

    La configuración está en Setup → Setup → Authentication configuration.

    Método Qué usa Cuándo tiene sentido
    Local Pandora ITSM Usuarios y contraseñas en la base de datos Instalaciones pequeñas o sin directorio central
    LDAP Directorio LDAP estándar Organizaciones con OpenLDAP, 389 Directory Server, etc.
    Active Directory Microsoft AD Empresas con cuentas y grupos en AD
    Pandora FMS API v2 de un servidor PFMS Entornos que ya centralizan usuarios en Pandora FMS

    Pandora ITSM consulta primero el método remoto configurado. Si el usuario existe y la contraseña es correcta, entra; si falla, puede usar la autenticación local solo si el fallback está activado.

    Autenticación local¶

    Es la opción por defecto y la más sencilla: los usuarios viven en tusuario y la contraseña se valida contra la base de datos.

    • El alta y la edición se hacen en People → User management (2.1).
    • La política de contraseñas se aplica aquí.
    • La recuperación de contraseña envía un enlace por correo, así que necesita SMTP operativo.
    • Los superadministradores siempre usan esta vía.

    Para una instalación pequeña es suficiente. Para una organización con directorio, duplicar usuarios en dos sitios suele acabar en cuentas huérfanas.

    Active Directory¶

    Delegar en Microsoft Active Directory permite centralizar cuentas y credenciales. Pandora ITSM sigue necesitando el perfil y el grupo: AD dice quién eres; ITSM decide qué puedes hacer.

    Campos de conexión:

    Campo Qué indica
    Active directory server Host o IP del controlador de dominio
    Active directory port Puerto, normalmente 389 o 636
    Domain Dominio de AD
    Start TLS Cifra la conexión con TLS

    Opciones importantes:

    • Fallback to local authentication: si AD falla, permite autenticar con la contraseña local. Útil como red de seguridad; también es una puerta que hay que vigilar.
    • Advanced Configuration AD: permite asociar grupos de AD con perfiles y grupos de Pandora ITSM. Es la forma de que un usuario de AD herede el perfil correcto.
    • Automatically create remote users: crea el usuario en ITSM la primera vez que entra. Hay que elegir nivel, perfil, grupo y empresa; la lista negra (Automatically create blacklist) evita que ciertas cuentas se creen solas.
    • Test: prueba la conexión antes de guardar. Si falla, el problema suele ser DNS, TLS, dominio o credenciales de servicio.

    LDAP¶

    LDAP es el equivalente genérico de AD: un directorio con usuarios y grupos. Pandora ITSM soporta LDAPv1, LDAPv2 y LDAPv3.

    Campo Qué indica
    LDAP server Host o IP del servidor LDAP
    LDAP port Puerto, normalmente 389 o 636
    LDAP version LDAPv1, LDAPv2 o LDAPv3
    Start TLS Cifra la conexión
    Base DN Punto de partida de la búsqueda
    Login attribute Atributo que contiene el nombre de usuario (uid, sAMAccountName, etc.)

    Igual que en AD, existen Fallback to local authentication, Automatically create remote users y lista negra. El botón Test comprueba la conexión.

    Los errores típicos son un Base DN demasiado alto, un atributo de login equivocado o un certificado TLS que no valida. Si el bind falla, el usuario ni siquiera llega a comprobar su contraseña.

    Pandora FMS¶

    Pandora ITSM puede delegar la autenticación en un servidor Pandora FMS. Es útil cuando ya hay un PFMS centralizando usuarios y no quieres mantener dos directorios.

    • URL to Pandora FMS setup: la URL completa a la API v2, por ejemplo https://<host>/pandora_console/api/v2.
    • Token: el token del usuario admin de PFMS para la API v2.
    • Test: comprueba que la conexión funciona antes de guardar.

    La creación automática de usuarios permite asignar nivel, perfil, grupo y empresa. Elige siempre el mínimo privilegio; una auto-creación con perfil de administrador es una puerta abierta con pegatina de bienvenida.

    La contraseña del usuario remoto se administra en el servidor PFMS. Si cambias la contraseña en ITSM, no estás cambiando la de PFMS.

    Autenticación en dos pasos¶

    La autenticación en dos pasos (2FA) añade una segunda prueba después de la contraseña. Pandora ITSM se integra con Google Authenticator y aplicaciones compatibles TOTP.

    En Setup → Setup → Authentication configuration → Two-factor authentication:

    • Two-factor authentication: activa la funcionalidad.
    • Force 2FA for all users: obliga a los usuarios a configurarla.
    • Warning 2FA for all users: solo les avisa de que deberían configurarla.

    Elige una de las dos opciones de comportamiento antes de guardar. Si no fuerzas ni avisas, el 2FA queda disponible pero nadie se entera.

    Cada usuario la activa en People → Edit my user:

    1. Activa Two-factor authentication.
    2. ITSM genera una clave y un código QR (Pandora ITSM: <id-user> + clave).
    3. Escanea el QR o introduce la clave en la aplicación.
    4. Introduce el código generado y pulsa Validate code.
    5. En el siguiente inicio de sesión, después de la contraseña, pide el código temporal.

    Si un usuario pierde el dispositivo, un superadministrador puede usar Reset double factor authentication code. Si el que pierde el dispositivo es el propio superadministrador, el reinicio se hace desde su sesión: ITSM envía un correo con un enlace válido durante 15 minutos. Por eso SMTP debe funcionar y el reloj del servidor debe estar sincronizado; un reloj desfasado invalida los códigos.

    Política de contraseñas¶

    En Setup → Setup → Password policy setup. La política no se aplica a los superadministradores.

    Opción Qué hace
    Enable password policy Activa el resto de reglas
    Min. size password Longitud mínima; por defecto 5
    Password must have numbers Exige al menos un número
    Password must have symbols Exige al menos un símbolo
    Password expiration (days) Caducidad; 0 significa que no caduca
    Force password change on first login Obliga a cambiarla al entrar
    User blocked if login fails (minutes) Minutos de bloqueo tras los intentos fallidos
    Number of failed login attempts Intentos antes del bloqueo

    Si la política está activa, la generación automática de contraseñas también la respeta. Y si no está activa, las demás opciones no hacen nada: el interruptor general manda.

    Sesión y opciones de seguridad¶

    En Setup → Setup → General setup hay varias opciones que afectan al acceso:

    • Session timeout (secs): tiempo máximo de sesión; por defecto 9000 segundos.
    • Enable HTTPS access: fuerza HTTPS en la consola.
    • Use SSL certificate y Path of SSL certificate: certificado y ruta; por defecto /etc/ssl/certs/pandoraitsm.pem.
    • Access port: puerto de acceso, 80 por defecto.
    • Public access to server: URL pública; debe incluir el sufijo /pandoraitsm. Si se configura mal, la consola puede quedar inaccesible.
    • API password: contraseña global para peticiones a la API. Los tokens v2 son por usuario; no los confundas.
    • Login hash password: se usa para generar una URL única de preautenticación.
    • Hide version: oculta la versión en el pie y en el login.
    • Show modal last time logged: muestra al usuario la fecha y hora de su último acceso.

    Si activas HTTPS, revisa el certificado y la cadena de confianza. En PHP puede hacer falta declarar el fichero de CA en openssl.cafile. Un certificado caducado no avisa en la documentación; avisa el navegador.

    Problemas frecuentes¶

    Síntoma Causa probable Comprobación
    El superadministrador no entra con AD/LDAP Es local por diseño Usa su contraseña local
    Un usuario remoto no entra y su contraseña es correcta Fallback local desactivado o bind remoto fallando Revisa el método y el Test
    LDAP/AD no conecta DNS, puerto, TLS o Base DN Prueba el Test y revisa el log
    El usuario se crea sin perfil o grupo Auto-creación incompleta Revisa nivel, perfil, grupo y empresa
    El código 2FA no vale Reloj desincronizado Sincroniza la hora del servidor
    No llega el enlace de reinicio 2FA del superadmin SMTP caído Revisa la configuración de correo
    La consola no carga tras activar HTTPS Certificado o URL pública incorrectos Revisa Apache, certificado y access_public
    El usuario queda bloqueado Intentos fallidos Espera los minutos configurados o revisa el usuario

    Buenas prácticas¶

    • Usa un directorio central si ya existe; no dupliques cuentas.
    • Mantén un superadministrador local como vía de rescate.
    • Elige mínimo privilegio en la auto-creación de usuarios remotos.
    • Fuerza 2FA a los administradores, no solo lo avises.
    • Revisa la política de contraseñas después de cada cambio de organización.
    • Comprueba HTTPS y la URL pública antes de guardar.
    • Documenta qué método usa cada colectivo y quién puede cambiarlo.
    • Prueba el acceso remoto y el local antes de dar por cerrada la configuración.

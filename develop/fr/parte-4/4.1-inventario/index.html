    Inventaire¶

    L'inventaire de Pandora ITSM n'échoue pas à cause de la console : il échoue à cause du modèle de données. Une liste d'équipements se monte en dix minutes ; un inventaire utile exige de décider au préalable quels types d'objet existent, quels champs sont partagés, qui peut voir quoi et comment les objets se relient entre eux. Le reste —vues, filtres et widgets— vient presque tout seul.

    Ce chapitre couvre l'inventaire complet : types d'objet, champs personnalisés et externes, objets, hiérarchie, stock, états, étiquettes, ACL, import CSV et inventaire distant depuis Pandora FMS. L'intégration avec Pandora FMS est détaillée au chapitre 11.3 ; ici, nous expliquons ce que l'inventaire en fait.

    L'inventaire sert à savoir quels objets l'organisation possède, où ils se trouvent, qui les utilise et à quels contrats, tickets et changements ils sont liés. Il ne découvre pas le réseau tout seul. Les objets entrent à la main, par CSV ou depuis la synchronisation avec Pandora FMS.

    Types d'objet¶

    Un type d'objet définit le modèle de données d'un ensemble d'objets. Un Computer n'a pas les mêmes champs qu'une licence ou qu'un contrat. Le menu est Inventory → Object Types.

    Pour créer un type, cliquez sur Create, renseignez ses caractéristiques et cliquez de nouveau sur Create. Pour le modifier, cliquez sur son nom. La liste permet de dupliquer un type avec tous ses champs personnalisés via Duplicate.

    Les paramètres du type sont les suivants :

    Paramètre À quoi il sert
    Name Nom du type d'objet.
    Icon Icône associée ; les images sont déposées dans images/objects/.
    Show in tree view Si activé, le type apparaît comme racine dans la vue arborescente.
    Min. stock Stock minimum du type.
    Max. stock Stock maximum du type.
    Catalogs to show in overview Catalogues affichés comme sections dans le résumé de l'objet.
    Description Description du type.
    Sync interval Fréquence de synchronisation avec Pandora FMS : Never, Weekly, Every 15 days, Monthly ou First time only.

    Sync interval n'apparaît que lorsque des nœuds Pandora FMS sont configurés et que le type est associé à un schéma Pandora FMS. Sans intégration, il n'y a rien à synchroniser.

    Champs personnalisés et globaux¶

    Chaque type possède ses propres champs. Ils se gèrent depuis Actions → Fields dans la liste des types : on les crée avec Create, on les modifie en cliquant sur leur nom et on les ordonne avec les flèches de la colonne d'actions. La suppression se trouve au même endroit.

    Les champs globaux sont l'exception utile : ils sont définis une seule fois dans Inventory → Object types → Global Fields et ajoutés à tous les types. Chaque type peut les masquer ou changer leur ordre, mais le champ reste le même. Ils servent pour ce qui est toujours présent : numéro de série, emplacement, date d'achat.

    Les propriétés communes à tous les champs sont les suivantes :

    Propriété Effet
    Unique Un seul objet peut porter cette valeur ; elle fait office d'identifiant.
    Inherit L'objet hérite du propriétaire, des utilisateurs et des entreprises de l'objet parent.
    Show in list Le champ apparaît par défaut dans la liste générale et peut servir de colonne.
    Prevent updates Le champ n'est pas mis à jour à la réception de données d'inventaire distant.

    Les types de données disponibles sont : numérique, case à cocher, texte, liste d'options, champ externe, date, lien web, mot de passe et valeur avec unité. Dans la liste d'options, les valeurs sont séparées par des virgules dans Combo values.

    Champs externes¶

    Un champ externe lit des informations dans une table supplémentaire de la base de données, créée à la main avec le DB Manager. C'est le moyen de relier l'inventaire à vos propres catalogues sans transformer chaque valeur en liste statique.

    Dans un champ simple, deux valeurs sont obligatoires : External table name, le nom exact de la table, et Field to be displayed, la colonne affichée. Les objets se mettent à jour seuls lorsque la table change. Primary key, Foreign key et Parent table name restent vides : ils concernent les champs composites.

    Un champ composite enchaîne deux tables. La table parente possède une clé primaire ; la table fille possède une clé étrangère qui pointe vers elle. Lors de la création du champ parent, on indique la Primary key ; pour le champ fils, la Foreign key et le Parent table name. Le résultat est une liste déroulante qui dépend de la valeur précédente : si l'on efface le parent, le fils peut être choisi de nouveau.

    Le cas classique est le pays et la ville. Créez les tables avec le DB Manager :

    CREATE TABLE t_country (
    id_country INT PRIMARY KEY,
    name TEXT
);

CREATE TABLE t_city (
    id_city INT,
    name TEXT,
    id_country INT,
    FOREIGN KEY (id_country) REFERENCES t_country(id_country)
);

    Ajoutez les valeurs avec INSERT, créez le champ Country sur t_country et le champ City sur t_city avec id_city comme clé primaire, id_country comme clé étrangère et t_country comme table parente. Dès lors, tout objet du type choisi peut sélectionner un pays et une ville. Si le champ possède Show in list, il apparaît aussi comme colonne et comme filtre.

    Objets d'inventaire¶

    Les objets se créent dans Inventory → Lists avec Create. Avant de remplir les champs, il faut décider qui les voit :

    • Owner : propriétaire de l'objet.
    • Associated companies : entreprises associées.
    • Associated users : utilisateurs associés.
    • Public : si activé, tout le monde le voit.

    Ces quatre champs constituent l'ACL de l'objet. Un objet est visible pour son propriétaire, pour les utilisateurs associés, pour les utilisateurs des entreprises associées et pour tous s'il est public. Les autres ne le voient pas.

    Un objet peut avoir un Parent, ce qui crée une hiérarchie, et des relations avec d'autres objets. Il stocke aussi le type, l'état, le contrat, la date de réception, la date de sortie, la date EOL, une image et un code QR.

    La vue de l'objet comporte deux colonnes. À droite se trouvent les données principales et les actions ; à gauche, les onglets :

    • Champs personnalisés.
    • Tickets : historique des tickets associés.
    • Changes : changements associés.
    • Relations.
    • Tracker : historique des modifications de l'objet et de ses enfants.
    • Utilisateurs associés.

    Les objets de type Computer ajoutent Hardware, Software et Extended Info avec les informations collectées depuis Pandora FMS.

    Les objets peuvent être dupliqués depuis la liste avec Duplicate ; c'est le moyen rapide d'enregistrer dix équipements qui ne diffèrent que par le numéro de série. Ils peuvent aussi être reclassés dans un autre type : le système demande comment chaque champ source correspond au champ de destination, convertit les identifiants internes et laisse remplir les nouveaux champs à la main. Certains champs sont abandonnés ; il convient de vérifier le résultat.

    Vues, recherches et opérations massives¶

    Inventory → Lists propose quatre façons de regarder la même chose :

    • Résumé : page d'accueil avec l'état de l'inventaire et les principaux types.
    • Liste : tableau de données avec filtres, colonnes configurables et export.
    • Arborescence : hiérarchie parent-enfant, groupée par type.
    • Stock : contrôle des stocks, expliqué plus bas.

    La recherche filtre par texte libre —description, identifiant et champs personnalisés—, par état, par type d'objet et par taille de page. Le résultat peut être exporté en CSV.

    En mode liste, vous pouvez sélectionner plusieurs objets et lancer des opérations massives : supprimer, changer le type d'objet, le parent, l'entreprise, le contrat, le propriétaire ou l'état. La suppression est irréversible ; le reste peut être défait objet par objet.

    Contrôle du stock¶

    Le stock n'est pas un nombre isolé : il se calcule à partir de deux éléments. Chaque type possède min_stock et max_stock ; chaque objet possède une limite de relations (relation_limit, appelée Max relations dans l'interface).

    • Avec 0 ou vide, l'objet compte pour une unité et autorise un nombre illimité de relations.
    • Avec 1 ou plus, l'objet autorise au maximum ce nombre de relations et apparaît au second niveau du contrôle du stock.

    La vue de stock comporte deux niveaux. Le premier affiche chaque type avec son stock minimum, maximum et utilisé, une barre de pourcentage et des actions pour voir les objets, créer un ticket, créer un change ou programmer une tâche. Le second affiche les objets avec une limite de relations et leur pourcentage d'utilisation. Si le total descend sous le minimum, l'avertissement passe au rouge.

    États et étiquettes¶

    Inventory → Status gère les états des objets. Pandora ITSM fournit cinq états internes : New, In use, Unused, Issued et Missing. Ils peuvent être modifiés et vous pouvez ajouter vos propres états. Si un état attribué est supprimé, les objets concernés reviennent à New.

    Les étiquettes (Inventory → Tags) fonctionnent comme dans le reste de la console : nom, couleur et relation avec les objets. Elles ne s'affichent pas par défaut dans la liste ; ajoutez-les comme colonne ou filtrez par elles.

    ACL de l'inventaire¶

    L'inventaire possède son propre jeu de permissions :

    Bit Ce qu'il autorise
    VR Voir les objets auxquels on a accès.
    VW Créer, modifier et supprimer des objets ; inclut la lecture.
    VM Gérer tout l'inventaire : objets, types, états, étiquettes et catalogues.

    La lecture n'est pas globale : la visibilité de l'objet s'applique (public, propriétaire, utilisateur associé ou entreprise associée). L'écriture exige VW ou VM, et la gestion des types, états et étiquettes exige VM. Le superadministrateur contourne l'ACL. Le rôle de l'entreprise dans les autres sections est expliqué au chapitre 2.3.

    Tableaux de bord et widgets¶

    L'inventaire fournit ses propres widgets de tableau de bord :

    • Inventory by status : pourcentage par état, filtrable par type.
    • Inventory by object type : pourcentage par type, avec multi-sélection.
    • Top N stock inventory : les types avec le pourcentage d'utilisation le plus élevé.
    • Stock relations : stock global et stock par objet avec limite de relations.
    • Inventory counter : nombre d'objets.
    • Inventory type boxes : accès directs par type d'objet.

    Import depuis un fichier CSV¶

    L'import massif se trouve dans Inventory → Import CSV. Choisissez le type d'objet, vérifiez le séparateur —| par défaut— et téléchargez le modèle avec Download sample CSV. Le modèle change selon le type car il inclut ses champs personnalisés.

    Le fichier doit comporter un en-tête sur la première ligne et au moins neuf colonnes dans cet ordre :

    Position Colonne Contenu
    1 Name Nom de l'objet. Obligatoire.
    2 Owner Utilisateur propriétaire. Obligatoire et doit exister.
    3 Status État par libellé ou identifiant. Obligatoire.
    4 Receipt date Date de réception.
    5 Removal date Date de sortie.
    6 Description Description.
    7 Companies Identifiants d'entreprise séparés par des virgules.
    8 Associated user Identifiants d'utilisateur séparés par des virgules.
    9 Parent Identifiant de l'objet parent, s'il existe.
    10+ Champs personnalisés Dans l'ordre du modèle du type.

    Les entreprises et les utilisateurs acceptent les crochets et les espaces, mais une liste séparée par des virgules est l'option sûre. Les champs personnalisés sont validés selon leur type : nombres, listes fermées, dates, champs externes et unicité. Si une ligne échoue, l'import indique la ligne et le motif.

    Ce format n'est pas celui que décrivaient les versions précédentes de la documentation : elles listaient des colonnes de fabricant, de contrat, de type d'objet ou public. Dans la version actuelle, le type se choisit dans le formulaire et le reste vient du modèle. Le code fait référence.

    Inventaire distant depuis Pandora FMS¶

    L'inventaire distant ne reçoit pas directement de fichiers XML envoyés par les EndPoints : il se synchronise depuis Pandora FMS. Le serveur Pandora FMS collecte les informations avec ses EndPoints et Pandora ITSM les lit à travers le nœud configuré, en créant ou en mettant à jour les objets. L'envoi direct d'inventaire depuis un EndPoint vers Pandora ITSM n'existe plus.

    La configuration de destination se trouve dans Setup → Pandora FMS Inventory, section Remote Inventory :

    • Default owner : propriétaire des nouveaux objets. Il est obligatoire.
    • Associated companies : entreprises par défaut.
    • Associated users : utilisateurs par défaut.

    Ces valeurs remplissent les objets créés par la synchronisation et décident donc de leur visibilité. Le nœud Pandora FMS, ses identifiants et sa portée se configurent dans l'intégration ; le chapitre 11.3 couvre la procédure complète.

    La synchronisation n'est pas immédiate : chaque type d'objet fixe son rythme avec Sync interval (Never, Weekly, Every 15 days, Monthly ou First time only). Le type doit être associé au schéma Pandora FMS pour que l'option apparaisse.

    Le cron d'inventaire est la pièce qui fait fonctionner cet ensemble. Il exécute include/inventory_cron.php et doit figurer dans crontab, généralement toutes les cinq minutes :

    php /var/www/html/pandoraitsm/include/inventory_cron.php

    À chaque passage, il enregistre la marque inventory_crontask, synchronise l'inventaire des nœuds Pandora FMS en respectant l'intervalle de chaque type, expire les programmations échues et supprime les objets Missing qui n'ont plus de parent.

    Les EndPoints s'installent et se configurent dans Pandora FMS, pas dans Pandora ITSM : ce sont eux qui alimentent le serveur de supervision. ITSM ne consomme que le résultat à travers le nœud. Les informations matérielles, logicielles et étendues des objets Computer arrivent par cette voie et sont liées via id_pandora.

    Bonnes pratiques¶

    • Définissez peu de types d'objet et de champs, avec discernement ; chaque champ supplémentaire se paie à chaque enregistrement, filtre et import.
    • Utilisez les champs globaux pour ce que tous les types partagent et des champs propres pour le spécifique.
    • Modélisez la hiérarchie avant d'importer : changer les parents après coup coûte plus cher.
    • Vérifiez Min. stock et Max. relations avant que le stock ne commence à mentir.
    • Respectez l'ACL dès le départ : propriétaire, entreprises, utilisateurs et Public décident qui voit l'objet.
    • Ne transformez pas l'inventaire en découverte réseau : si la donnée n'est ni dans Pandora FMS ni dans le CSV, elle n'apparaît pas.

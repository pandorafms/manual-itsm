    Rapports et tableaux de bord¶

    Un rapport ne sert pas à remplir une réunion : il sert à répondre à une question. Pandora ITSM regroupe sous Reports les rapports sur les personnes, le support, les projets et les requêtes SQL, et ajoute des tableaux de bord pour voir l'essentiel sans ouvrir cinq écrans différents. Le problème n'est jamais le manque de données ; le problème est de confondre un joli graphique avec une décision bien informée.

    Ce chapitre explique comment construire les tableaux de bord, comment programmer les rapports et ce que mesure chaque rapport. Les rapports de projets restent ici, aux côtés des autres, parce qu'ils partagent le menu, les modèles et le planificateur.

    Où se trouvent les rapports¶

    Le menu Reports regroupe :

    • Dashboards → Manage Dashboard : tableaux visuels.
    • Report manager : modèles, programmation et bibliothèque de rapports.
    • People management : temps, congés, personnes et performance des équipes.
    • Support : support, tickets, résolutions, opérateurs et clients.
    • Project management : rapports de projets.
    • Custom SQL report : requêtes personnalisées.

    Les permissions reposent sur les bits Report Reader (RR) et Report Manager (RM) du profil, ainsi que sur la visibilité de groupe. Un utilisateur peut voir un rapport sans pouvoir le créer, ou créer une requête SQL sans pouvoir voir les données d'un autre groupe.

    Tableaux de bord¶

    Les tableaux de bord sont des postes de commande. Chaque utilisateur peut avoir les siens et choisir celui qui s'affiche à la connexion.

    Dans Reports → Dashboards → Manage Dashboard, on liste les tableaux, on les recherche par mot-clé et on les crée avec Create. Chacun dispose de Update pour changer son nom et son groupe, et de Delete pour le supprimer. Le Default dashboard contient tous les widgets disponibles et sert de démonstration.

    Créer et modifier¶

    Lors de la création, on indique un Name unique, sans espace au début ni à la fin, et un Group. Le nom peut être modifié ensuite avec Update.

    Pour modifier le contenu, on ouvre le tableau et on active le commutateur d'édition. Add cell ajoute une cellule et New widget permet de choisir le type de widget. Chaque widget se configure avec l'icône d'engrenage et se supprime avec la corbeille. On peut le faire glisser par son titre et le redimensionner depuis les bords.

    Widgets¶

    Customized links¶

    Ajoute un lien fonctionnel qui s'ouvre dans la même fenêtre ou dans un nouvel onglet. L'URL doit commencer par http:// ou https:// ; sinon, elle est traitée comme un lien interne. Une image est également obligatoire : les deux champs sont nécessaires.

    Exemple de lien interne vers la liste des changements :

    • URL : changes/operation/changes/changes_list
    • Open new tab : activé
    • Image : ticket.svg

    Les autres champs —texte, titre, police et couleurs— sont facultatifs.

    Message board¶

    Un éditeur de texte enrichi pour intégrer des tableaux, des liens, des images, des listes ou des documents complets. Il commence par un message de bienvenue qui disparaît lorsqu'on ajoute son propre contenu.

    Predefined links¶

    Ajoute des liens internes avec libellé et icône :

    • Knowledge base.
    • Downloads.
    • Create ticket.
    • Wiki.
    • Time tracker.
    • My tickets.

    Search box¶

    Ajoute une zone de recherche par mot-clé. Il faut sélectionner au moins une zone : base de connaissance, Wiki, tickets, projets, personnes, contacts, contrats, entreprises, factures ou leads.

    Support Activity Graph¶

    Affiche un graphique d'activité sur un ou plusieurs calendriers à partir d'un filtre de tickets enregistré. Chaque utilisateur ne peut choisir que ses propres filtres.

    Support Evolution Graph¶

    Affiche les tickets ouverts et fermés à partir d'un filtre enregistré, avec une fréquence de rafraîchissement configurable. Il n'utilise lui aussi que les filtres de l'utilisateur.

    Support SLA¶

    Avec un filtre enregistré, affiche un diagramme circulaire avec le pourcentage de SLA respecté et non respecté.

    Support statistics¶

    Regroupe les tickets d'un filtre enregistré par priorité, état, type ou statistiques générales. Il faut choisir une option dans Statistic.

    Ticket list¶

    Affiche une liste paginée de tickets —cinq par défaut— avec les champs et l'ordre choisis. Elle utilise un filtre enregistré et une période de rafraîchissement pour garder les informations à jour.

    Gestionnaire de rapports¶

    Dans Reports → Report manager, on crée des modèles et des programmations. Les rapports programmés sont stockés dans la bibliothèque et peuvent être envoyés par courriel. Le cron du système doit être actif ; sans cron, il n'y a pas de magie, seulement une file d'attente.

    Modèles de rapports¶

    Dans Reports → Report manager → Templates, on définit la couverture, l'en-tête et le pied de page des rapports PDF. La couverture accepte des images, des liens, du formatage et des marges. Les macros disponibles sont :

    • _fullname_ : utilisateur qui génère ou demande le rapport.
    • _date_ : date de génération.
    • _time_ : heure de génération.
    • _reportname_ : nom du rapport.

    Les macros fonctionnent aussi dans l'en-tête, où le logo peut être changé. Couverture, en-tête et pied de page peuvent être désactivés séparément.

    Planificateur de rapports¶

    Dans Reports → Report manager → Report schedule, on programme un rapport pour qu'il s'exécute une fois, chaque semaine ou chaque mois. On choisit un modèle, on l'enregistre dans la bibliothèque et on peut envoyer une notification ou le rapport lui-même par courriel.

    Attribuer une entreprise au rapport programmé permet aux utilisateurs de cette entreprise de le voir et de le modifier. Selon le type de rapport, ses filtres apparaissent ; Custom SQL n'affiche que les rapports SQL déjà créés. On peut créer autant de programmations que nécessaire.

    Bibliothèque de rapports¶

    Dans Reports → Report manager → Report library, on parcourt les rapports générés et on les recherche par type ou par nom.

    Rapports sur les personnes¶

    Pandora ITSM permet de suivre le temps de travail, les pauses, le travail à distance ou sur site et les congés. Les rapports de cette zone peuvent être programmés chaque semaine ou chaque mois.

    Suivi du temps¶

    Reports → People management → Time tracking affiche l'activité quotidienne, hebdomadaire ou mensuelle enregistrée par un utilisateur avec le Time tracker. Des périodes sont prédéfinies —cette semaine, ce mois, les trois derniers mois— et l'on peut en demander une personnalisée.

    Au moins un enregistrement quotidien doit exister pour que le rapport affiche des données ; les autres jours apparaissent vides. Exporte en CSV, plein écran et PDF.

    Les trois rapports de congés partagent le menu, mais pas les permissions : le rapport détaillé exige HR et, en pratique, UM pour y accéder depuis le menu ; le calendrier et l'exportation dépendent de l'accès à Reports.

    Rapport détaillé des congés¶

    Reports → People management → Detailed vacation report présente le rapport en deux modes : Show vacation report et le rapport des unités de travail. Les filtres sont l'utilisateur, le groupe et la date de création (Created from et Created to) ; ils s'appliquent lorsque vous cliquez sur Search.

    Le résultat affiche les utilisateurs, le total de jours de congés, les jours pris et les jours restants. Il peut être affiché en plein écran ou exporté en PDF. Si le rapport des unités de travail est sélectionné, il ajoute les jours non justifiés, les jours non travaillés justifiés pour maladie, les congés et les congés extra. Exporte en plein écran et PDF ; pas en CSV.

    Calendrier général des congés¶

    Reports → People management → General vacation calendar affiche les congés approuvés en vue mensuelle, hebdomadaire ou quotidienne. On peut avancer et reculer par mois et revenir à aujourd'hui avec Today. La recherche d'utilisateur limite le calendrier à une personne et les jours non ouvrés sont mis en évidence. Il est uniquement visible à l'écran.

    Rapport sur les personnes¶

    Reports → People management → People report sélectionne par défaut l'utilisateur actuel et les trois derniers mois de tous les projets, avec un résumé des tickets. Il affiche l'activité du projet et son pourcentage, des graphiques de tickets par groupe et par groupe créateur, un tableau de tickets —si Show only summary est désactivé— et un résumé des tickets et du temps travaillé.

    Exporte en CSV, plein écran et PDF.

    UT mensuelles¶

    Reports → People management → People monthly WU affiche tous les utilisateurs du mois en cours avec le total d'heures et la note moyenne. On peut changer de mois et filtrer par utilisateur.

    Le bouton de rapport de chaque utilisateur ouvre une boîte de dialogue pour modifier ses unités de travail, une par une ou en masse. Seules les unités de travail de tâches (Work Unit Tasks) acceptent la modification en masse. Selon les privilèges, chaque unité peut être modifiée, supprimée ou bloquée.

    Rapport utilisateur détaillé¶

    Reports → People management → Detailed user report exige des dates de début et de fin. Il propose trois options :

    • Project : regroupe par utilisateur et projet.
    • Role and task : regroupe par utilisateur et tâche.
    • Role and task (details) : ajoute des descriptions et des totaux de tickets, d'heures et de coûts.

    On sélectionne l'utilisateur, la période, les rôles, les tâches et les projets. Il n'exporte ni en CSV, ni en plein écran, ni en PDF.

    Rapport de congés¶

    Reports → People management → Vacation report sélectionne tous les utilisateurs actifs par défaut. Choisissez le groupe, les utilisateurs et les dates (Date from et Date to) ; les dates sont obligatoires. View affiche le tableau à l'écran et Export télécharge le résultat. Le filtrage par nom s'applique lorsque vous cliquez sur View, pas pendant la saisie. Exporte en CSV, mais pas en plein écran ni en PDF.

    Performance des équipes¶

    Reports → People management → Team performance affiche la performance hebdomadaire du personnel d'une entreprise. On filtre par groupe, date et zone de Pandora ITSM : projets, support, changements ou suivi du temps.

    Avec les valeurs par défaut, il ne renvoie aucune donnée, et c'est normal :

    • Le filtre principal est l'entreprise.
    • L'interface de filtres s'ouvre avec Ctrl + f.
    • Le jour de début de semaine vient de la configuration générale ; lundi par défaut.

    Exporte en plein écran, PDF et Microsoft Excel ; pas en CSV.

    Rapports de support¶

    Les rapports de support reposent sur le ticketing enregistré. Ils aident à évaluer les coûts, la qualité, les temps, l'effort, les profils du personnel et les profils des clients.

    Rapport de support¶

    Reports → Support → Support report génère un PDF avec des dizaines de graphiques, résumés, listes et paramètres. Pour choisir les filtres rapidement, il vaut mieux partir d'une recherche de tickets personnalisée et enregistrée.

    Le rapport comporte deux parties :

    • Show statistics : informations statistiques avec graphiques.
    • Show list : informations tabulaires des tickets.

    Il faut en sélectionner une ou les deux. Dans Issue fields, on choisit les champs du tableau sans affecter les graphiques. Il inclut huit graphiques circulaires généraux avec des regroupements Top-N —tickets les plus actifs, clients les plus actifs, opérateurs, ouverts, fermés— ainsi que des listes et graphiques de tendance.

    Exporte en plein écran et PDF ; pas en CSV.

    Rapport détaillé du ticket¶

    Reports → Support → Detailed ticket report affiche tous les détails d'un ticket : dates, participants, description, champs personnalisés, SLA et, en option, unités de travail, fichiers, suivi et statistiques.

    On saisit au moins deux lettres dans Select issues, on choisit le ticket et on clique sur Report. Les options supplémentaires sont :

    • Stats : statistiques générales, des unités de travail, activité par utilisateur et par état, groupe, propriétaire et entreprise.
    • Tracking : changements du ticket, filtrables par utilisateur.
    • Files : fichiers joints.
    • Work Units : unités de travail, avec option de modification du temps.

    Les privilèges de l'utilisateur limitent ce qui peut être vu et modifié. Exporte en plein écran et PDF ; pas en CSV.

    Rapport de résolution¶

    Reports → Support → Resolution report liste les tickets fermés et montre l'impact sur le temps, les pauses mortes, les personnes impliquées et la résolution, y compris le retour du client. On filtre par date de création et de clôture, créateur et entreprise. Exporte en plein écran et PDF.

    Rapport par type de ticket¶

    Reports → Support → Ticket type report regroupe les tickets par entreprise et par type sur un intervalle de temps. On filtre par créateur, entreprise et groupe. Exporte en CSV, plein écran et PDF.

    Rapport des opérateurs¶

    Reports → Support → Operator report mesure la qualité du support par opérateur : temps consacré, temps moyen de résolution, retour du client et tickets totaux. On filtre par entreprise, utilisateur, état et plage horaire.

    Exporte en CSV, plein écran et PDF.

    Rapports des incidents clients¶

    Reports → Support → Customer tickets affiche les incidents créés, résolus et en cours, regroupés par utilisateur, année et mois. Company est obligatoire ; Users permet de sélectionner un ou plusieurs utilisateurs de cette entreprise.

    Options :

    • Show section state : tableau des états par mois et par utilisateur.
    • Show section type tickets : tableau des types par mois et par utilisateur.
    • Show section total : total global.
    • Created from Pandora FMS : sépare les tickets créés depuis Pandora FMS et depuis Pandora ITSM.

    Exporte en plein écran et PDF ; pas en CSV.

    Rapports de projets¶

    Les rapports de projets se trouvent dans Reports → Project management. Ils aident à planifier les temps et les coûts et à voir l'évolution du projet grâce aux heures imputées par les personnes impliquées.

    General project report¶

    Reports → Project management → General project report → Select project affiche un projet sélectionné. Sans projet, un message d'erreur apparaît ; c'est normal et cela n'indique pas une panne.

    Options :

    • Show project : informations de base, personnes, résumé du travail et des coûts, répartition des tâches, charge de travail, activité et résumé des tâches.
    • Show task activity : pour les tâches sélectionnées, heures, coûts, estimations et graphiques de répartition et d'activité.
    • Show task work unit : date, durée, personnes et description de chaque unité de travail des tâches sélectionnées.
    • Show in table : toutes les tâches selon les filtres de date, jalon ou personnes.

    On peut filtrer par jalons, tâches, dates, personnes et entreprise liée. Exporte en CSV, plein écran et PDF.

    All projects report¶

    Reports → Project management → All projects report filtre par texte dans le nom ou la description, propriétaire, personnes impliquées, date, groupe, projets archivés et champs personnalisés du projet.

    La liste affiche l'identifiant, le groupe, le nom, le propriétaire, les personnes impliquées et la progression des tâches. Exporte en CSV, plein écran et PDF.

    Project expense report¶

    Reports → Project management → Project expense report affiche les projets du dernier mois. On filtre par date de début ou de fin et par pourcentage de réalisation. Show task breakdown détaille chaque tâche. En sélectionnant un projet, on peut filtrer par jalons. Exporte en CSV, plein écran et PDF.

    Project bundle of hours report¶

    Reports → Project management → Project bundle of hours report sélectionne un projet et un mois. Il affiche un résumé par tâche et par tickets, avec les heures consommées et restantes. On peut filtrer par entreprise et contrats liés. Exporte en plein écran et PDF ; pas en CSV.

    Rapport SQL personnalisé¶

    Reports → Custom SQL report permet de créer ses propres requêtes renvoyant un tableau exportable vers une feuille de calcul ou un PDF.

    Seul un superadministrateur ou un utilisateur disposant de la permission RM peut créer, modifier et supprimer des rapports SQL. Pour les consulter, il faut RR et appartenir au même groupe que le rapport.

    Une requête simple :

    SELECT id, name, country FROM tcompany ORDER BY country;

    Les champs peuvent être renommés avec des alias :

    SELECT
  id AS `Identification number`,
  name AS Name,
  country AS `Country origin`
FROM tcompany ORDER BY country;

    Pour des raisons de sécurité, DELETE, DROP, ALTER, TRUNCATE, CREATE, UPDATE, INSERT INTO, EXEC et MERGE sont interdits. Exporte en CSV, plein écran et PDF.

    Conseils pour les rapports SQL¶

    • Dans les modèles, _reportname_ peut être remplacé par le vrai nom du rapport SQL et des images personnalisées peuvent être insérées.
    • Les nouveaux rapports SQL sont affectés au groupe None ; attribuez-leur un groupe précis.
    • Pour connaître les tables et les champs, créez des rapports avec SHOW TABLES; et DESCRIBE <table_name>;. Cela évite de créer des utilisateurs de base de données : l'ACL est gérée dans Pandora ITSM.

    Bonnes pratiques¶

    • Définir la question avant de choisir le rapport.
    • Enregistrer des recherches de tickets réutilisables pour les tableaux de bord.
    • Vérifier les permissions RR/RM et la visibilité de groupe avant de publier.
    • Maintenir le cron actif si vous utilisez le planificateur.
    • Utiliser les modèles pour rendre les PDF lisibles, pas pour cacher des données.
    • Ne pas transformer un tableau de bord en album de graphiques sans responsable.
    • Documenter quel rapport répond à chaque question et qui le révise.

    Advanced configuration¶

    Advanced configuration is where Pandora ITSM stops being a freshly installed product and becomes the organisation's system. Here you decide language, URLs, email, authentication, menu visibility and the values that affect tickets, projects and CRM. Most settings have a sensible default; the trouble starts when someone changes one without knowing what depends on it.

    Where configuration lives¶

    Most of it lives in Setup → Setup. Each block has its own screen and tokens. After changing values, click Update to save them to the database. An unsaved change is a good intention.

    Many sections require super administrator or a specific profile bit. If a setting does not appear, it is not an interface bug: a permission is probably missing.

    General setup¶

    Setup → Setup → General setup holds the global parameters:

    Field What it controls
    Language Global language; the user's language takes precedence.
    Site name Name shown in titles and subjects.
    Enable error log Error log in pandora_itsm.log.
    Timezone for Pandora ITSM Time zone; Europe/Madrid by default.
    List of IP with access to API IPs allowed to use the API, comma-separated; * allows anyone.
    Default admin user Super administrator for periodic tasks.
    API password Password for API requests.
    First day of the week First day in calendars; Monday by default.
    Welcome view Welcome screen period; 21 days by default.
    Login hash password Key for a unique pre-authentication URL.
    Enable HTTPS access Forces HTTPS.
    Use SSL certificate and Path of SSL certificate Certificate and path; /etc/ssl/certs/pandoraitsm.pem by default.
    Access port Access port; 80 by default.
    Public access to server Public URL; must include the /pandoraitsm suffix.
    CSV encoding type and Separator data in CSV CSV encoding and separator.
    Chromium path Browser path for report generation.
    Maximum direct download size (MB) Maximum download size.
    Max. upload file size (MB) Maximum upload size; PHP also applies.
    Max. Upload file size in CRM / incidents CRM and ticket-specific limits.
    Temporary directory for PDF files Temporary PDF directory; /tmp/ by default.
    Hide version Hides the version in footer and login.
    Show modal last time logged Shows the user's last login.
    Active automatic time tracking stop Stops time tracking at Stop time tracking after (8.5 hours by default).

    If you enable HTTPS, check the certificate and trust chain. PHP may need openssl.cafile in php.ini.

    Public access to server is dangerous if misconfigured: the console can become unreachable. The emergency exit is to fix the token in the database:

    UPDATE tconfig SET value='http://URL/pandoraitsm' WHERE token='access_public';

    Visual setup¶

    Setup → Setup → Visual setup controls appearance:

    • Theme: global and per-user theme; Default (Light) by default.
    • Favicon: tab icon.
    • Block size for pagination: items per page; low values avoid performance issues.
    • Global dashboard (welcome message): welcome dashboard.
    • Font for ITSM: interface and PDF font.
    • Tabs menu: tabs, drop-down menu or both.
    • Global search limit: results per area.

    Global search covers open tickets, projects, people, contacts, contracts, companies, invoices, leads and Wiki. Each user sees only what their ACL allows. Custom logos and favicons live in images/custom_logos and images/favicon.

    Password policy¶

    Setup → Setup → Password policy setup. The policy does not apply to super administrators. Enable password policy is the master switch: if it is off, the other options do nothing.

    Main fields: minimum length (5 by default), numbers, symbols, expiry in days (0 = never), forced change on first login, lock minutes (5 by default) and failed attempts. Automatic password generation also follows the policy when enabled. Authentication details are in 2.2 Authentication and security.

    Issue setup¶

    Setup → Setup → Issue setup groups ticket settings:

    • Ticket submission settings: Manual, Simplified or Smart.
    • Visual options: show creator/owner, ticket search limit (300 by default), quick edit, date format, work unit completion date and comment order.
    • Ticket behaviour: rating, creator/owner changes, automatic work unit on creation, type changes, mandatory type, external users, auto-assignment and customer validation before closing.
    • Work unit options (WU): automatic close (45 days by default), default time (0.25 h), email on work unit management, internal units by default and public comments.
    • Workflows: check closed tickets and days to check (15 by default).
    • Email sending options: which changes send email, notification grouping, attachments, internal units and work unit creator notices.
    • Customization: statuses, resolutions, priorities and special days.
    • Default custom columns: ticket list columns.
    • Survey Questions: survey when the rating is negative.

    Functional details are in 3.1 Tickets and incidents, 3.2 Workflow and statuses and 3.3 SLA, escalation and quality.

    Changes setup¶

    Setup → Setup → Changes setup adjusts change notifications and behaviour. The module logic is in 5.1 Change management.

    Email and templates¶

    Setup → Setup → Email setup configures sending (SMTP) and receiving (POP/IMAP):

    • Notification period: minimum between SLA notices (24 hours by default).
    • System email from address: system sender.
    • SMTP Host, Port, User, Password and encryption.
    • OAuth 2.0 for Microsoft 365, with Client ID, Tenant ID and Secret.
    • SMTP queue retries, Max. pending emails and Max. emails sent per execution.
    • POP/IMAP Host, Port, User, Password, protocol and Message delimiter.
    • Accept any certificate off by default; do not enable it except in extreme cases.

    Receiving is only needed if tickets are created or updated by email. Details, providers and OAuth are in 3.4 Email and support.

    Email templates setup edits .tpl files and subjects. Default templates can be duplicated and made default. Macros cover tickets, changes, change tasks and work units; the full list is in the template setup and in 3.4.

    Email queue control shows pending emails, attempts and status. They can be reactivated or bulk-deleted.

    Menu visibility¶

    Setup → Setup → Visibility management hides sections per group:

    • Hidden: not shown, even by direct URL.
    • Full: full access.

    Without configuration, access is full. Each section is checked against a profile bit: projects PR, tickets IR, inventory VR, knowledge base KR, file releases KR, calendar AR, work orders WOR, people and setup any profile. Super administrators always see everything. If a user has several groups, the least restrictive visibility applies. A rule for All replaces previous ones for that section.

    Pandora FMS inventory¶

    Setup → Setup → Pandora FMS inventory controls inventory and remote reception:

    • Duplicate inventory name: allows repeated names.
    • CSV compatibility import: import/export format.
    • Default owner, Associated company and Associated user for remote inventory.

    Inventory is documented in 4.1 Inventory.

    Authentication¶

    Setup → Setup → Authentication configuration chooses local, Active Directory, LDAP or Pandora FMS. Super administrators always authenticate locally. Session timeout (secs) sets session length (9000 seconds by default). Two-factor authentication and the rest of the details are in 2.2 Authentication and security.

    CRM setup¶

    Setup → Setup → CRM setup has four blocks:

    Invoices¶

    • Enable auto ID and Invoice ID pattern: default 21/[1000]; the variable part is in brackets and only applies to Submitted invoices.
    • Invoice header logo: logo in images/custom_logo.
    • Header, taxes, payment methods and footer.

    Contracts¶

    Contract Statuses lets you edit, delete and add contract statuses.

    Campaigns¶

    • Email batch campaigns: emails per block (500 by default).
    • Web tracking JavaScript: tracking code.
    • Captcha: Cloudflare, with site key.

    Deals¶

    • Default pipeline deal.
    • Time since last update (days): stale opportunities.
    • Schedule reminder repeat hours: 24 by default.
    • Days to expire schedule: 7 by default.
    • Notification email (Deal Registrations).

    CRM details are in 8.1–8.7.

    Old data maintenance¶

    Setup → Setup → Old data maintenance decides how long data is kept. 0 means keep forever. Defaults:

    Data Days
    Events 30
    Closed tickets 0
    Work units 0
    Work orders 0
    Audit 15
    Sessions 7
    Workflow events 900
    Ticket attachments 0
    File tracking 30
    Backups 30
    Invalid emails 30
    Reports 365
    Archived chatbot rooms 365

    Reset all data deletes all data and attachments. It is not cleaning: it is starting from scratch.

    Project management¶

    Setup → Setup → Project management sets defaults:

    • Users without work unit autocomplete.
    • Working hours per day (8).
    • Work unit autocomplete in days (0).
    • Default time for simple (4 h) and multiple (4 h) work units.
    • Currency (€).
    • Vacation days (22).
    • Disable adding tickets and work units to pending or verified tasks.
    • User who receives vacation request notifications.
    • Weekly work unit notice (40 h).

    Details are in 6.1 Projects and tasks and 7.1 Time management.

    Integrations¶

    • Pandora RC: enables remote management.
    • ChatBot: server and channels.
    • GitLab: access token to read project tickets.

    Integration chapters are in Part 11.

    Administration tools¶

    • File manager: upload and organise files in attachment, attachment/downloads, images and images/custom_logos.
    • Diagnostic info: version, PHP, database, system, performance, logs, attachments and server date.
    • News board: global news by group and with expiry; supports _lastlogin_.
    • DB Manager: SQL console for super administrators or DM profile; misuse is irreversible.
    • Links: external or internal menu links; internal ones use paths such as wiki/operation/wiki/wiki.
    • System events: cron, scheduled reports and failures.
    • Audit log: user actions, text and date search, CSV export.
    • Error log: pandora_itsm.log, with a clear option.
    • Translate strings: custom translations over the original English.

    Best practices¶

    • Change one block at a time and click Update.
    • Test changes in a staging environment before production.
    • Document who changed each option and why.
    • Review HTTPS, email and authentication after any infrastructure change.
    • Back up before touching old data or the database manager.
    • Do not use Reset all data as a cleaning tool.

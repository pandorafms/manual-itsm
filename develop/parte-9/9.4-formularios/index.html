    Formularios¶

    Un formulario es la puerta de entrada de contactos desde una web. No es una campaña ni una lista: es el mecanismo que convierte una visita anónima en un contacto con nombre, correo y empresa. En Pandora ITSM se gestiona desde el CRM, pero su uso es claramente de marketing.

    Dónde están¶

    Los formularios se gestionan en CRM → Forms. La lista permite crear, duplicar, borrar y generar el código de inserción de cada formulario.

    Cada formulario tiene:

    Campo Qué indica
    Name Nombre del formulario.
    Language Idioma; Any o uno concreto.
    Description Para qué sirve.
    Email Correos que reciben aviso, separados por comas.
    Assigned to Assigned user o Form team.
    Assigned user / Form team Destinatario interno del formulario.
    Submission type Default, Submission message o Redirect to URL.
    Form submission message Mensaje tras enviar.
    Redirect to URL URL de destino tras enviar.
    Button label Texto del botón.
    Warn on companies already registered Avisa si la empresa ya existe.

    Constructor de formularios¶

    El editor tiene dos zonas: Available Fields y Form Builder. Los campos disponibles son:

    • Text Input, Textarea, Label/Text.
    • Email, Phone, URL, Number, Date.
    • Select, Checkbox, Radio Button.
    • Hidden Field.
    • Custom Styles.
    • Captcha.
    • Policy Acceptance.

    Cada campo se arrastra al formulario y se configura. Se puede mapear con un campo estándar del contacto o con un campo personalizado, y marcar si es obligatorio.

    Campos clave¶

    El campo marcado como key field identifica contactos existentes. Normalmente es el correo o el teléfono. Si el valor coincide con un contacto ya registrado, el formulario actualiza el contacto; no crea un duplicado. Si no coincide, crea uno nuevo.

    Ese comportamiento es la diferencia entre un formulario útil y una fábrica de duplicados.

    Publicación¶

    Cuando el formulario está listo, la acción Generate bundle genera el código JavaScript que se incrusta en la web. El formulario se muestra en la página y envía los datos a Pandora ITSM.

    El resultado puede ser:

    • Un mensaje de confirmación en la propia página.
    • Una redirección a una URL concreta.

    Ambas opciones se configuran en Submission type.

    Avisos y asignación¶

    Los correos de Email reciben un aviso con cada envío. El formulario puede asignarse a un usuario o a un equipo, para que el contacto caiga en la bandeja correcta.

    La opción Warn on companies already registered ayuda a detectar empresas duplicadas antes de crear otra ficha. No las fusiona automáticamente: avisa.

    Idiomas y traducciones¶

    El campo Language permite limitar el formulario a un idioma. El editor de traducciones permite adaptar las etiquetas y los mensajes a cada idioma. Si la web es multilingüe, el formulario también debe serlo.

    Uso en marketing¶

    Los contactos captados por un formulario entran en el CRM y pueden formar parte de listas dinámicas por etiquetas, campos o empresa. Una campaña puede segmentar después por esos criterios, sin exportar ni duplicar contactos.

    El formulario capta; la lista organiza; la campaña envía. Mezclar las tres cosas suele acabar en un CSV imposible de mantener.

    Privacidad y seguridad¶

    • Usa Captcha para frenar bots.
    • Añade Policy Acceptance si necesitas consentimiento explícito.
    • Publica siempre el formulario por HTTPS.
    • No incluyas datos sensibles que no necesites.
    • Revisa la política de privacidad y el tratamiento de datos.
    • No pongas credenciales ni tokens en campos ocultos.

    Buenas prácticas¶

    • Pide solo los datos que vas a usar.
    • Usa el correo como campo clave para evitar duplicados.
    • Prueba el formulario en la web real, no solo en el editor.
    • Define un mensaje de confirmación claro.
    • Asigna cada formulario a un usuario o equipo responsable.
    • Revisa periódicamente los contactos creados y las empresas duplicadas.

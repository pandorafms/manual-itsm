    Inventario¶

    El inventario de Pandora ITSM no falla por la consola: falla por el modelo de datos. Una lista de equipos se puede montar en diez minutos; un inventario útil exige decidir antes qué tipos de objeto existen, qué campos se comparten, quién puede ver cada cosa y cómo se relacionan los objetos entre sí. Lo demás —vistas, filtros y widgets— viene casi solo.

    Este capítulo cubre el inventario completo: tipos de objeto, campos personalizados y externos, objetos, jerarquía, stock, estados, etiquetas, ACL, importación CSV e inventario remoto desde Pandora FMS. La integración con Pandora FMS se detalla en el capítulo 11.4; aquí se explica lo que el inventario hace con ella.

    El inventario sirve para saber qué objetos tiene la organización, dónde están, quién los usa y con qué contratos, tickets y cambios se relacionan. No descubre la red por su cuenta. Los objetos entran a mano, por CSV o desde la sincronización con Pandora FMS.

    Tipos de objeto¶

    Un tipo de objeto define la plantilla de datos de un conjunto de objetos. Un Computer no tiene los mismos campos que una licencia o un contrato. El menú es Inventory → Object Types.

    Para crear un tipo, pulsa Create, rellena sus características y vuelve a pulsar Create. Para editarlo, haz clic en su nombre. La lista permite duplicar un tipo con todos sus campos personalizados mediante Duplicate.

    Los parámetros del tipo son:

    Parámetro Para qué sirve
    Name Nombre del tipo de objeto.
    Icon Icono asociado; las imágenes se suben a images/objects/.
    Show in tree view Si se activa, el tipo aparece como raíz en la vista de árbol.
    Min. stock Stock mínimo del tipo.
    Max. stock Stock máximo del tipo.
    Catalogs to show in overview Catálogos que se muestran como secciones en el resumen del objeto.
    Description Descripción del tipo.
    Sync interval Cada cuánto se sincroniza con Pandora FMS: Never, Weekly, Every 15 days, Monthly o First time only.

    Sync interval solo aparece cuando hay nodos de Pandora FMS configurados y el tipo está asociado a un esquema de Pandora FMS. Sin integración, no hay nada que sincronizar.

    Campos personalizados y globales¶

    Cada tipo tiene sus campos. Se gestionan desde Actions → Fields en la lista de tipos: se crean con Create, se editan haciendo clic en su nombre y se ordenan con las flechas de la columna de acciones. El borrado también vive ahí.

    Los campos globales son la excepción útil: se definen una vez en Inventory → Object types → Global Fields y se añaden a todos los tipos. Cada tipo puede ocultarlos o cambiar su orden, pero el campo es el mismo. Sirven para lo que siempre está: número de serie, ubicación, fecha de compra.

    Las propiedades comunes a todos los campos son:

    Propiedad Efecto
    Unique Solo puede existir un objeto con ese valor; funciona como identificador.
    Inherit El objeto hereda propietario, usuarios y empresas del objeto padre.
    Show in list El campo aparece por defecto en el listado general y puede usarse como columna.
    Prevent updates El campo no se actualiza al recibir datos de inventario remoto.

    Los tipos de dato disponibles son: numérico, casilla de verificación, texto, lista de opciones, campo externo, fecha, enlace web, contraseña y valor con unidad. En la lista de opciones, los valores se separan por comas en Combo values.

    Campos externos¶

    Un campo externo lee información de una tabla adicional de la base de datos, creada a mano con el DB Manager. Es la vía para enlazar el inventario con catálogos propios sin convertir cada valor en una lista estática.

    En un campo simple se indican dos cosas obligatorias: External table name, el nombre exacto de la tabla, y Field to be displayed, la columna que se muestra. Los objetos se actualizan solos cuando cambia la tabla. Primary key, Foreign key y Parent table name se dejan vacíos: son para los campos compuestos.

    Un campo compuesto encadena dos tablas. La tabla padre tiene una clave primaria; la tabla hija tiene una clave foránea que apunta a ella. Al crear el campo padre se indica la Primary key; al crear el hijo, la Foreign key y el Parent table name. El resultado es un desplegable que depende del valor anterior: si se borra el padre, el hijo se puede volver a elegir.

    El caso clásico es país y ciudad. Con el DB Manager se crean las tablas:

    CREATE TABLE t_country (
    id_country INT PRIMARY KEY,
    name TEXT
);

CREATE TABLE t_city (
    id_city INT,
    name TEXT,
    id_country INT,
    FOREIGN KEY (id_country) REFERENCES t_country(id_country)
);

    Se añaden los valores con INSERT, se crea el campo Country sobre t_country y el campo City sobre t_city con id_city como clave primaria, id_country como clave foránea y t_country como tabla padre. A partir de ahí, cualquier objeto del tipo elegido puede seleccionar país y ciudad. Si el campo lleva Show in list, también aparece como columna y como filtro.

    Objetos de inventario¶

    Los objetos se crean en Inventory → Lists con Create. Antes de rellenar campos, hay que decidir quién los ve:

    • Owner: propietario del objeto.
    • Associated companies: empresas asociadas.
    • Associated users: usuarios asociados.
    • Public: si se activa, lo ve todo el mundo.

    Esos cuatro campos son el ACL del objeto. Un objeto es visible para su propietario, para los usuarios asociados, para los usuarios de las empresas asociadas y para todos si es público. El resto no lo ve.

    Un objeto puede tener un Parent, lo que crea una jerarquía, y relaciones con otros objetos. También guarda el tipo, el estado, el contrato, la fecha de recepción, la fecha de baja, la fecha EOL, una imagen y un código QR.

    La vista del objeto tiene dos columnas. A la derecha están los datos principales y las acciones; a la izquierda, las pestañas:

    • Campos personalizados.
    • Tickets: histórico de tickets asociados.
    • Changes: cambios asociados.
    • Relaciones.
    • Tracker: histórico de cambios del objeto y de sus hijos.
    • Usuarios asociados.

    Los objetos de tipo Computer añaden Hardware, Software y Extended Info con la información recogida de Pandora FMS.

    Los objetos se pueden duplicar desde el listado con Duplicate; es la forma rápida de dar de alta diez equipos que solo cambian en el número de serie. También se pueden reclasificar a otro tipo: el sistema pide cómo se corresponde cada campo del origen con el destino, convierte los identificadores internos y deja que los campos nuevos se rellenen a mano. Algunos campos se descartan; conviene revisar el resultado.

    Vistas, búsquedas y operaciones masivas¶

    Inventory → Lists ofrece cuatro formas de mirar lo mismo:

    • Resumen: portada con el estado del inventario y los tipos principales.
    • Listado: tabla de datos con filtros, columnas configurables y exportación.
    • Árbol: jerarquía padre-hijo, agrupada por tipo.
    • Stock: control de existencias, que se explica más abajo.

    La búsqueda permite filtrar por texto libre —descripción, identificador y campos personalizados—, por estado, por tipo de objeto y por tamaño de página. El resultado se puede exportar a CSV.

    En el modo listado se pueden seleccionar varios objetos y hacer operaciones masivas: borrar, cambiar el tipo de objeto, el padre, la empresa, el contrato, el propietario o el estado. El borrado es irreversible; el resto se puede deshacer objeto a objeto.

    Control de stock¶

    El stock no se lleva con un número suelto: se calcula con dos piezas. Cada tipo tiene min_stock y max_stock; cada objeto tiene un límite de relaciones (relation_limit, que la interfaz llama Max relations).

    • Con 0 o vacío, el objeto cuenta como una unidad y admite relaciones sin límite.
    • Con 1 o más, el objeto admite como máximo ese número de relaciones y aparece en el segundo nivel del control de stock.

    La vista de stock tiene dos niveles. El primero muestra cada tipo con su stock mínimo, máximo y usado, una barra de porcentaje y acciones para ver objetos, crear un ticket, crear un change o programar una tarea. El segundo muestra los objetos con límite de relaciones y su porcentaje de uso. Si el total baja del mínimo, el aviso se pone en rojo.

    Estados y etiquetas¶

    Inventory → Status gestiona los estados del objeto. Pandora ITSM trae cinco estados internos: New, In use, Unused, Issued y Missing. Se pueden editar y añadir estados propios. Si se borra un estado que estaba asignado, los objetos afectados vuelven a New.

    Las etiquetas (Inventory → Tags) funcionan como en el resto de la consola: nombre, color y relación con objetos. No se muestran por defecto en el listado; hay que añadirlas como columna o filtrar por ellas.

    ACL de inventario¶

    El inventario tiene su propio juego de permisos:

    Bit Qué permite
    VR Ver los objetos a los que se tiene acceso.
    VW Crear, editar y borrar objetos; incluye la lectura.
    VM Gestionar todo el inventario: objetos, tipos, estados, etiquetas y catálogos.

    La lectura no es global: se aplica la visibilidad del objeto (público, propietario, usuario asociado o empresa asociada). La escritura exige VW o VM, y la gestión de tipos, estados y etiquetas exige VM. El superadministrador se salta el ACL. El papel de la empresa en el resto de secciones se explica en el capítulo 2.3.

    Cuadros de mando y widgets¶

    El inventario aporta sus propios widgets al cuadro de mando:

    • Inventory by status: porcentaje por estado, filtrable por tipo.
    • Inventory by object type: porcentaje por tipo, con multiselección.
    • Top N stock inventory: los tipos con mayor porcentaje de uso.
    • Stock relations: stock global y por objeto con límite de relaciones.
    • Inventory counter: recuento de objetos.
    • Inventory type boxes: accesos directos por tipo de objeto.

    Importación desde CSV¶

    La importación masiva vive en Inventory → Import CSV. Se elige el tipo de objeto, se revisa el separador —por defecto |— y se descarga la plantilla con Download sample CSV. La plantilla cambia según el tipo porque incluye sus campos personalizados.

    El fichero debe llevar cabecera en la primera fila y, al menos, nueve columnas en este orden:

    Posición Columna Contenido
    1 Name Nombre del objeto. Obligatorio.
    2 Owner Usuario propietario. Obligatorio y debe existir.
    3 Status Estado por etiqueta o identificador. Obligatorio.
    4 Receipt date Fecha de recepción.
    5 Removal date Fecha de baja.
    6 Description Descripción.
    7 Companies Identificadores de empresa separados por comas.
    8 Associated user Identificadores de usuario separados por comas.
    9 Parent Identificador del objeto padre, si lo hay.
    10+ Campos personalizados En el orden de la plantilla del tipo.

    Empresas y usuarios admiten corchetes y espacios, pero lo seguro es una lista separada por comas. Los campos personalizados se validan según su tipo: números, listas cerradas, fechas, campos externos y unicidad. Si una fila falla, la importación informa de la línea y del motivo.

    Este formato no es el que describían versiones anteriores de la documentación: allí aparecían columnas de fabricante, contrato, tipo de objeto o public. En la versión actual el tipo se elige en el formulario y el resto se deduce de la plantilla. Manda el código.

    Inventario remoto desde Pandora FMS¶

    El inventario remoto no recibe XMLs de EndPoints directamente: se sincroniza desde Pandora FMS. El servidor de Pandora FMS recoge la información con sus EndPoints y Pandora ITSM la lee a través del nodo configurado, creando o actualizando los objetos. El envío directo de inventario desde un EndPoint a Pandora ITSM ya no existe.

    La configuración de destino está en Setup → Pandora FMS Inventory, sección Remote Inventory:

    • Default owner: dueño de los objetos nuevos. Es obligatorio.
    • Associated companies: empresas por defecto.
    • Associated users: usuarios por defecto.

    Esos valores rellenan los objetos que crea la sincronización y, por tanto, deciden su visibilidad. El nodo de Pandora FMS, sus credenciales y su alcance se configuran en la integración; el capítulo 11.4 cubre el procedimiento completo.

    La sincronización no es inmediata: cada tipo de objeto decide su ritmo con Sync interval (Never, Weekly, Every 15 days, Monthly o First time only). El tipo debe estar asociado al esquema de Pandora FMS para que la opción aparezca.

    El cron de inventario es la pieza que hace que esto funcione. Se ejecuta con include/inventory_cron.php y debe estar en el crontab, normalmente cada cinco minutos:

    php /var/www/html/pandoraitsm/include/inventory_cron.php

    En cada pasada registra la marca inventory_crontask, sincroniza el inventario de los nodos de Pandora FMS respetando el intervalo de cada tipo, caduca las programaciones vencidas y elimina los objetos Missing que ya no tienen padre.

    Los EndPoints se instalan y se configuran en Pandora FMS, no en Pandora ITSM: son los que alimentan al servidor de monitorización. ITSM solo consume el resultado a través del nodo. La información de hardware, software y datos extendidos de los objetos Computer llega por esa vía y se enlaza mediante id_pandora.

    Buenas prácticas¶

    • Define pocos tipos de objeto y campos con criterio; cada campo de más se paga en cada alta, filtro e importación.
    • Usa campos globales para lo que comparten todos los tipos y campos propios para lo específico.
    • Modela la jerarquía antes de importar: cambiar padres después es más caro.
    • Revisa Min. stock y Max. relations antes de que el stock empiece a mentir.
    • Respeta el ACL desde el principio: propietario, empresas, usuarios y Public deciden quién ve el objeto.
    • No conviertas el inventario en un descubrimiento de red: si el dato no está en Pandora FMS ni en el CSV, no aparece.

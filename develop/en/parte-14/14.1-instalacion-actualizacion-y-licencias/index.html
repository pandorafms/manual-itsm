    Installation, updates and licences¶

    Short answers to the problems that come up most often before Pandora ITSM is up and running. Each answer links to the chapter with the full procedure.

    What does the server need to install Pandora ITSM?¶

    Two things that are easily forgotten: 2 GB of RAM and 10 GB of free disk. The installer supports EL9, EL10, Ubuntu 22.04 and Ubuntu 24.04, with PHP 8.2 or 8.4 and MySQL 8.0 or 8.4. If the server falls short, the script stops; it does not negotiate. Details are in 1.1 Installation.

    The installer stops before it starts. What should I check?¶

    In order: that the distribution is one of the supported ones, that there is enough memory and disk, that the server can reach the official Pandora FMS repository and that no previous installation exists —packages, directory or database with the same name—. The symptom table in 1.1 Installation maps each failure to its check.

    The console does not respond after the script. Is it broken?¶

    Almost never. Check Apache, PHP-FPM and SELinux, and read the logs before reinstalling. If the console opens but data does not load, the problem is usually the database or config.inc.php. A "it does not work" without a log is a conversation that starts badly; attach the log to the incident.

    No update is available¶

    Check three things: that the pandora_uid registration is correct, that the server has Internet access and that Limit to LTS updates is not enabled if you expect an FR release. The procedure and the error table are in 1.2 Updating.

    Memory error while applying an update¶

    Raise memory_limit to 800M or more and run the process again. If the failure happens with a patch, restore the backup before insisting. PHP limits are explained in 1.2 Updating.

    The .itsm file for the offline update will not upload¶

    Check that the extension is .itsm, that the size does not exceed post_max_size or upload_max_filesize, and that the form can write to the temporary directory. The recommended values are in 1.2 Updating.

    How do I know the update was actually applied?¶

    Look at About ITSM, the Warp update journal and the MR status. If the version does not change, it may be an unapplied update or a cache; sign in again before calling it done. The post-update check is in 1.2 Updating.

    How many administrators can I create?¶

    As many as Manager Count in the licence allows. Before creating a new one, check the counter; disabling the account of someone who leaves frees a slot. Do not make an administrator out of someone who only needs to read. Limits and licence blocking are in 1.4 Licensing.

    What happens if the licence expires?¶

    The console enters limited mode. Renew before the Expires date, especially if you have a bulk user creation planned. The licence is not pasted into tickets or shared by email; keep it somewhere safe. Details in 1.4 Licensing.

    Can I use the admin account for everything?¶

    No. admin is a rescue account, not a working user. Sharing it removes traceability and turns any incident into an argument about who did what. Create named users with the minimum profile and reserve admin for what really needs it.

    Intégration avec Pandora FMS¶

    Pandora FMS supervise ; Pandora ITSM traite. L'intégration existe pour que l'alerte et le ticket ne vivent pas dans deux mondes séparés : une alerte de supervision peut ouvrir un ticket, et le technicien qui le résout voit l'actif qui l'a déclenchée.

    L'intégration fonctionne dans les deux sens. Depuis Pandora FMS, les tickets de Pandora ITSM sont créés, clôturés, consultés et modifiés, à la main ou automatiquement via des alertes et des réponses d'événements. Dans l'autre sens, Pandora ITSM reçoit l'inventaire des agents Pandora FMS et le transforme en objets Computer avec leurs informations matérielles, logicielles et étendues.

    Tout repose sur l'API v2 de Pandora ITSM. Il n'y a ni base de données partagée ni agent spécial : FMS appelle l'API avec un token, et l'API fait le reste.

    Prérequis et permissions¶

    Avant de configurer quoi que ce soit, vérifiez ces points :

    • Pandora FMS et Pandora ITSM se joignent par le réseau, de préférence en HTTPS.
    • La version de Pandora FMS est 783 ou supérieure si vous utilisez l'installation conjointe depuis sa console.
    • L'IP de Pandora FMS est autorisée dans Setup → Setup → General setup → List of IP with access to API de Pandora ITSM. Par défaut, seul localhost est permis.
    • Vous disposez d'un token API v2 généré dans Pandora ITSM. Le chapitre 11.1 explique comment le créer.
    • L'utilisateur du token possède les permissions IM (gestion des tickets) et VW (écriture de l'inventaire). Sans elles, l'API rejette les appels de FMS.

    Le token est l'identifiant de l'intégration. Ne le partagez pas avec d'autres utilisateurs et ne le réutilisez pas pour un second outil ; s'il fuit, supprimez-le et créez-en un autre.

    Configurer la communication¶

    Deux étapes dans Pandora ITSM : autoriser l'IP et créer le token.

    1. Ajoutez l'IP ou la plage de Pandora FMS dans Setup → Setup → General setup → List of IP with access to API.
    2. Générez un token dans People → Edit my user → Create Token API v2, avec un libellé comme Pandora FMS et une date d'expiration.
    3. Vérifiez que l'utilisateur du token peut gérer les tickets (IM) et écrire dans l'inventaire (VW).

    Dans Pandora FMS, l'intégration se configure dans sa section de gestion des incidents, en indiquant l'URL de Pandora ITSM et le token. La procédure détaillée se trouve dans le manuel de Pandora FMS ; elle n'est pas répétée ici car elle change avec la console de supervision et ne relève pas de la documentation de Pandora ITSM.

    Lorsque la communication fonctionne, FMS peut créer et clôturer des tickets dans ITSM et afficher les tickets existants. Le test le plus rapide consiste à ouvrir un ticket depuis FMS et à vérifier qu'il apparaît dans Support → Tickets de Pandora ITSM.

    Synchronisation de l'inventaire¶

    La synchronisation transforme les agents de Pandora FMS en objets d'inventaire de Pandora ITSM. Elle se configure dans Setup → Setup, onglet Pandora FMS Inventory.

    L'écran comporte trois blocs :

    • Clean objects : nombre de jours après lesquels les objets marqués Missing et sans parent sont supprimés. 0 désactive le nettoyage.
    • Remote inventory : valeurs par défaut des objets créés par la synchronisation. Default owner est obligatoire ; les entreprises et utilisateurs associés décident de leur visibilité.
    • Nodes connected : les serveurs Pandora FMS qui se sont connectés correctement à Pandora ITSM.

    Le tableau des nœuds affiche le nom du nœud, le chemin de connexion —par exemple http://172.16.0.1:90/pandora_console/api/v2—, la progression des agents synchronisés, l'état de la connexion et l'opération de suppression. Un point vert indique que le nœud répond.

    Le nœud ne s'ajoute pas à la main dans Pandora ITSM : Pandora FMS l'enregistre lorsque la communication fonctionne. S'il n'apparaît pas, le problème vient de la configuration de FMS, de l'URL ou du token, pas de cet écran. Pour redémarrer une connexion, supprimez le nœud et reconfigurez-la depuis Pandora FMS.

    Chaque type d'objet synchronisé fixe son rythme avec Sync interval : Never, Weekly, Every 15 days, Monthly ou First time only. L'option n'apparaît que lorsque des nœuds sont configurés et que le type est associé à un schéma Pandora FMS. Les détails des types, champs et stocks se trouvent au chapitre 4.1.

    Les objets synchronisés sont de type Computer et sont liés à l'agent via id_pandora. Leur fiche affiche les onglets Hardware, Software et Extended Info avec les informations collectées par Pandora FMS.

    La synchronisation n'est pas immédiate : c'est le cron d'inventaire, include/inventory_cron.php, qui l'exécute, généralement toutes les cinq minutes. À chaque passage, il enregistre la marque inventory_crontask, synchronise les nœuds, expire les programmations échues et supprime les objets Missing qui n'ont plus de parent.

    Installation conjointe depuis la console Pandora FMS¶

    Pandora FMS peut installer une instance de Pandora ITSM depuis sa propre console. C'est un moyen rapide de tester l'intégration, pas la voie recommandée pour la production.

    Dans Pandora FMS, allez dans Management → Settings → System Settings → ITSM et cliquez sur Install ITSM.

    Avant d'installer, Pandora FMS vérifie trois choses :

    • Que la base de données itsm n'existe pas ; si elle n'existe pas, elle est créée.
    • Que l'utilisateur de Pandora FMS —généralement pandora— a les permissions nécessaires pour la créer.
    • Que le répertoire /var/www/html/pandora_console/itsm n'existe pas ; il sera créé pendant l'installation.

    Si l'utilisateur de la base de données n'a pas les permissions, l'administrateur MySQL doit les accorder avant de continuer :

    GRANT ALL PRIVILEGES ON `itsm`.* TO `pandora`;

    L'installation télécharge les paquets nécessaires depuis le dépôt officiel de Pandora FMS et crée le répertoire ITSM dans la console Pandora FMS. La progression montre les étapes et, à la fin, un lien pour accéder pour la première fois à la console Pandora ITSM.

    Une fois terminée, vérifiez que vous pouvez accéder à Pandora ITSM et que Pandora FMS voit les tickets. Si l'installation conjointe échoue, vérifiez les permissions MySQL et l'espace disque avant de la relancer.

    Bonnes pratiques et problèmes fréquents¶

    • Utilisez un token dédié à l'intégration, avec libellé et date d'expiration. Si quelque chose fuit, vous savez quoi supprimer.
    • Autorisez uniquement l'IP de Pandora FMS, pas une plage ouverte.
    • Vérifiez que l'utilisateur du token conserve IM et VW ; un changement de profil casse l'intégration sans prévenir.
    • Si le nœud n'apparaît pas, vérifiez l'URL et le token dans Pandora FMS. S'il apparaît mais ne progresse pas, regardez le cron et l'état de la connexion.
    • Ne supprimez pas un nœud pendant qu'il synchronise. Attendez qu'il termine ou que la progression s'arrête.
    • L'installation conjointe est destinée aux tests. Pour la production, installez Pandora ITSM séparément et configurez l'intégration via l'API.

    Pour le détail de l'API et des tokens, revenez au chapitre 11.1. Pour les types d'objet, les champs et le contrôle du stock, au chapitre 4.1. Pour les tickets venant de FMS, au chapitre 3.1.

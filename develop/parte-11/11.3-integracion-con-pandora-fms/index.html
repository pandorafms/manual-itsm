    Integración con Pandora FMS¶

    Pandora FMS monitoriza; Pandora ITSM atiende. La integración existe para que el aviso y el ticket no vivan en mundos separados: una alerta de monitorización puede abrir un ticket, y el técnico que lo resuelve ve el activo que la provocó.

    La integración va en dos direcciones. Desde Pandora FMS se crean, cierran, consultan y editan tickets de Pandora ITSM, a mano o de forma automática mediante alertas y respuestas de eventos. En sentido contrario, Pandora ITSM recibe el inventario de los agentes de Pandora FMS y lo convierte en objetos Computer con sus datos de hardware, software e información extendida.

    Todo se apoya en la API v2 de Pandora ITSM. No hay una base de datos compartida ni un agente especial: FMS llama a la API con un token, y la API hace el resto.

    Requisitos y permisos¶

    Antes de configurar nada, comprueba estos puntos:

    • Pandora FMS y Pandora ITSM se ven por red, preferiblemente por HTTPS.
    • La versión de Pandora FMS es 783 o superior si vas a usar la instalación conjunta desde su consola.
    • La IP de Pandora FMS está autorizada en Setup → Setup → General setup → List of IP with access to API de Pandora ITSM. Por defecto solo se permite localhost.
    • Tienes un token de API v2 generado en Pandora ITSM. El capítulo 11.1 explica cómo crearlo.
    • El usuario del token tiene permisos IM (gestión de tickets) y VW (escritura de inventario). Sin ellos, la API rechaza las llamadas de FMS.

    El token es la credencial de la integración. No lo compartas con otros usuarios ni lo reutilices para una segunda herramienta; si se filtra, se borra y se crea otro.

    Configurar la comunicación¶

    En Pandora ITSM hay dos pasos: autorizar la IP y crear el token.

    1. Añade la IP o el rango de Pandora FMS en Setup → Setup → General setup → List of IP with access to API.
    2. Genera un token en People → Edit my user → Create Token API v2, con una etiqueta como Pandora FMS y una fecha de expiración.
    3. Comprueba que el usuario del token puede gestionar tickets (IM) y escribir inventario (VW).

    En Pandora FMS, la configuración de la integración se hace en su sección de gestión de incidencias, indicando la URL de Pandora ITSM y el token. El procedimiento detallado vive en el manual de Pandora FMS; aquí no se replica porque cambia con la consola de monitorización y no es documentación de ITSM.

    Cuando la comunicación funciona, FMS puede crear y cerrar tickets en ITSM y mostrar los tickets existentes. La prueba más rápida es abrir un ticket desde FMS y comprobar que aparece en Support → Tickets de Pandora ITSM.

    Sincronización de inventario¶

    La sincronización convierte los agentes de Pandora FMS en objetos de inventario de Pandora ITSM. Se configura en Setup → Setup, pestaña Pandora FMS Inventory.

    La pantalla tiene tres bloques:

    • Clean objects: días tras los que se borran los objetos marcados como Missing que ya no tienen padre. 0 desactiva la limpieza.
    • Remote inventory: valores por defecto de los objetos que crea la sincronización. Default owner es obligatorio; las empresas y usuarios asociados deciden su visibilidad.
    • Nodes connected: los servidores de Pandora FMS que han conectado correctamente con Pandora ITSM.

    La tabla de nodos muestra el nombre del nodo, la ruta de conexión —por ejemplo, http://172.16.0.1:90/pandora_console/api/v2—, el progreso de los agentes sincronizados, el estado de la conexión y la operación de borrado. Un punto verde indica que el nodo responde.

    El nodo no se añade a mano en Pandora ITSM: lo registra Pandora FMS cuando la comunicación funciona. Si no aparece, el problema está en la configuración de FMS, en la URL o en el token, no en esta pantalla. Para reiniciar una conexión, borra el nodo y vuelve a configurarla desde Pandora FMS.

    Cada tipo de objeto sincronizado decide su ritmo con Sync interval: Never, Weekly, Every 15 days, Monthly o First time only. La opción solo aparece cuando hay nodos configurados y el tipo está asociado a un esquema de Pandora FMS. Los detalles de tipos, campos y stock están en el capítulo 4.1.

    Los objetos sincronizados son de tipo Computer y se enlazan con el agente mediante id_pandora. En su ficha aparecen las pestañas Hardware, Software y Extended Info con la información recogida por Pandora FMS.

    La sincronización no es inmediata: la ejecuta el cron de inventario, include/inventory_cron.php, normalmente cada cinco minutos. En cada pasada registra la marca inventory_crontask, sincroniza los nodos, caduca las programaciones vencidas y elimina los objetos Missing que ya no tienen padre.

    Instalación conjunta desde la consola de Pandora FMS¶

    Pandora FMS permite instalar una instancia de Pandora ITSM desde su propia consola. Es una forma rápida de probar la integración, no la vía recomendada para producción.

    En Pandora FMS, entra en Management → Settings → System Settings → ITSM y pulsa Install ITSM.

    Antes de instalar, Pandora FMS comprueba tres cosas:

    • Que la base de datos itsm no existe; si no existe, se crea.
    • Que el usuario de Pandora FMS —normalmente pandora— tiene permisos para crearla.
    • Que el directorio /var/www/html/pandora_console/itsm no existe; se creará durante la instalación.

    Si el usuario de la base de datos no tiene permisos, el administrador de MySQL debe concederlos antes de continuar:

    GRANT ALL PRIVILEGES ON `itsm`.* TO `pandora`;

    La instalación descarga los paquetes necesarios desde el repositorio oficial de Pandora FMS y crea el directorio de ITSM dentro de la consola de Pandora FMS. El progreso muestra los pasos y, al terminar, un enlace para acceder por primera vez a la consola de Pandora ITSM.

    Cuando termine, comprueba que puedes acceder a Pandora ITSM y que desde Pandora FMS se ven los tickets. Si la instalación conjunta falla, revisa los permisos de MySQL y el espacio en disco antes de repetirla.

    Buenas prácticas y problemas frecuentes¶

    • Usa un token propio para la integración, con etiqueta y caducidad. Si algo se filtra, sabes qué borrar.
    • Autoriza solo la IP de Pandora FMS, no un rango abierto.
    • Revisa que el usuario del token conserve IM y VW; un cambio de perfil rompe la integración sin avisar.
    • Si el nodo no aparece, comprueba la URL y el token en Pandora FMS. Si aparece pero no progresa, mira el cron y el estado de la conexión.
    • No borres un nodo mientras está sincronizando. Espera a que termine o a que el progreso se detenga.
    • La instalación conjunta es para pruebas. Para producción, instala Pandora ITSM por separado y configura la integración por API.

    Para el detalle de la API y los tokens, vuelve al capítulo 11.1. Para los tipos de objeto, campos y control de stock, al capítulo 4.1. Para los tickets que llegan desde FMS, al capítulo 3.1.

    Licensing¶

    A licence is not a sticker: it decides who can log in, how many administrators fit and what happens when the support date gets close. In Pandora ITSM the limit you notice most is the manager user limit; regular users are rarely the problem, but administrators pile up with surprising ease.

    The point of this chapter is simple: manage the licence before it hurts. Checking the count when nobody can log in is too late; checking it before creating the next administrator is cheap.

    Licence types¶

    Pandora ITSM works with four modes:

    Mode What it is Expiry Manager limit
    Perpetual Indefinite use of the product Support and update access expire Per contract
    Subscription Use while the subscription is active On expiry, the console enters limited mode Per contract
    Trial Product evaluation 30 days 25
    Free Free use with limited features No use expiry 1

    A perpetual licence does not stop working when it expires: what expires is support and access to updates. Subscription and trial do condition use: on expiry, the console enters limited mode and Enterprise features stop working. Free is the entry door: one administrator and the features available in that mode.

    Do not confuse the licence date with the version date. The first is tied to the contract; the second to the release cycle. Version details are in 1.3.

    How it is limited and counted¶

    The limit applied today is the manager user limit. A user counts as a manager if they have any profile with management permissions (im, am, um, dm, fm, pm, km, vm, wm, cm, frm or chm) or if they are a superadministrator. Regular users are the rest.

    The count:

    • Counts distinct users, not profiles. A user with three manager profiles takes one seat.
    • Does not count disabled users. A deactivated user frees their seat.
    • Does count users blocked by licence until they are disabled or deleted. Blocking does not give the seat back by magic.
    • Is calculated on the spot: creating, enabling or disabling a user changes the number.

    The regular-user limit exists in the code, but the current commercial licence leaves it practically without effect. In practice, the number to watch is Manager Count against Manager Limit.

    What happens when the limit is exceeded¶

    When the number of managers exceeds the limit, Pandora ITSM does not delete users or change profiles on its own. It does something simpler: it blocks login for the extra ones.

    The criterion is creation order: the oldest managers keep access and the newest are blocked. They appear in the user list with login disabled, and when they try to log in they receive a notice that the limit has been exceeded.

    There are three ways to recover access:

    1. Disable or delete managers who no longer need the account.
    2. Change the profile of a manager to a regular profile, if their duties allow it.
    3. Expand the licence with more manager seats.

    When the licence is expanded, blocked users are enabled again. The notice and the block disappear, but the count remains: the seat is not free, it is paid for.

    How the licence looks¶

    The Warp update → License screen shows the four pieces of data that matter:

    • License Mode: perpetual, subscription, trial or free.
    • Expires: licence or support expiry date.
    • Manager Limit: contracted manager seats.
    • Manager Count: managers currently occupying a seat.

    The same information appears in About ITSM. If the count is close to the limit, do not wait for the next hire: review inactive users or expand the licence.

    How to update the licence¶

    The normal flow is:

    1. Open Warp update → License.
    2. Paste the licence key into License key.
    3. Click Update license.
    4. Confirm that the mode, expiry and limit have changed.

    If you need a new licence:

    1. Click Request new license.
    2. Copy the Request key shown in the window.
    3. Provide the Auth key you receive from support.
    4. Validate online with Online validation or, if the server has no outbound access, use offline validation: enter the Auth key, click Generate and copy the resulting licence.
    5. Go back to the console, paste the licence and click Update license.

    Expired licences¶

    When a subscription or trial licence expires, the console stops working normally: the expired or invalid licence warning appears and Enterprise features become limited. It is not a configuration error; it is the licence.

    With a perpetual licence the product keeps working. What expires is support and access to updates; the console warns you, but it does not block normal use.

    In either case, the path is the same: Request new license, support Auth key and online or offline validation. If the licence has expired, do not try to fix it by updating the product: renew the licence first.

    Best practices¶

    • Check Manager Count before creating a new administrator.
    • Disable the accounts of people who leave; a disabled account frees a seat.
    • Do not share the admin account or make someone an administrator just because they need to read reports.
    • Keep the licence key in a safe place; do not paste it into tickets.
    • Watch the Expires date and renew before the console enters limited mode.
    • If you are going to expand the licence, do it before a mass user creation.

    IA y chatbot¶

    El chatbot de Pandora ITSM no es una ventana que responde «hola» y se queda esperando. Es un sistema de atención con dos piezas: un servidor de chat con su cliente web y, si se quiere, un motor de inteligencia artificial que aprende de la base de conocimiento y de los diálogos para proponer respuestas.

    Sin IA, el chat funciona igual: los usuarios abren una conversación y un operador contesta. Con IA, el sistema puede responder solo, asistir al operador o hacer las dos cosas según el modo. La diferencia entre «tener chat» y «tener chatbot» está en esa segunda pieza, y en entrenarla.

    La arquitectura tiene tres elementos: el cliente de chat, con el que interactúa el usuario; el servidor de chat, con el que trabaja el operador; y el motor de predicción, que genera las respuestas. El cliente y el servidor vienen con Pandora ITSM; el motor de predicción se instala aparte.

    Servidor de chat¶

    La configuración global está en Setup → Setup → ChatBot, dentro de Chat Global Options.

    Los campos principales son:

    • Enable chat: activa el servicio.
    • Ws url, Ws port y Ws password: dirección, puerto y contraseña del web service del chat.
    • Ws channel by default: canal que se usa por defecto.
    • Check chat server: comprueba la conexión; un punto verde indica que responde.
    • General chat: Disabled, Only IA o Manual.
    • Ticket chat: Disabled o Enabled para el chat dentro de los tickets.
    • Enable SSL: activa HTTPS y muestra las rutas de certificado y clave.

    Ws url debe ser la URL pública de la instalación de Pandora ITSM —la misma que aparece en Public access to server, en el setup general—, no una dirección interna que el navegador del usuario no pueda alcanzar. Si el chat no conecta, revisa esa URL antes de tocar Node.js.

    Si la IA está activa, debajo aparecen los botones botón de actualización de la base de conocimiento y Update conversational model, que reentrenan los modelos con la información actual.

    HTTPS y Node.js¶

    Para servir el chat fuera de la consola conviene HTTPS. Activa Enable SSL, sustituye los certificados de ejemplo por los tuyos, guarda con Update y comprueba que Check chat server sigue en verde.

    El servidor de chat es una aplicación Node.js que vive en extras/chat_server. La instalación típica en un sistema con yum es:

    curl -fsSL https://rpm.nodesource.com/setup_lts.x | bash -
yum install -y nodejs
npm i -g pm2
cd /var/www/html/pandoraitsm/extras/chat_server
npm update
pm2 start server.js

    Usa una versión de Node.js compatible con las dependencias actuales —el servidor usa Express 5, así que necesita una versión moderna— y no la 12 que aparecía en manuales antiguos. Si npm se queja de la versión, el chat no arrancará aunque la configuración sea correcta.

    Para que arranque con el sistema, crea /etc/systemd/system/pandoraitsm-chat.service:

    [Unit]
Description=Pandora ITSM Chat Server
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/node server.js
Restart=always
User=root
Environment=NODE_ENV=production
WorkingDirectory=/var/www/html/pandoraitsm/extras/chat_server

[Install]
WantedBy=multi-user.target

    Y actívalo:

    systemctl daemon-reload
systemctl enable --now pandoraitsm-chat.service

    La conexión a la base de datos se configura en extras/chat_server/config/config.js. Los valores por defecto sirven para una instalación estándar; cámbialos si la base de datos está en otro servidor o usa otras credenciales.

    Motor de IA y configuración por canal¶

    El motor de predicción se instala como root y escucha en el puerto 6000/tcp:

    yum install -y python3 python36-Cython
wget http://<servidor>/prediction_engine-latest.tgz
tar xvzf prediction_engine-latest.tgz
cd prediction_engine
./install.sh
systemctl restart prediction_engine.service

    La IA se configura por canal, no de forma global: Support → Chat → Channel Manage, clic en el nombre del canal y Enable Chat IA.

    Hay dos modos de IA:

    • Pandora ITSM AI: usa el motor de predicción local. Se indican IA url —la URL del web service, por ejemplo http://192.168.1.10—, IA port —por defecto 6000— y Mode IA:
    • Manual: la IA no responde; el operador lleva la conversación.
    • Semi-auto: la IA sugiere respuestas y el operador elige.
    • Full-auto: la IA responde sola.
    • ChatGPT (OpenAI): usa la API de OpenAI. Se configuran API Key, Model (gpt-4 o gpt-3.5-turbo), Max tokens, Context time, Temperature, Avatar, Title, Subtitle y Context.

    En Full-auto aparecen además los tiempos de respuesta y el umbral de certeza:

    • Initial response time: segundos antes de la primera respuesta.
    • Response time between conversations: espera entre pregunta y pregunta.
    • Progress bar timeout: tiempo que tiene el operador para elegir una respuesta antes de que la IA conteste sola.
    • Certainty threshold: seguridad mínima, entre 0 y 1, para aceptar una respuesta. Un valor bajo responde a todo; uno alto prefiere callar.

    En ChatGPT, Context es el mensaje de sistema que se envía al principio. Pandora ITSM le añade la indicación de responder en el idioma del usuario —o en el idioma por defecto del canal si el del usuario no está disponible—. Temperature va de 0 a 1: cuanto más baja, más predecible; cuanto más alta, más creativa.

    Antes de cambiar modelos o entrenar, haz una copia:

    cp -r /opt/prediction_engine/models /opt/prediction_engine/models.bak

    Para restaurar:

    cp -f /opt/prediction_engine/models.bak/* /opt/prediction_engine/models/

    Entrenamiento de modelos¶

    Lo normal es usar los botones los botones de actualización del modelo de la base de conocimiento y del modelo conversacional del Setup. El entrenamiento manual es avanzado y solo tiene sentido si necesitas controlar el corpus.

    El modelo de preguntas y respuestas se entrena con un CSV con este formato:

    lang;question;answer
"es";"¿Cómo abro un ticket?";"En Support → Create new ticket."
"en";"How do I open a ticket?";"In Support → Create new ticket."

    Puedes generarlo desde la base de datos de Pandora ITSM:

    SELECT id_language AS lang, title AS question, data AS answer
FROM tkb_data
INTO OUTFILE '/opt/prediction_engine/data/pandoraitsm_kb.csv'
FIELDS TERMINATED BY ';' ENCLOSED BY '"'
LINES TERMINATED BY '\n';

    Comprime el CSV, colócalo en /opt/prediction_engine/data/ y entrena:

    cd /opt/prediction_engine/src
python kb_train.pyc

    Los diálogos conversacionales se definen en YAML por idioma:

    categories:
  - Soporte
  - Facturación
conversations:
  - - Hola
    - ¿En qué puedo ayudarte?
  - - Quiero abrir un ticket
    - Entra en Support y pulsa Create new ticket

    Los ficheros se guardan en /opt/prediction_engine/data/chat_es o chat_en, según el código ISO del idioma, y se entrenan con:

    cd /opt/prediction_engine/src
python chat_train.pyc

    Además de los ficheros YAML, Support → Chat → Conversations → Data management permite añadir ítems conversacionales por categoría e idioma y buscarlos por palabra clave.

    Uso del chat y canales¶

    Los canales definen dónde se conversa. Support → Chat → Channel Manage lista los canales y permite crear, editar, borrar y generar el código para incrustarlos.

    Cada canal necesita al menos un operador. Con Edit users se añaden usuarios y se define su descripción, avatar e idiomas. El operador puede tener un avatar distinto al de su ficha y varios idiomas de atención.

    Los operadores atienden desde Support → Chat → Chat View. La pantalla muestra las conversaciones con estado, usuario, canal, idioma, tiempo activo, operador y ticket asociado. Para recibir avisos sonoros hay que estar en esa pantalla; el chat no avisa si el operador está en otra sección.

    Si el chat lo abre un usuario interno, la conversación indica de quién se trata. Si lo abre un visitante anónimo desde fuera, aparece como usuario externo.

    Para usar el chat fuera de Pandora ITSM, pulsa Generate Bundle en el canal. El icono de estrella muestra el snippet JavaScript que hay que incrustar en la web o aplicación. La URL del snippet es la URL pública configurada en el servidor de chat; debe ser accesible desde donde estén los usuarios, normalmente Internet.

    Buenas prácticas y problemas frecuentes¶

    • Usa HTTPS si el chat va a estar fuera de la consola. El aviso del navegador espanta a cualquier visitante.
    • Dedica un canal a cada uso —soporte interno, web pública, preventa— y no mezcles operadores e idiomas sin criterio.
    • Antes de entrenar, copia /opt/prediction_engine/models. Un corpus mal preparado se lleva por delante el modelo anterior.
    • Si el chat no conecta, revisa en este orden: Ws url, servicio Node.js, Check chat server y certificados.
    • Si la IA no responde, revisa el modo del canal, la URL y el puerto del motor, y que el servicio prediction_engine esté en el puerto 6000.
    • Rota la API key de OpenAI si la compartes o sospechas que se ha filtrado.

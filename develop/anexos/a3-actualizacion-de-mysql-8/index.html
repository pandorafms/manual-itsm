    Actualización de MySQL 5.7 a MySQL 8¶

    MySQL 8 cambia lo suficiente como para que una actualización a ciegas no sea una buena idea: desaparece la caché de consultas, cambian los complementos de autenticación y el motor necesita un respaldo que pueda importarse en la versión nueva. Este anexo recoge el procedimiento para pasar de MySQL 5.7 a Percona Server 8 en Pandora ITSM.

    Prerrequisitos¶

    Para migrar de MySQL 5.7 a MySQL 8 debes estar actualizado como mínimo a la versión 104 de Pandora ITSM.

    Requisito Detalle
    Usuario root Los comandos gestionan servicios, repositorios y la base de datos; hacen falta privilegios de administrador.
    Versión de MySQL Ejecuta mysql --version y comprueba que estás en 5.7.
    Copia de seguridad Guarda la base de datos y el fichero my.cnf antes de tocar nada.
    Ventana de mantenimiento La consola queda parada durante la migración.

    Comprueba el punto de partida:

    mysql --version

    La respuesta debe ser similar a:

    mysql  Ver 14.14 Distrib 5.7.33, for Linux (x86_64) using EditLine wrapper

    Haz un respaldo de la base de datos. El procedimiento general está en 12.2 Mantenimiento y copias de seguridad. La base de datos se cita en este anexo como <pandora_itsm_db_name>.

    Rocky Linux 8 / AlmaLinux 8 / RHEL 8¶

    Detén Apache:

    systemctl stop httpd.service

    O, si la instalación usa SysV:

    /etc/init.d/httpd stop

    Haz un respaldo especial de la base de datos compatible con MySQL 8:

    mysqldump -u root -p <pandora_itsm_db_name> \
  --skip-add-drop-table \
  --complete-insert \
  --no-create-info > backup_pandora_itsm.sql

    Haz también un respaldo tal cual está hecho en MySQL 5.7, como seguro para volver atrás:

    mysqldump -u root -p <pandora_itsm_db_name> > backup_pandora_itsm_5.7.sql

    Guarda el fichero de configuración:

    cp /etc/my.cnf /tmp/my.cnf.BACK

    Elimina los repositorios de Percona 5:

    rpm -qa | grep Percona-Server | xargs rpm -e --nodeps

    Instala el repositorio de Percona 8:

    dnf install https://repo.percona.com/yum/percona-release-latest.noarch.rpm -y

    Habilita el repositorio:

    percona-release setup ps80

    Instala Percona Server 8:

    dnf install percona-server-server

    Restablece el fichero de configuración:

    mv /tmp/my.cnf.BACK /etc/my.cnf

    Desactiva las directivas de caché de consultas, que ya no existen en MySQL 8:

    sed -i -e "s/^query_cache_type.*/#query_cache_type/g" /etc/my.cnf
sed -i -e "s/^query_cache_size.*/#query_cache_size/g" /etc/my.cnf
sed -i -e "s/^query_cache_min_res_unit.*/#query_cache_min_res_unit/g" /etc/my.cnf
sed -i -e "s/^query_cache_limit.*/#query_cache_limit/g" /etc/my.cnf

    Si no tienes un entorno de alta disponibilidad, desactiva los logs binarios añadiendo esta línea en la sección [mysqld] de my.cnf:

    skip-log-bin

    Inicia MySQL:

    systemctl start mysql

    O, si el servicio usa otro nombre:

    service mysqld start

    Verifica la versión instalada:

    mysql --version

    La respuesta debe ser similar a:

    mysql  Ver 8.0.28-19 for Linux on x86_64 (Percona Server (GPL), Release 19, Revision 31e88966cd3)

    Migrar la base de datos¶

    Entra en la línea de comandos de MySQL:

    mysql -u root -p <pandora_itsm_db_name>

    Borra la base de datos antigua, crea una nueva e importa el esquema y los datos del respaldo especial:

    DROP DATABASE <pandora_itsm_db_name>;
CREATE DATABASE <pandora_itsm_db_name>;
USE <pandora_itsm_db_name>;
SOURCE /var/www/html/pandoraitsm/integria_db.sql;
SOURCE backup_pandora_itsm.sql;

    El esquema integria_db.sql es el de la instalación de Pandora ITSM. No uses el de otra versión ni el de otro producto.

    Permisos y autenticación¶

    Hay que volver a crear los permisos de la base de datos. Si no estás conectado como root, entra con:

    mysql -uroot -p

    Dentro de MySQL, desactiva el complemento de validación de contraseñas si lo tenías activo (es opcional):

    UNINSTALL COMPONENT 'file://component_validate_password';

    Crea el usuario de conexión si no existe:

    CREATE USER "<DBUSER>"@'%' IDENTIFIED BY "<DBPASS>";

    Si quieres restringir la conexión a una IP concreta, cambia % por la dirección de la fuente de conexión.

    Asigna la autenticación nativa de MySQL:

    ALTER USER "<DBUSER>"@'%' IDENTIFIED WITH mysql_native_password BY "<DBPASS>";

    Otorga los permisos sobre la base de datos de Pandora ITSM:

    GRANT ALL PRIVILEGES ON <pandora_itsm_db_name>.* TO "<DBUSER>"@'%';

    Guarda los cambios y sal:

    FLUSH PRIVILEGES;
exit

    Si necesitas cambiar el método de autenticación a SHA, consulta la documentación de MySQL 8 para tu versión antes de modificar el usuario.

    Arrancar la consola¶

    Inicia Apache de nuevo:

    systemctl start httpd.service

    O, si la instalación usa SysV:

    /etc/init.d/httpd start

    Comprueba que la consola responde, que puedes iniciar sesión y que los datos anteriores siguen ahí. Si algo falla, conserva los dos respaldos y el my.cnf hasta haber validado la instalación.

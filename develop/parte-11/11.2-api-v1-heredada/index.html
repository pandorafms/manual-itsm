    API v1 (heredada)¶

    La API 1.0 de Pandora ITSM sigue viva por compatibilidad. No es una API REST: es una llamada HTTP al fichero include/api.php con una operación (op) y una lista de parámetros separados por comas. Devuelve CSV por defecto, XML si se pide y, en algunas llamadas, JSON.

    Si estás empezando una integración, usa la API v2 del capítulo 11.1. Esta API solo se mantiene para scripts antiguos y para integraciones que ya hablan su dialecto. El código que manda es include/api.php y include/functions_api.php; lo que no esté en el despachador no existe, por mucha documentación antigua que lo mencione.

    Qué es y cómo se llama¶

    La URL base es la de la consola seguida de include/api.php:

    https://<Console_web_URL>/pandoraitsm/include/api.php?<parámetros>

    Los parámetros comunes son:

    Parámetro Obligatorio Qué hace
    user Sí Usuario de Pandora ITSM que ejecuta la llamada y sobre el que se aplican las ACL.
    user_pass Sí, salvo bearer token Contraseña del usuario.
    pass Solo si api_password está configurada Contraseña específica de la API.
    op Sí Operación que se ejecuta.
    params Según la operación Parámetros de la operación, separados por token.
    token No Separador de params; por defecto la coma (,).
    return_type No csv (por defecto), xml o json según la operación.
    info No info=version devuelve la versión sin autenticarse.

    La llamada de información no necesita usuario, contraseña ni IP autorizada:

    …/include/api.php?info=version

    Devuelve una cadena similar a:

    Pandora ITSM Enterprise Edition 5.0.109 Build 260603 MR109

    Una operación desconocida no devuelve un error descriptivo: el despachador duerme 15 segundos y termina sin cuerpo. Si un script se queda colgado, revisa primero el nombre de op.

    Autenticación¶

    La API 1.0 encadena varias comprobaciones. Todas las llamadas, salvo info=version, pasan por la lista de IP y por la autenticación de usuario.

    Lista de IP¶

    La lista se configura en Setup → Setup → General setup, campo List of IP with access to API (token api_acl). Por defecto solo permite 127.0.0.1.

    Acepta direcciones separadas por comas, espacios o líneas, y un asterisco como comodín: 192.168.7.* o *. El código usa una expresión regular, así que el comodín también puede coincidir con una parte de la dirección. Abrir la API a * es cómodo para probar y una mala idea en producción.

    Contraseña de API¶

    Si api_password no está vacía, hay que enviarla en el parámetro pass. Si está vacía, la comprobación se omite.

    La contraseña viaja sin cifrar. Si usas este método, la llamada debe ir por HTTPS; en HTTP cualquiera que escuche la red la ve.

    Usuario y contraseña¶

    user y user_pass son obligatorios en todas las llamadas que no usen bearer token. No hay forma de desactivar esta comprobación: la contraseña de API es un segundo factor, no un sustituto.

    Bearer token¶

    También se puede autenticar con la cabecera HTTP:

    Authorization: Bearer <token>

    El token se compara con el campo api_key del usuario indicado en user. La lista de IP sigue aplicándose. Si la cabecera está presente, la API no usa user_pass ni pass; si el token no coincide, la respuesta es 401.

    Ejemplo con curl:

    curl -k \
  -H "Authorization: Bearer $PITSM_API_TOKEN" \
  "https://192.0.2.10/pandoraitsm/include/api.php?user=admin&op=get_groups&return_type=xml"

    Si la autenticación falla, la API responde 401 y no devuelve cuerpo. No hay mensaje de error distinto para usuario inexistente, contraseña incorrecta o IP no autorizada.

    Formato de las llamadas¶

    params es una lista ordenada. El separador por defecto es la coma, pero se puede cambiar con token:

    …&op=create_workunit&params=1,Descripción,0.5,0,1,1
…&op=create_workunit&token=|&params=1|Descripción|0.5|0|1|1

    Dos convenciones se repiten en las llamadas de tickets:

    • Una coma dentro de un valor se escribe como :::.
    • Un espacio se codifica como %20 en la URL.

    Por ejemplo, Doe, John se envía como Doe:::%20John. No todas las funciones hacen la sustitución inversa; las que la soportan la aplican al título, la descripción o el nombre, según el caso.

    return_type acepta csv (por defecto), xml y, solo en las llamadas que lo implementan, json: incidencias, unidades de trabajo, estados, grupos, usuarios, prioridades, campos, tipos y conteo de tickets.

    Las respuestas correctas no siempre son 1: muchas llamadas devuelven el identificador creado, un 0 o un -1. Las ACL se comprueban dentro de cada función y pueden registrar una entrada de auditoría antes de salir sin cuerpo.

    Funciones¶

    Cada llamada tiene su propia ficha. Los parámetros se indican en el orden exacto de params; un parámetro marcado como obligatorio debe ir siempre, aunque vaya vacío si el formato lo permite.

    get_login¶

    Comprueba que las credenciales son válidas. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_login

    Devuelve: 1 si la autenticación es correcta. Si falla, la llamada ya habrá devuelto 401 antes de llegar aquí.

    create_user¶

    Crea un usuario y lo asigna a un grupo y un perfil. Parámetros: usuario (obligatorio), grupo (obligatorio), perfil (obligatorio), email (opcional), contraseña (opcional; si va vacía se usa el nombre del usuario que llama), descripción (opcional), nombre real (opcional), externo (0 o 1).

    …/api.php?user=admin&user_pass=adminpass&op=create_user&params=jorge,3,4,jorge@example.com,userpass,description,Jorge%20Surname,1

    Devuelve: 1 si se crea, 0 si falla. Exige permiso UM. externo=1 crea nivel -1 (Standalone); externo=0 crea nivel 0 (agrupado).

    get_incidents¶

    Lista los tickets visibles para el usuario. Parámetros: cadena de búsqueda, estado, grupo (obligatorio; 1 para todos), prioridad, inventario, propietario, creador, id de ticket y id de inventario Pandora.

    …/api.php?user=user&user_pass=userpass&op=get_incidents&params=day,-10,1,-1,0,admin,user1

    Estados: 0 todos, 1 nuevo, 2 no confirmado, 3 asignado, 4 reabierto, 5 pendiente de cierre, 6 pendiente de terceros, 7 cerrado, -10 todos menos cerrados. Prioridades: 10, 0, 1, 2, 3, 4, -1.

    Devuelve: CSV, XML o JSON. Límite interno de 5.000 tickets. Un usuario no administrador solo ve los tickets que posee o ha creado.

    user_exists_in_group¶

    Comprueba si un usuario está en uno o varios grupos. Parámetros: usuario, grupo1, grupo2…

    …/api.php?user=user&user_pass=userpass&op=user_exists_in_group&params=test,4,5

    Devuelve: 1 o 0. Un administrador devuelve 1 sin consultar los grupos.

    get_incident_details¶

    Devuelve el detalle de un ticket. Parámetro: id de ticket.

    …/api.php?user=user&user_pass=userpass&op=get_incident_details&params=2

    Devuelve: CSV o XML con los campos del ticket.

    create_incident¶

    Crea un ticket. Parámetros: título (obligatorio), grupo (obligatorio), prioridad, descripción, inventarios separados por :, tipo de ticket, email en copia, propietario, ticket padre, estado (obligatorio), extra_data, resolución, extra_data2, extra_data3, extra_data4 y los campos personalizados del tipo desde la posición 15.

    …/api.php?user=user&user_pass=userpass&op=create_incident&params=Title,2,1,Description%20of%20the%20incident,1:2:3,1,copy@example.com,admin,0,1

    Devuelve: el id del ticket creado o -1 si falla. Exige permiso IW. El título vacío aborta la llamada. Una coma en el título o la descripción se envía como :::.

    update_incident¶

    Actualiza un ticket. Parámetros: id, título, descripción, epílogo, grupo, prioridad, resolución, estado, propietario, padre, tipo, extra_data, extra_data2, extra_data3, extra_data4 y campos personalizados desde la posición 15.

    …/api.php?user=user&user_pass=userpass&op=update_incident&params=4,new%20title,new%20description,new%20epilog,4,2,1,3,admin,0,6

    Devuelve: resultado de la actualización. Si el ticket se cierra, guarda la resolución; si no, la fuerza a 0. Solo el propietario, el creador o un administrador pueden modificarlo.

    delete_incident¶

    Borra un ticket. Parámetro: id de ticket.

    …/api.php?user=user&user_pass=userpass&op=delete_incident&params=3

    Devuelve: 1. Exige acceso al ticket.

    add_inventory_to_ticket¶

    Asocia un objeto de inventario a un ticket. Parámetros: id de ticket, id de inventario.

    …/api.php?user=user&user_pass=userpass&op=add_inventory_to_ticket&params=1,2

    Devuelve: 1 o 0. Exige permiso VW.

    get_incident_tracking¶

    Devuelve el historial de seguimiento del ticket. Parámetro: id de ticket.

    …/api.php?user=user&user_pass=userpass&op=get_incident_tracking&params=2

    Devuelve: CSV o XML con los registros de tracking.

    get_incidents_resolutions¶

    Devuelve el catálogo de resoluciones. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_resolutions

    Devuelve: CSV o XML con id y name de cada resolución.

    get_incidents_status¶

    Devuelve el catálogo de estados. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_status

    Devuelve: CSV, XML o JSON con id y name de cada estado.

    get_incident_priorities¶

    Devuelve el catálogo de prioridades. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_incident_priorities

    Devuelve: CSV, XML o JSON con id y name de cada prioridad.

    get_incident_fields¶

    Devuelve los campos personalizados de un tipo de ticket y, si se indica un ticket, sus valores. Parámetros: id de tipo, id de ticket (opcional).

    …/api.php?user=user&user_pass=userpass&op=get_incident_fields&params=4,32

    Devuelve: CSV, XML o JSON con los campos. Si el ticket no se indica, solo devuelve la definición del tipo.

    get_types¶

    Devuelve el catálogo de tipos de ticket. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_types

    Devuelve: CSV, XML o JSON con id y name de cada tipo.

    get_tickets_count¶

    Cuenta tickets agrupados por una columna y un periodo. Parámetros: columna, días máximos.

    …/api.php?user=user&user_pass=userpass&op=get_tickets_count&params=id_grupo,30

    Devuelve: JSON con el conteo por grupo. Es la única llamada que siempre responde JSON, aunque se pida otro return_type.

    get_incident_workunits¶

    Lista las unidades de trabajo de un ticket. Parámetro: id de ticket.

    …/api.php?user=user&user_pass=userpass&op=get_incident_workunits&params=3

    Devuelve: CSV, XML o JSON con las unidades.

    create_workunit¶

    Añade una unidad de trabajo a un ticket. Parámetros: id de ticket, descripción, horas, coste (0 o 1), público (0 o 1), id de perfil.

    …/api.php?user=user&user_pass=userpass&op=create_workunit&params=1,Description,0.5,0,1,1

    Devuelve: 0 o un mensaje de error. No admite tickets cerrados ni duplica una unidad con la misma descripción en el mismo ticket.

    get_incident_files¶

    Lista los ficheros adjuntos de un ticket. Parámetro: id de ticket.

    …/api.php?user=user&user_pass=userpass&op=get_incident_files&params=1

    Devuelve: CSV o XML con los adjuntos.

    download_file¶

    Descarga un adjunto. Parámetro: id de adjunto.

    …/api.php?user=user&user_pass=userpass&op=download_file&params=32

    Devuelve: contenido del fichero en Base64.

    attach_file¶

    Adjunta un fichero a un ticket. Parámetros: id de ticket, nombre, tamaño, descripción, contenido en Base64.

    …/api.php?user=user&user_pass=userpass&op=attach_file&params=1,example.txt,234,File%20of%20example,aW50ZWdyaWEgcm9ja3M=

    Devuelve: 0 si va bien, -1 si no puede escribir. Si el fichero ya existe en el ticket, devuelve 0 sin duplicarlo.

    delete_file¶

    Borra un adjunto. Parámetro: id de adjunto.

    …/api.php?user=user&user_pass=userpass&op=delete_file&params=32

    Devuelve: 0 si va bien, -1 si falla la comprobación de permisos, -2 si no puede borrar el fichero físico.

    validate_user¶

    Comprueba usuario y contraseña. Parámetros: usuario, contraseña.

    …/api.php?user=user&user_pass=userpass&op=validate_user&params=jorge,jorge_pass

    Devuelve: 1 si es correcto, 0 si el usuario no existe o está deshabilitado, -1 si la contraseña es incorrecta.

    delete_user¶

    Borra un usuario. Parámetro: usuario.

    …/api.php?user=user&user_pass=userpass&op=delete_user&params=pepe

    Devuelve: 1 o 0. No permite borrar admin. Exige permiso UM.

    user_exists¶

    Comprueba si existe un usuario. Parámetro: usuario.

    …/api.php?user=user&user_pass=userpass&op=user_exists&params=pepe

    Devuelve: 1 o 0.

    get_users¶

    Lista los usuarios visibles para quien llama. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_users

    Devuelve: CSV, XML o JSON con los identificadores.

    get_groups¶

    Lista los grupos visibles. Parámetro opcional: params=1 para incluir el grupo 1.

    …/api.php?user=user&user_pass=userpass&op=get_groups
…/api.php?user=user&user_pass=userpass&op=get_groups&params=1

    Devuelve: CSV, XML o JSON con id y name de cada grupo.

    get_stats¶

    Devuelve una métrica de tickets. Parámetros: métrica, cadena, estado, usuario, grupo, empresa, inventario, prioridad.

    …/api.php?user=user&user_pass=userpass&op=get_stats&params=sla_compliance
…/api.php?user=user&user_pass=userpass&op=get_stats&params=opened,,1

    Métricas: total_incidents, opened, closed, avg_life, sla_compliance, avg_scoring y avg_worktime. Si no se indica grupo, se usa el grupo 1.

    Devuelve: un valor CSV o XML.

    get_incidents_summary¶

    Devuelve el resumen por estado. Parámetro opcional: new, unconfirmed, assigned, reopened, verified, pending_third_person, closed, not_closed o total.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_summary
…/api.php?user=user&user_pass=userpass&op=get_incidents_summary&params=not_closed

    Devuelve: todos los contadores o solo el campo pedido, en CSV o XML.

    get_last_cron_execution¶

    Devuelve los minutos desde la última ejecución del cron. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_last_cron_execution

    Devuelve: minutos, o -1 si no hay registro.

    get_previous_cron_execution¶

    Devuelve los minutos desde la ejecución anterior del cron. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_previous_cron_execution

    Devuelve: minutos, o -1 si no hay registro.

    get_num_queued_emails¶

    Devuelve los correos pendientes en cola. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_num_queued_emails

    Devuelve: número de correos.

    get_last_invoice_id¶

    Devuelve el último bill_id de factura enviada. No lleva parámetros.

    …/api.php?user=user&user_pass=userpass&op=get_last_invoice_id

    Devuelve: el identificador o vacío.

    get_invoice¶

    Devuelve los datos de una factura. Parámetro: bill_id.

    …/api.php?user=user&user_pass=userpass&op=get_invoice&params=140601_0071

    Devuelve: CSV o XML con la factura.

    create_invoice¶

    Crea una factura. Parámetros: usuario, tarea, empresa, bill_id, concepto, importe, impuesto, moneda, descripción, bloqueo, usuario bloqueador, fecha de creación, fecha de pago, estado, referencia, nota interna, tipo (Submitted o Received), idioma.

    …/api.php?user=user&user_pass=userpass&op=create_invoice&params=admin,,1,140601_0082,paso,3.00,,EUR,,,,,,paid,,,Submitted,

    Devuelve: estado y mensaje, por ejemplo 1,"invoice created" o 0,"invalid billing id". Exige permiso CW.

    create_company¶

    Crea una empresa. Parámetros: nombre, dirección, identificación fiscal, rol, país, manager, empresa padre.

    …/api.php?user=user&user_pass=userpass&op=create_company&params=Artica,AlbertoAguilera,12312312,1,Spain,admin,0

    Devuelve: id de la empresa creada. Exige permiso CW; el manager debe existir o ir vacío.

    mark_created_incident¶

    Marca el registro de creación de un ticket con información extra. Parámetros: id de ticket, texto.

    …/api.php?user=user&user_pass=userpass&op=mark_created_incident&params=10,Origen%20externo

    Devuelve: resultado directo de la actualización, sin CSV ni XML.

    mark_updated_incident¶

    Marca el registro de actualización de un ticket. Parámetros: id de ticket, texto.

    …/api.php?user=user&user_pass=userpass&op=mark_updated_incident&params=10,Actualizado%20por%20API

    Devuelve: resultado directo de la actualización.

    ovo_manager¶

    Integración específica OVO. Parámetros: título, grupo, prioridad, descripción, inventario, tipo, información extra, mensaje de grupo.

    …/api.php?user=user&user_pass=userpass&op=ovo_manager&params=Title,2,2,Description,10626,10,extra,msg

    Usa el grupo 11 y el usuario ovo de forma fija. Devuelve: resultado variable según las actualizaciones que aplique. No es una llamada general.

    reset_double_factor¶

    Restablece el doble factor. Parámetro: hash cifrado con el formato de la consola (para administradores).

    …/api.php?user=admin&user_pass=adminpass&op=reset_double_factor&params=<hash>

    Devuelve: JSON con status. Un usuario normal solo puede restablecer su propio factor.

    Extender la API¶

    La API 1.0 no tiene router automático. Para añadir una llamada hacen falta dos piezas:

    1. Una función en include/functions_api.php que reciba $return_type y los parámetros, y devuelva o imprima el resultado.
    2. Un case en el switch ($op) de include/api.php que la invoque.

    El esqueleto mínimo es:

    function api_mi_llamada($return_type, $user, $params)
{
    // Comprobaciones de ACL y validación.
    $result = 1;

    switch ($return_type) {
        case 'xml':
            echo xml_node($result);
            break;
        default:
            echo $result;
            break;
    }
}

    Y en el despachador:

    case 'mi_llamada':
    $params = explode($token, $params);
    echo api_mi_llamada($return_type, $user, $params);
    break;

    Mantén el formato de salida y las comprobaciones de ACL dentro de la función. La API v1 no pone nada de eso por ti.

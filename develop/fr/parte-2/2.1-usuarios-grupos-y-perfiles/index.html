    Utilisateurs, groupes et profils¶

    Pandora ITSM s'organise autour d'une idée simple qui se complique ensuite juste ce qu'il faut : chaque utilisateur possède un profil dans un groupe. Le groupe décide quelles informations il voit ; le profil décide ce qu'il peut en faire. Un droit mal configuré ne provoque pas d'erreur : il donne accès. Et c'est pire.

    La thèse de ce chapitre est la même que d'habitude : le moindre privilège n'est pas une mode d'audit, c'est ce qui empêche un utilisateur de casser ce qu'il ne comprend pas. Avec des groupes bien séparés et des profils ajustés, le reste du produit fonctionne mieux.

    Le modèle : groupe, profil et utilisateur¶

    La structure des permissions repose sur trois concepts :

    • User ID : nom unique pour se connecter à la console web.
    • Group : ensemble d'utilisateurs qui se voient entre eux. Il peut représenter un service, un client ou une entreprise.
    • Profile : ensemble de bits d'accès qui définit ce que l'utilisateur peut faire.

    Un utilisateur peut avoir plusieurs combinaisons profil + groupe. Par exemple, chef de projet dans un groupe et opérateur de tickets dans un autre. Les permissions ne sont pas globales : elles s'appliquent au groupe dans lequel elles sont accordées.

    À cela s'ajoutent les Teams : des regroupements d'utilisateurs de différents groupes qui travaillent ensemble dans Support, Changes ou CRM sans dupliquer les comptes ni modifier leurs profils.

    Gestion des utilisateurs¶

    Le gestionnaire se trouve dans People → User management.

    • Pour modifier, cliquez sur le User ID.
    • Pour supprimer, sélectionnez la ligne et cliquez sur Delete selected, ou utilisez Delete user dans la colonne Actions.
    • Pour créer, cliquez sur Create user +.

    Chaque utilisateur possède deux interrupteurs à ne pas confondre :

    • Activation : si le compte est activé.
    • Login enabled : s'il peut se connecter de façon interactive à la console.

    Certains utilisateurs n'existent que pour gérer des tickets par courriel : ils n'ont pas besoin de connexion interactive.

    Dans la fiche utilisateur, vous pouvez choisir le Dashboard (welcome screen) qu'il verra à la connexion et lui attribuer une Company. L'entreprise compte : dans plusieurs sections, l'accès dépend non seulement du groupe mais aussi de l'entreprise de l'utilisateur.

    Modification par l'utilisateur lui-même¶

    Tout utilisateur peut modifier ses données depuis People → Edit my user ou depuis le raccourci de l'en-tête. Il peut y voir sa clé API 1.0 dans un QR code ou générer un jeton pour l'API 2.0. Un utilisateur sans profil peut aussi accéder à cette option.

    Usurper des utilisateurs¶

    Un administrateur peut entrer dans la console en tant qu'autre utilisateur pour vérifier ce que celui-ci voit et peut faire avant d'accorder ou de retirer des permissions. L'action se trouve dans la fiche utilisateur, dans l'en-tête General info : Impersonate user. Elle n'apparaît qu'aux administrateurs et pour des utilisateurs valides.

    Après confirmation, la session devient celle de l'utilisateur usurpé et une bannière ambre permanente affiche l'utilisateur effectif, l'administrateur réel et le bouton Stop impersonating. Tous les onglets du navigateur partagent l'usurpation, car le cookie de session est commun. La session de l'administrateur n'est pas perdue : Stop impersonating la restaure et revient à la page d'origine.

    Vous ne pouvez pas usurper un autre administrateur, un utilisateur désactivé, un compte sans connexion, vous-même ni enchaîner les usurpations. Si l'utilisateur cible ne remplit plus les conditions pendant la session (par exemple s'il devient administrateur), la console restaure automatiquement l'administrateur.

    Les actions effectuées pendant l'usurpation sont enregistrées dans l'audit avec l'administrateur réel et l'utilisateur usurpé, et les traces de l'utilisateur effectif portent le suffixe [Impersonated by <administrateur>]. Le début, la fin, la restauration automatique et les tentatives non autorisées sont enregistrés dans le journal d'audit. Si l'administrateur clique sur Logout pendant l'usurpation, l'usurpation s'arrête d'abord ; un second Logout ferme sa propre session.

    Types d'utilisateur¶

    Type Ce qu'il peut faire
    Utilisateur groupé (Grouped user) Accède, voit et modifie les informations des groupes qui lui sont attribués, selon son profil.
    Utilisateur groupé uniquement par entreprise Comme un utilisateur groupé, mais ne voit que les tickets des utilisateurs de sa même entreprise et de son groupe.
    Utilisateur indépendant (Standalone) Dans Tickets, il ne voit que les tickets qu'il a créés ou qui lui sont attribués. Sert au support des clients externes.
    Superadministrateur Accès et privilèges totaux sur toutes les sections et tous les groupes. A toujours la connexion active.

    Un superadministrateur peut être désactivé comme compte, mais sa connexion reste active. C'est une exception volontaire, pas un oubli.

    Administrateurs d'utilisateurs et licence¶

    Seuls les utilisateurs disposant du droit UM ou les superadministrateurs peuvent créer et supprimer des utilisateurs.

    Pandora ITSM tient un comptage spécial des administrateurs, car la licence limite leur nombre. Si le nombre est dépassé, la console bloque la connexion des administrateurs en trop ; les plus anciens gardent l'accès et les plus récents restent dehors. Ils apparaissent dans la liste avec la connexion désactivée.

    Pour libérer des places : désactivez ou supprimez des administrateurs, changez leur profil en profil standard ou étendez la licence. Le détail est en 1.4.

    Profils et permissions¶

    Les profils se gèrent dans People → Profile management. Chaque profil possède un nom, une abréviation de deux ou trois lettres et une série de bits d'accès.

    À la fin de la fiche utilisateur, on attribue la combinaison groupe et profil :

    Chaque section utilise les bits à sa manière : les tickets combinent groupe et profil ; les téléchargements utilisent des catégories ; le CRM utilise les entreprises et leur hiérarchie parent/enfant. Il n'existe pas de sens unique pour « avoir la permission » : il faut regarder la section.

    Projets¶

    Bit Ce qu'il permet
    PR · Voir projet Voir les projets auxquels l'utilisateur est affecté.
    PM · Modifier projet Créer et modifier les groupes de projets. Compte comme administrateur pour la licence.

    Le manager du projet peut agir sur ses projets et tâches, et les supprimer. Le propriétaire a les mêmes permissions que le manager. L'administrateur peut le faire sur n'importe quel projet. Les sous-tâches héritent des permissions de la tâche parente.

    Tickets¶

    Bit Ce qu'il permet
    IR · Voir tickets Voir les tickets dont l'utilisateur est créateur, éditeur ou auteur d'une unité de travail.
    IW · Modifier tickets Créer des tickets et modifier les existants. La modification est limitée au propriétaire du ticket.
    IM · Supprimer tickets Supprimer des tickets, gérer les types d'incident et les SLA. Compte comme administrateur.
    IC · Clôturer tickets Clôturer des tickets sans en être le propriétaire.

    Escalade et qualité¶

    Bit Ce qu'il permet
    SI · Escalader tickets Affecter des tickets à un groupe auquel l'utilisateur n'a pas accès.
    QA · Contrôle qualité Voir les rapports de qualité et les revues de tickets clôturés.

    Base de connaissances¶

    Bit Ce qu'il permet
    KR · Voir Voir les articles de la base de connaissances.
    KW · Modifier Créer et modifier des articles.
    KM · Gérer Supprimer des articles. Compte comme administrateur.

    Téléchargements et répertoires¶

    Bit Ce qu'il permet
    FRR · Voir dossiers Voir les répertoires et fichiers téléversés.
    FRW · Modifier dossiers Téléverser des fichiers, mettre à jour les existants et créer des répertoires.
    FRM · Gérer dossiers Supprimer des fichiers. Compte comme administrateur.

    Inventaire¶

    Bit Ce qu'il permet
    VR · Voir inventaire Voir les objets propres, publics, ceux de l'entreprise de l'utilisateur ou ceux qui lui sont spécifiquement attribués.
    VW · Modifier inventaire Créer et modifier les objets auxquels il a accès.
    VM · Gérer inventaire Supprimer des objets et gérer les types d'objet. Compte comme administrateur.

    Rapports¶

    Bit Ce qu'il permet
    RR · Voir rapports Voir les rapports et leurs données.
    RM · Gérer rapports Créer, modifier et supprimer des rapports, modèles et planifications.

    Wiki¶

    Bit Ce qu'il permet
    WR · Voir Voir le Wiki.
    WW · Modifier Créer et modifier des pages.
    WM · Gérer Modifier, supprimer et affecter des utilisateurs au Wiki. Compte comme administrateur.

    Les permissions de lecture et d'écriture par page se configurent dans le Wiki.

    CRM¶

    Le CRM ne fonctionne pas par groupes mais par entreprises et leur hiérarchie parent/enfant. Si un utilisateur a accès à une entreprise, il hérite de l'accès à ses entreprises filles, sauf l'utilisateur indépendant, qui ne voit que la sienne.

    Bit Ce qu'il permet
    CR · Voir CRM Voir les entreprises, contacts et opportunités auxquels il a accès.
    CW · Modifier CRM Créer et modifier les entreprises, contacts et opportunités accessibles.
    CM · Gérer CRM Modifier ou supprimer des entreprises et leur structure. Compte comme administrateur.
    CA · Admin CRM Administration avancée du CRM : formulaires, marketing et réglages du module.
    CIR · Voir factures Voir les factures des entreprises accessibles.
    CIW · Modifier factures Créer et modifier des factures.
    CIM · Gérer factures Supprimer des factures.
    DRR · Deal Registrations Voir et gérer les enregistrements d'opportunité (Deal Registrations).
    AR · Lire agenda Voir l'agenda propre et celui des autres selon la visibilité.
    AW · Modifier agenda Ajouter et modifier des éléments de l'agenda.
    AM · Gérer agenda Supprimer des éléments, y compris ceux de tiers visibles. Compte comme administrateur.

    Administration de Pandora ITSM¶

    Bit Ce qu'il permet
    UM · Gérer utilisateurs Créer, modifier et administrer les profils utilisateur. Compte comme administrateur.
    DM · Gestion base de données Accéder à la console de base de données et exécuter du SQL. Compte comme administrateur.
    FM · Gestion du framework Accéder à la configuration et aux options administratives. Compte comme administrateur.

    Ressources Humaines et ChatBot¶

    Bit Ce qu'il permet
    HR · Ressources Humaines Modifier ou supprimer les unités de travail des tâches spéciales : congés, arrêts, etc.
    CUW · Voir utilisateurs ChatBot Voir la liste des utilisateurs inclus dans le ChatBot.
    COW · Voir opérateurs ChatBot Voir la liste des opérateurs.
    COM · Gérer ChatBot Gérer les utilisateurs et opérateurs du ChatBot.

    Gestion des changements¶

    Bit Ce qu'il permet
    CHR · Lire changements Voir les changements des équipes auxquelles il appartient.
    CHW · Modifier changements Créer des demandes de changement et voir la configuration de Changes. Peut s'ajouter à l'équipe ou la quitter ; seul un superadmin ou un gestionnaire de changements peut le réintégrer.
    CHM · Gérer changements Voir tous les changements ouverts et fermés et modifier selon son rôle. Compte comme administrateur.

    Importation d'utilisateurs¶

    People → Import users from CSV permet de créer des utilisateurs en masse. Seuls les administrateurs y ont accès.

    Le groupe, le profil, le profil global et l'avatar sont choisis dans le formulaire de la console ; les valeurs du CSV pour ces champs sont ignorées. Si la politique de mots de passe est active, elle peut être appliquée aux utilisateurs importés.

    Colonnes du CSV, dans l'ordre :

    1. id_user
    2. password
    3. real_name
    4. email
    5. telephone
    6. description
    7. avatar
    8. disabled
    9. id_company
    10. num_employee
    11. enable_login
    12. Champs personnalisés, dans l'ordre où ils existent dans le système. Si vous ne voulez pas donner de valeur, laissez un espace vide.

    Champs utilisateur personnalisés¶

    People → User fields permet de créer vos propres champs : texte, zone de texte, sélecteur, champ lié ou case à cocher. Seul un administrateur peut les définir.

    • Show in list : le champ apparaît comme colonne dans la liste des utilisateurs.
    • Show in search : le champ apparaît dans le filtre utilisateurs. La recherche distingue les majuscules des minuscules.

    Gestion des groupes¶

    People → Groups Management n'est visible que pour les utilisateurs disposant de permissions de gestion des utilisateurs. Ils peuvent gérer leur groupe ou leurs groupes et voient toujours le groupe All, qui ne peut être ni modifié ni supprimé.

    Les tickets appartiennent toujours à un groupe. On peut définir un utilisateur par défaut pour les nouveaux tickets du groupe ; ensuite, l'utilisateur peut escalader les tickets dans son groupe s'il en a la permission.

    Champs du groupe :

    Champ Ce qu'il fait
    Forced email Active ou désactive l'envoi des tickets aux courriels du groupe.
    Parent Groupe parent.
    Default user Utilisateur attribué par défaut aux nouveaux tickets.
    Icon Image du groupe.
    Send customer satisfaction email Envoie une enquête de satisfaction à la clôture.
    Open ticket limit Maximum de tickets ouverts simultanés du groupe sur la dernière année ; pour les utilisateurs externes, par utilisateur.
    Enforced open tickets limit Empêche la création de tickets à la limite ; sinon, il avertit seulement.
    Total ticket limit Maximum de tickets du groupe sur la dernière année, ouverts ou fermés. Il est restrictif.
    Ticket SLA SLA appliqué aux tickets du groupe.
    Default inventory object Objet d'inventaire associé par défaut aux nouveaux tickets.
    Email from Adresse affichée comme origine de la notification.
    Group email Adresses qui reçoivent les avis de changement des tickets du groupe.

    Retirer un utilisateur d'un groupe supprime aussi le profil associé à ce groupe. S'il n'avait que ce profil, il reste sans droits suffisants.

    Files de courriel par groupe¶

    People → Group management → Email → Email origin configure les files de courriel qui créent des tickets. Cela nécessite un compte de courriel configuré dans la console.

    Pandora ITSM ne peut télécharger que depuis un seul compte POP3 ou IMAP ; on utilise donc des alias sur le serveur de courriel pour séparer les destinations. Selon l'adresse de destination, le ticket va dans un groupe ou un autre, et l'expéditeur peut être créé automatiquement.

    Teams¶

    People → Teams permet de créer des équipes de travail qui regroupent des utilisateurs de différents groupes pour Support, Changes ou CRM, sans dupliquer les comptes ni modifier leurs profils.

    Créer un Team demande deux champs :

    1. Name : nom de l'équipe ; les espaces sont autorisés. N'utilisez pas uniquement des espaces : il ne pourra pas être modifié et devra être supprimé.
    2. Manage : utilisateur qui administrera l'équipe.

    On peut ajouter une boîte aux lettres, de préférence celle du responsable, et une description.

    Par défaut, les trois options sont cochées : Support, Change et CRM. Chacune crée son propre équipe dans la fonctionnalité correspondante. Au moins une est recommandée.

    Supprimer un Team depuis cet écran supprime aussi les équipes associées dans les fonctionnalités. C'est irréversible.

    Avec Add users +, vous filtrez les utilisateurs activés par groupe ou entreprise et les ajoutez au Team. L'option All ajoute tous les utilisateurs filtrés, ou tous les utilisateurs activés s'il n'y a pas de filtre.

    Un utilisateur désactivé dans la gestion des utilisateurs ne pourra pas travailler sur les tâches du Team même s'il reste dans la liste. Pour Support, il a besoin d'un des bits IR, IW, IM, IC, SI ; pour Changes, CHR, CHW, CHM ; pour CRM, les bits CR, CW, CM, CA ou DRR et le niveau adéquat dans les entreprises, factures et agenda.

    Bonnes pratiques¶

    • Créez un groupe par service, client ou entreprise ; ne mélangez pas tout dans All.
    • Accordez le profil minimum qui permet de travailler ; l'étendre ensuite est facile.
    • Vérifiez Manager Count avant de créer un administrateur (1.4).
    • Désactivez les comptes des personnes qui partent ; un compte désactivé libère une place.
    • Ne partagez pas admin et ne donnez pas UM à quelqu'un qui a seulement besoin de consulter.
    • Revoyez les profils après un changement d'organisation.
    • Utilisez les Teams pour le travail transversal, pas pour dupliquer des utilisateurs.
    • Documentez quel profil possède chaque groupe ; le prochain administrateur vous remerciera.

    Integración con Pandora RC¶

    Pandora RC no es un escritorio remoto más: es un sistema de gestión remota en la nube. El agente se conecta hacia el portal, no al revés, así que el equipo puede cambiar de IP, quedarse detrás de un cortafuegos o pasar por una red doméstica sin que la sesión deje de funcionar. Pandora ITSM se limita a abrir la puerta desde el objeto de inventario.

    La integración tiene dos partes: configurar las credenciales del portal y preparar el objeto de inventario que apunta al agente. Si falta cualquiera de las dos, la pestaña de acceso remoto no aparece o falla al conectar.

    Qué es¶

    Pandora RC es un servicio SaaS de gestión remota de equipos. Cada dispositivo tiene un agente instalado y un identificador; la consola de Pandora ITSM usa ese identificador para pedir un token y abrir una sesión dentro de una pestaña del inventario.

    La sesión se presenta en un iframe con estas vistas:

    Pestaña Para qué sirve
    Information Resumen del agente y estado de la conexión.
    Terminal Terminal remota.
    Display Escritorio remoto.
    Processes Procesos del equipo.
    Services Servicios del sistema.
    Files Explorador de ficheros.

    Las pestañas solo funcionan si el agente de Pandora RC tiene habilitados los módulos correspondientes. La integración no los activa por su cuenta.

    Configuración¶

    El punto de entrada es Setup → Setup → Pandora RC. Solo pueden entrar administradores o perfiles con permiso FM; la integración no está disponible en instalaciones SaaS.

    El formulario tiene dos bloques que se guardan por separado:

    1. Enable Pandora RC: marca Yes y pulsa el botón Update gris de esa misma fila. Ese botón guarda únicamente la habilitación.
    2. Pandora RC API: rellena usuario, contraseña, hostname, puerto y timeout, y guarda con el botón Update verde de la esquina inferior derecha.

    Si guardas las credenciales sin haber habilitado la integración, el formulario de credenciales ni siquiera se muestra. Primero se habilita; después se configura.

    Los campos de la API son:

    Campo Valor por defecto Qué espera
    User Vacío Usuario de Pandora RC.
    Password Vacío Contraseña del usuario.
    API Hostname portal.ehorus.com Host del portal, sin protocolo y sin puerto.
    API Port 443 Puerto HTTPS del portal.
    Request timeout 30 Segundos máximos de espera; 0 desactiva el límite.

    Los valores se guardan en la configuración con los tokens ehorus_enabled, ehorus_hostname, ehorus_port, ehorus_req_timeout, ehorus_user y ehorus_pass. La contraseña queda almacenada en la configuración; no se muestra en claro fuera del formulario.

    Al habilitar la integración por primera vez se crea el campo global PandoraRCID para los tipos de objeto de Pandora FMS y se migran los valores antiguos de eHorus Id. En instalaciones que vienen de versiones anteriores es normal seguir viendo el rótulo eHorus Id; el valor se conserva y termina en el campo nuevo.

    Probar la conexión¶

    El botón Test (etiqueta Start) prueba los valores que hay en el formulario, sin necesidad de guardarlos. Lanza una petición al portal y muestra un icono de éxito o de fallo con uno de estos mensajes:

    Mensaje Qué significa
    Empty user or password Falta el usuario o la contraseña.
    User not found El portal no reconoce el usuario.
    Invalid password La contraseña no es correcta.
    Connection timeout El portal no responde dentro del timeout.

    Una prueba correcta no guarda nada: después hay que pulsar el Update verde. Si la prueba falla, revisa hostname, puerto, credenciales y salida de red antes de tocar el resto de la integración.

    Preparar el objeto de inventario¶

    Antes de conectar, el servidor Apache de Pandora ITSM debe permitir que la consola se incruste en un iframe del mismo origen:

    Header always set X-Frame-Options "SAMEORIGIN"

    Sin esa cabecera, el navegador puede bloquear el iframe y la sesión remota se queda en blanco.

    El objeto de inventario debe tener un valor en el campo PandoraRCID —o en el eHorus Id heredado—. Ese valor es el identificador del agente de Pandora RC.

    1. Entra en Inventory → Create new object, pon un nombre y pulsa Create.
    2. En el enlace Click here to continue working with Object #XXX, abre el objeto recién creado.
    3. En Object type, elige Computer o Pandora agents, según el tipo que corresponda al equipo.
    4. En Custom fields, rellena PandoraRCID con el identificador del agente. En instalaciones antiguas el campo aparece como eHorus Id.
    5. Pulsa Update changes para guardar.

    El campo es global para los tipos de objeto de Pandora FMS. Si no aparece, comprueba que la integración esté habilitada y que el tipo de objeto sea uno de los que reciben el campo; en una instalación antigua puede seguir mostrándose con el nombre eHorus Id.

    Conexión remota¶

    Con el objeto preparado, abre su ficha de inventario. Si la integración está habilitada y el campo tiene valor, aparece la pestaña Pandora RC con el icono del producto.

    Al entrar, la consola muestra Remote management of this device with Pandora RC y el botón Launch. Al pulsarlo, Pandora ITSM pide un token al portal, carga el iframe y muestra las pestañas de la sesión. Si el agente tiene contraseña, la propia sesión la pedirá al conectar; tenla a mano.

    El token de la sesión caduca. Cuando eso ocurre, el iframe se retira y aparece el aviso The connection was lost and the authorization token was expired. Reload the page to request a new authorization token. Recarga la ficha para pedir uno nuevo.

    Requisitos y problemas frecuentes¶

    • El servidor de Pandora ITSM debe poder alcanzar https://<hostname>:<puerto> del portal. El puerto habitual es 443.
    • El certificado del portal debe ser válido: la comprobación TLS no se desactiva.
    • La integración exige administrador o permiso FM, y no está disponible en SaaS.
    • El agente debe tener habilitados los módulos de terminal, escritorio, procesos, servicios o ficheros que quieras usar.
    Síntoma Causa probable Qué hacer
    Pandora RC is not enabled La integración está deshabilitada. Actívala en Setup → Setup → Pandora RC.
    Missing eHorus Id El objeto no tiene identificador de agente. Rellena PandoraRCID o eHorus Id y guarda.
    There was an error retrieving an authorization token Credenciales, host, puerto o TLS incorrectos. Usa Test y revisa la salida de red.
    There was an error retrieving the agent token El identificador no existe o el usuario no tiene acceso al agente. Revisa el valor del campo y los permisos en Pandora RC.
    There was an error retrieving the agent data El agente no responde o el portal no lo devuelve. Comprueba que el agente esté conectado.
    El iframe se queda en blanco Falta X-Frame-Options: SAMEORIGIN o el navegador lo bloquea. Añade la cabecera en Apache y recarga.
    The connection was lost and the authorization token was expired El token de sesión caducó. Recarga la ficha del objeto.
    Connection timeout El portal no responde en el tiempo configurado. Sube el timeout o revisa la conectividad.

    La integración no guarda la sesión remota en Pandora ITSM: el token es efímero y la conversación real ocurre entre el navegador y el agente de Pandora RC. Si el acceso falla, el problema suele estar en la red, el certificado o el agente, no en el objeto de inventario.

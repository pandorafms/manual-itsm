    Configuración avanzada¶

    La configuración avanzada es donde Pandora ITSM deja de ser un producto recién instalado y se convierte en el sistema de la organización. Aquí se deciden el idioma, las URL, el correo, la autenticación, la visibilidad de menús y los valores que afectan a tickets, proyectos y CRM. Casi todo tiene un valor por defecto sensato; el problema empieza cuando alguien lo cambia sin saber qué depende de él.

    Dónde está la configuración¶

    Casi todo vive en Setup → Setup. Cada bloque tiene su propia pantalla y sus propios tokens. Después de modificar valores hay que pulsar Update para guardarlos en la base de datos. Un cambio sin guardar es una buena intención.

    Muchas secciones exigen ser superadministrador o tener un bit concreto del perfil. Si un ajuste no aparece, no es un fallo de la interfaz: probablemente falta permiso.

    Configuración general¶

    En Setup → Setup → General setup se concentran los parámetros globales:

    Campo Qué controla
    Language Idioma global; el idioma del usuario prevalece.
    Site name Nombre visible en títulos y asuntos.
    Enable error log Registro de errores en pandora_itsm.log.
    Timezone for Pandora ITSM Huso horario; por defecto Europe/Madrid.
    List of IP with access to API IPs con acceso a la API, separadas por comas; * permite cualquiera.
    Default admin user Superadministrador para tareas periódicas.
    API password Contraseña para peticiones a la API.
    First day of the week Primer día de calendarios; lunes por defecto.
    Welcome view Periodo de la pantalla de bienvenida; 21 días por defecto.
    Login hash password Clave para generar una URL única de preautenticación.
    Enable HTTPS access Fuerza HTTPS.
    Use SSL certificate y Path of SSL certificate Certificado y ruta; por defecto /etc/ssl/certs/pandoraitsm.pem.
    Access port Puerto de acceso; 80 por defecto.
    Public access to server URL pública; debe incluir el sufijo /pandoraitsm.
    CSV encoding type y Separator data in CSV Codificación y separador de CSV.
    Chromium path Ruta del navegador para generar informes.
    Maximum direct download size (MB) Tamaño máximo de descarga.
    Max. upload file size (MB) Tamaño máximo de subida; también depende de PHP.
    Max. Upload file size in CRM / incidents Límites específicos de CRM y tickets.
    Temporary directory for PDF files Directorio temporal para PDF; /tmp/ por defecto.
    Hide version Oculta la versión en pie y login.
    Show modal last time logged Muestra el último acceso al usuario.
    Active automatic time tracking stop Para el fichaje automáticamente al llegar a Stop time tracking after (8,5 horas por defecto).

    Si activas HTTPS, revisa el certificado y la cadena de confianza. PHP puede necesitar openssl.cafile en php.ini.

    Public access to server es peligroso si se configura mal: la consola puede quedar inaccesible. La salida de emergencia es corregir el token en la base de datos:

    UPDATE tconfig SET value='http://URL/pandoraitsm' WHERE token='access_public';

    Configuración visual¶

    En Setup → Setup → Visual setup se ajusta la apariencia:

    • Theme: tema global y por usuario; Default (Light) por defecto.
    • Favicon: icono de la pestaña.
    • Block size for pagination: elementos por página; valores bajos evitan problemas de rendimiento.
    • Global dashboard (welcome message): dashboard de bienvenida.
    • Font for ITSM: fuente de interfaz y PDF.
    • Tabs menu: pestañas, menú desplegable o ambos.
    • Global search limit: número de resultados por área.

    La búsqueda global busca en tickets abiertos, proyectos, personas, contactos, contratos, empresas, facturas, leads y Wiki. Cada usuario ve solo lo que su ACL le permite. Los logotipos y favicons personalizados se guardan en images/custom_logos y images/favicon.

    Política de contraseñas¶

    En Setup → Setup → Password policy setup. La política no se aplica a los superadministradores. El interruptor Enable password policy manda: si está desactivado, el resto de opciones no hacen nada.

    Campos principales: longitud mínima (5 por defecto), números, símbolos, caducidad en días (0 = nunca), cambio obligatorio en el primer acceso, minutos de bloqueo (5 por defecto) y número de intentos fallidos. La generación automática de contraseñas también respeta la política cuando está activa. El detalle de autenticación está en 2.2 Autenticación y seguridad.

    Configuración de incidencias¶

    En Setup → Setup → Issue setup se agrupan los ajustes de tickets:

    • Ticket submission settings: modo Manual, Simplified o Smart.
    • Visual options: mostrar creador/propietario, límite de tickets por búsqueda (300 por defecto), edición rápida, formato de fecha, fecha de realización de unidades de trabajo y orden de comentarios.
    • Ticket behaviour: valoración, cambio de creador/propietario, unidad de trabajo automática al crear, cambio de tipo, tipo obligatorio, usuarios externos, autoasignación y validación del cliente antes del cierre.
    • Work unit options (WU): cierre automático (45 días por defecto), tiempo por defecto (0,25 h), correo al gestionar unidades de trabajo, unidades internas por defecto y comentarios públicos.
    • Workflows: comprobar tickets cerrados y días a revisar (15 por defecto).
    • Email sending options: qué cambios generan correo, agrupación de notificaciones, adjuntos, unidades internas y avisos al creador de la unidad de trabajo.
    • Customization: estados, resoluciones, prioridades y días especiales.
    • Default custom columns: columnas del listado de tickets.
    • Survey Questions: encuesta cuando la valoración es negativa.

    El detalle funcional está en 3.1 Tickets e incidencias, 3.2 Flujo de trabajo y estados y 3.3 SLA, escalado y calidad.

    Configuración de cambios¶

    En Setup → Setup → Changes setup se ajustan las notificaciones y el comportamiento de los cambios. La lógica del módulo está en 5.1 Gestión del cambio.

    Correo y plantillas¶

    En Setup → Setup → Email setup se configura el envío (SMTP) y la recepción (POP/IMAP):

    • Notification period: mínimo entre avisos de SLA (24 horas por defecto).
    • System email from address: remitente del sistema.
    • SMTP Host, Port, User, Password y cifrado.
    • OAuth 2.0 para Microsoft 365, con Client ID, Tenant ID y Secret.
    • SMTP queue retries, Max. pending emails y Max. emails sent per execution.
    • POP/IMAP Host, Port, User, Password, protocolo y Message delimiter.
    • Accept any certificate desactivado por defecto; no lo actives salvo caso extremo.

    La recepción solo es necesaria si se crean o actualizan tickets por correo. Los detalles, proveedores y OAuth están en 3.4 Correo y soporte.

    En Email templates setup se editan las plantillas .tpl y los asuntos. Las plantillas predeterminadas se pueden duplicar y convertir en predeterminadas. Las macros cubren ticket, cambio, tarea de cambio y unidad de trabajo; el listado completo está en la configuración de plantillas y en 3.4.

    En Email queue control se ven los correos pendientes, los intentos y el estado. Se pueden reactivar o borrar en masa.

    Visibilidad de menús¶

    En Setup → Setup → Visibility management se ocultan secciones por grupo:

    • Oculto: no se muestra, ni siquiera por URL directa.
    • Completo: acceso completo.

    Si no hay configuración, el acceso es completo. Cada sección se cruza con un bit del perfil: proyectos PR, tickets IR, inventario VR, base de conocimiento KR, file releases KR, agenda AR, work orders WOR, personas y configuración cualquier perfil. El superadministrador siempre ve todo. Si un usuario tiene varios grupos, se aplica la visibilidad menos restrictiva. Crear una regla para All sustituye las anteriores de esa sección.

    Inventario de Pandora FMS¶

    En Setup → Setup → Pandora FMS inventory se controla el inventario y la recepción remota:

    • Duplicate inventory name: permite nombres repetidos.
    • CSV compatibility import: controla el formato de importación/exportación.
    • Default owner, Associated company y Associated user para el inventario remoto.

    El inventario se documenta en 4.1 Inventario.

    Autenticación¶

    En Setup → Setup → Authentication configuration se elige local, Active Directory, LDAP o Pandora FMS. Los superadministradores siempre se autentican localmente. Session timeout (secs) define la duración de la sesión (9000 segundos por defecto). La autenticación en dos pasos y el resto de detalles están en 2.2 Autenticación y seguridad.

    Configuración CRM¶

    En Setup → Setup → CRM setup se ajustan cuatro bloques:

    Facturas¶

    • Enable auto ID y Invoice ID pattern: patrón por defecto 21/[1000]; la parte variable va entre corchetes y solo se aplica a facturas Submitted.
    • Invoice header logo: logo en images/custom_logo.
    • Cabecera, impuestos, métodos de pago y pie.

    Contratos¶

    Contract Statuses permite editar, borrar y añadir estados de contrato.

    Campañas¶

    • Email batch campaigns: correos por bloque (500 por defecto).
    • Web tracking JavaScript: código de seguimiento.
    • Captcha: Cloudflare, con clave de sitio.

    Deals¶

    • Default pipeline deal.
    • Time since last update (days): ofertas obsoletas.
    • Schedule reminder repeat hours: 24 por defecto.
    • Days to expire schedule: 7 por defecto.
    • Notification email (Deal Registrations).

    El detalle de CRM está en 8.1–8.7.

    Mantenimiento de datos antiguos¶

    En Setup → Setup → Old data maintenance se decide cuánto se conserva. 0 significa conservar siempre. Valores por defecto:

    Dato Días
    Eventos 30
    Tickets cerrados 0
    Unidades de trabajo 0
    Partes de trabajo 0
    Auditoría 15
    Sesiones 7
    Eventos de workflow 900
    Adjuntos de tickets 0
    Seguimiento de archivos 30
    Copias de seguridad 30
    Correos no válidos 30
    Informes 365
    Salas de chatbot archivadas 365

    Reset all data borra todos los datos y adjuntos. No es una limpieza: es empezar de cero.

    Gestión de proyectos¶

    En Setup → Setup → Project management se ajustan los valores por defecto:

    • Usuarios sin autocompletado de unidades de trabajo.
    • Horas de trabajo por día (8).
    • Autocompletado de unidades de trabajo en días (0).
    • Tiempo por defecto para unidad simple (4 h) y múltiple (4 h).
    • Moneda (€).
    • Días de vacaciones (22).
    • Deshabilitar la adición de tickets y unidades de trabajo a tareas pendientes o verificadas.
    • Usuario que recibe las notificaciones de solicitud de vacaciones.
    • Aviso de unidades de trabajo semanales (40 h).

    El detalle está en 6.1 Proyectos y tareas y 7.1 Gestión del tiempo.

    Integraciones¶

    • Pandora RC: activa la integración de gestión remota.
    • ChatBot: servidor y canales.
    • GitLab: token de acceso para consultar tickets de un proyecto en modo lectura.

    Los capítulos de integración están en la Parte 11.

    Herramientas de administración¶

    • File manager: sube y organiza ficheros en attachment, attachment/downloads, images e images/custom_logos.
    • Diagnostic info: versión, PHP, base de datos, sistema, rendimiento, logs, adjuntos y fecha del servidor.
    • News board: noticias globales por grupo y con caducidad; admite _lastlogin_.
    • DB Manager: consola SQL para superadministradores o perfil DM; su mal uso es irreversible.
    • Links: enlaces externos o internos del menú; los internos usan rutas como wiki/operation/wiki/wiki.
    • System events: histórico de cron, informes programados y fallos.
    • Audit log: acciones de usuario, búsqueda por texto y fecha, exportación CSV.
    • Error log: pandora_itsm.log, con opción de borrar.
    • Translate strings: traducciones personalizadas sobre el inglés original.
    • Console extensions: registro, instalación y activación de extensiones de consola; el detalle está en 12.3 Extensiones de consola.

    Buenas prácticas¶

    • Cambia un bloque cada vez y pulsa Update.
    • Prueba los cambios en un entorno de pruebas antes de producción.
    • Documenta quién cambió cada opción y por qué.
    • Revisa HTTPS, correo y autenticación después de cualquier cambio de infraestructura.
    • Haz copia de seguridad antes de tocar datos antiguos o el gestor de base de datos.
    • No uses Reset all data como herramienta de limpieza.

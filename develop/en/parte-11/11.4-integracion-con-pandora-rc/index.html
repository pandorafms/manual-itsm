    Pandora RC integration¶

    Pandora RC is not just another remote desktop: it is a cloud-based remote management system. The agent connects out to the portal, not the other way around, so the device can change IP address, sit behind a firewall or use a home network without breaking the session. Pandora ITSM only opens the door from the inventory object.

    The integration has two parts: configuring the portal credentials and preparing the inventory object that points to the agent. If either is missing, the remote access tab does not appear or the connection fails.

    What it is¶

    Pandora RC is a SaaS remote device management service. Each device has an installed agent and an identifier; the Pandora ITSM console uses that identifier to request a token and open a session inside an inventory tab.

    The session is shown in an iframe with these views:

    Tab What it is for
    Information Agent summary and connection status.
    Terminal Remote terminal.
    Display Remote desktop.
    Processes Device processes.
    Services System services.
    Files File browser.

    The tabs only work if the Pandora RC agent has the corresponding modules enabled. The integration does not enable them on its own.

    Configuration¶

    The entry point is Setup → Setup → Pandora RC. Only administrators or profiles with FM permission can enter; the integration is not available in SaaS installations.

    The form has two blocks that are saved separately:

    1. Enable Pandora RC: select Yes and click the grey Update button in that row. That button saves only the enablement.
    2. Pandora RC API: fill in user, password, hostname, port and timeout, then save with the green Update button at the bottom right.

    If you save credentials before enabling the integration, the credentials form is not shown at all. Enable it first, then configure it.

    The API fields are:

    Field Default What it expects
    User Empty Pandora RC user.
    Password Empty User password.
    API Hostname portal.ehorus.com Portal host, without protocol or port.
    API Port 443 Portal HTTPS port.
    Request timeout 30 Maximum wait in seconds; 0 disables the limit.

    The values are stored in the configuration with the ehorus_enabled, ehorus_hostname, ehorus_port, ehorus_req_timeout, ehorus_user and ehorus_pass tokens. The password is stored in the configuration; it is not shown in clear text outside the form.

    Enabling the integration for the first time creates the global PandoraRCID field for Pandora FMS object types and migrates old eHorus Id values. On installations upgraded from older versions it is normal to still see the eHorus Id label; the value is preserved and ends up in the new field.

    Testing the connection¶

    The Test button (labelled Start) tests the values currently in the form, without saving them. It sends a request to the portal and shows a success or failure icon with one of these messages:

    Message What it means
    Empty user or password The user or password is missing.
    User not found The portal does not recognise the user.
    Invalid password The password is wrong.
    Connection timeout The portal does not answer within the timeout.

    A successful test saves nothing: click the green Update afterwards. If the test fails, check hostname, port, credentials and network access before touching the rest of the integration.

    Preparing the inventory object¶

    Before connecting, the Pandora ITSM Apache server must allow the console to be embedded in a same-origin iframe:

    Header always set X-Frame-Options "SAMEORIGIN"

    Without that header, the browser may block the iframe and the remote session stays blank.

    The inventory object must have a value in the PandoraRCID field — or in the legacy eHorus Id —. That value is the Pandora RC agent identifier.

    1. Go to Inventory → Create new object, enter a name and click Create.
    2. Open the Click here to continue working with Object #XXX link to open the newly created object.
    3. In Object type, choose Computer or Pandora agents, depending on the device type.
    4. In Custom fields, fill in PandoraRCID with the agent identifier. On older installations the field appears as eHorus Id.
    5. Click Update changes to save it.

    The field is global for Pandora FMS object types. If it does not appear, check that the integration is enabled and that the object type is one of those that receive the field; on an older installation it may still be displayed with the eHorus Id name.

    Remote connection¶

    With the object ready, open its inventory page. If the integration is enabled and the field has a value, the Pandora RC tab appears with the product icon.

    On entering, the console shows Remote management of this device with Pandora RC and the Launch button. When you click it, Pandora ITSM requests a token from the portal, loads the iframe and shows the session tabs. If the agent has a password, the session itself asks for it when connecting; keep it at hand.

    The session token expires. When that happens, the iframe is removed and the message The connection was lost and the authorization token was expired. Reload the page to request a new authorization token. appears. Reload the page to request a new one.

    Requirements and common problems¶

    • The Pandora ITSM server must be able to reach https://<hostname>:<port> on the portal. The usual port is 443.
    • The portal certificate must be valid: TLS verification is not disabled.
    • The integration requires administrator or FM permission and is not available in SaaS.
    • The agent must have the terminal, desktop, processes, services or files modules enabled for the tabs you want to use.
    Symptom Likely cause What to do
    Pandora RC is not enabled The integration is disabled. Enable it in Setup → Setup → Pandora RC.
    Missing eHorus Id The object has no agent identifier. Fill in PandoraRCID or eHorus Id and save.
    There was an error retrieving an authorization token Wrong credentials, host, port or TLS. Use Test and check network access.
    There was an error retrieving the agent token The identifier does not exist or the user cannot access the agent. Check the field value and Pandora RC permissions.
    There was an error retrieving the agent data The agent does not answer or the portal does not return it. Check that the agent is connected.
    The iframe stays blank X-Frame-Options: SAMEORIGIN is missing or the browser blocks it. Add the header in Apache and reload.
    The connection was lost and the authorization token was expired The session token expired. Reload the object page.
    Connection timeout The portal does not answer within the configured time. Increase the timeout or check connectivity.

    The integration does not store the remote session in Pandora ITSM: the token is ephemeral and the real conversation happens between the browser and the Pandora RC agent. If access fails, the problem is usually the network, the certificate or the agent, not the inventory object.

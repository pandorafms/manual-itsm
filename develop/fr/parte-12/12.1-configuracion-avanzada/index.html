    Configuration avancée¶

    La configuration avancée est le moment où Pandora ITSM cesse d'être un produit fraîchement installé pour devenir le système de l'organisation. On y décide la langue, les URL, le courriel, l'authentification, la visibilité des menus et les valeurs qui affectent les tickets, les projets et le CRM. La plupart des réglages ont une valeur par défaut sensée ; le problème commence quand quelqu'un en change un sans savoir ce qui en dépend.

    Où se trouve la configuration¶

    L'essentiel se trouve dans Setup → Setup. Chaque bloc a son écran et ses tokens. Après modification, cliquez sur Update pour enregistrer en base. Un changement non enregistré est une bonne intention.

    De nombreuses sections exigent un superadministrateur ou un bit de profil précis. Si un réglage n'apparaît pas, ce n'est pas un bug de l'interface : il manque probablement une permission.

    Configuration générale¶

    Setup → Setup → General setup regroupe les paramètres globaux :

    Champ Ce qu'il contrôle
    Language Langue globale ; celle de l'utilisateur prévaut.
    Site name Nom affiché dans les titres et les sujets.
    Enable error log Journal d'erreurs dans pandora_itsm.log.
    Timezone for Pandora ITSM Fuseau horaire ; Europe/Madrid par défaut.
    List of IP with access to API IP autorisées pour l'API, séparées par des virgules ; * autorise tout le monde.
    Default admin user Superadministrateur pour les tâches périodiques.
    API password Mot de passe des requêtes API.
    First day of the week Premier jour des calendriers ; lundi par défaut.
    Welcome view Période de l'écran d'accueil ; 21 jours par défaut.
    Login hash password Clé pour une URL unique de pré-authentification.
    Enable HTTPS access Force HTTPS.
    Use SSL certificate et Path of SSL certificate Certificat et chemin ; /etc/ssl/certs/pandoraitsm.pem par défaut.
    Access port Port d'accès ; 80 par défaut.
    Public access to server URL publique ; doit inclure le suffixe /pandoraitsm.
    CSV encoding type et Separator data in CSV Encodage et séparateur CSV.
    Chromium path Chemin du navigateur pour les rapports.
    Maximum direct download size (MB) Taille maximale de téléchargement.
    Max. upload file size (MB) Taille maximale d'envoi ; PHP s'applique aussi.
    Max. Upload file size in CRM / incidents Limites spécifiques CRM et tickets.
    Temporary directory for PDF files Répertoire temporaire PDF ; /tmp/ par défaut.
    Hide version Masque la version dans le pied de page et le login.
    Show modal last time logged Affiche la dernière connexion.
    Active automatic time tracking stop Arrête le pointage à Stop time tracking after (8,5 heures par défaut).

    Si vous activez HTTPS, vérifiez le certificat et la chaîne de confiance. PHP peut avoir besoin de openssl.cafile dans php.ini.

    Public access to server est dangereux mal configuré : la console peut devenir inaccessible. La sortie de secours est de corriger le token en base :

    UPDATE tconfig SET value='http://URL/pandoraitsm' WHERE token='access_public';

    Configuration visuelle¶

    Setup → Setup → Visual setup contrôle l'apparence :

    • Theme : thème global et par utilisateur ; Default (Light) par défaut.
    • Favicon : icône de l'onglet.
    • Block size for pagination : éléments par page ; des valeurs basses évitent les problèmes de performance.
    • Global dashboard (welcome message) : tableau de bord d'accueil.
    • Font for ITSM : police de l'interface et des PDF.
    • Tabs menu : onglets, menu déroulant ou les deux.
    • Global search limit : résultats par zone.

    La recherche globale couvre les tickets ouverts, projets, personnes, contacts, contrats, entreprises, factures, leads et Wiki. Chaque utilisateur ne voit que ce que son ACL autorise. Les logos et favicons personnalisés vivent dans images/custom_logos et images/favicon.

    Politique de mots de passe¶

    Setup → Setup → Password policy setup. La politique ne s'applique pas aux superadministrateurs. Enable password policy est l'interrupteur principal : s'il est désactivé, les autres options ne font rien.

    Champs principaux : longueur minimale (5 par défaut), chiffres, symboles, expiration en jours (0 = jamais), changement obligatoire à la première connexion, minutes de blocage (5 par défaut) et tentatives échouées. La génération automatique suit aussi la politique si elle est active. Les détails d'authentification sont dans 2.2 Authentification et sécurité.

    Configuration des incidents¶

    Setup → Setup → Issue setup regroupe les réglages des tickets :

    • Ticket submission settings : Manual, Simplified ou Smart.
    • Visual options : afficher créateur/propriétaire, limite de recherche (300 par défaut), édition rapide, format de date, date de réalisation des unités de travail et ordre des commentaires.
    • Ticket behaviour : évaluation, changement de créateur/propriétaire, unité de travail automatique à la création, changement de type, type obligatoire, utilisateurs externes, auto-affectation et validation client avant clôture.
    • Work unit options (WU) : clôture automatique (45 jours par défaut), temps par défaut (0,25 h), courriel lors de la gestion, unités internes par défaut et commentaires publics.
    • Workflows : vérifier les tickets fermés et nombre de jours (15 par défaut).
    • Email sending options : quels changements envoient un courriel, regroupement, pièces jointes, unités internes et avis au créateur de l'unité.
    • Customization : états, résolutions, priorités et jours spéciaux.
    • Default custom columns : colonnes de la liste des tickets.
    • Survey Questions : enquête lorsque l'évaluation est négative.

    Les détails fonctionnels sont dans 3.1 Tickets et incidents, 3.2 Flux de travail et états et 3.3 SLA, escalade et qualité.

    Configuration des changements¶

    Setup → Setup → Changes setup ajuste les notifications et le comportement des changements. La logique du module est dans 5.1 Gestion du changement.

    Courriel et modèles¶

    Setup → Setup → Email setup configure l'envoi (SMTP) et la réception (POP/IMAP) :

    • Notification period : minimum entre avis SLA (24 heures par défaut).
    • System email from address : expéditeur système.
    • SMTP Host, Port, User, Password et chiffrement.
    • OAuth 2.0 pour Microsoft 365, avec Client ID, Tenant ID et Secret.
    • SMTP queue retries, Max. pending emails et Max. emails sent per execution.
    • POP/IMAP Host, Port, User, Password, protocole et Message delimiter.
    • Accept any certificate désactivé par défaut ; ne l'activez qu'en cas extrême.

    La réception n'est nécessaire que si des tickets sont créés ou mis à jour par courriel. Les détails, fournisseurs et OAuth sont dans 3.4 Courriel et support.

    Email templates setup modifie les fichiers .tpl et les sujets. Les modèles par défaut peuvent être dupliqués et rendus par défaut. Les macros couvrent tickets, changements, tâches de changement et unités de travail ; la liste complète est dans la configuration des modèles et en 3.4.

    Email queue control affiche les courriels en attente, les tentatives et l'état. Ils peuvent être réactivés ou supprimés en masse.

    Visibilité des menus¶

    Setup → Setup → Visibility management masque des sections par groupe :

    • Hidden : non affichée, même par URL directe.
    • Full : accès complet.

    Sans configuration, l'accès est complet. Chaque section est comparée à un bit de profil : projets PR, tickets IR, inventaire VR, base de connaissance KR, file releases KR, agenda AR, work orders WOR, personnes et configuration tout profil. Le superadministrateur voit toujours tout. Si un utilisateur a plusieurs groupes, la visibilité la moins restrictive s'applique. Une règle All remplace les précédentes pour cette section.

    Inventaire Pandora FMS¶

    Setup → Setup → Pandora FMS inventory contrôle l'inventaire et la réception distante :

    • Duplicate inventory name : autorise les noms répétés.
    • CSV compatibility import : format d'import/export.
    • Default owner, Associated company et Associated user pour l'inventaire distant.

    L'inventaire est documenté dans 4.1 Inventaire.

    Authentification¶

    Setup → Setup → Authentication configuration choisit local, Active Directory, LDAP ou Pandora FMS. Les superadministrateurs s'authentifient toujours localement. Session timeout (secs) définit la durée de session (9000 secondes par défaut). L'authentification à deux facteurs et le reste des détails sont dans 2.2 Authentification et sécurité.

    Configuration CRM¶

    Setup → Setup → CRM setup contient quatre blocs :

    Factures¶

    • Enable auto ID et Invoice ID pattern : 21/[1000] par défaut ; la partie variable est entre crochets et ne s'applique qu'aux factures Submitted.
    • Invoice header logo : logo dans images/custom_logo.
    • En-tête, taxes, moyens de paiement et pied de page.

    Contrats¶

    Contract Statuses permet de modifier, supprimer et ajouter des états de contrat.

    Campagnes¶

    • Email batch campaigns : courriels par bloc (500 par défaut).
    • Web tracking JavaScript : code de suivi.
    • Captcha : Cloudflare, avec clé de site.

    Deals¶

    • Default pipeline deal.
    • Time since last update (days) : opportunités obsolètes.
    • Schedule reminder repeat hours : 24 par défaut.
    • Days to expire schedule : 7 par défaut.
    • Notification email (Deal Registrations).

    Les détails CRM sont dans 8.1–8.7.

    Maintenance des anciennes données¶

    Setup → Setup → Old data maintenance décide de la conservation. 0 signifie conserver toujours. Valeurs par défaut :

    Donnée Jours
    Événements 30
    Tickets fermés 0
    Unités de travail 0
    Ordres de travail 0
    Audit 15
    Sessions 7
    Événements de workflow 900
    Pièces jointes des tickets 0
    Suivi des fichiers 30
    Sauvegardes 30
    Courriels invalides 30
    Rapports 365
    Salles de chatbot archivées 365

    Reset all data supprime toutes les données et pièces jointes. Ce n'est pas du nettoyage : c'est repartir de zéro.

    Gestion de projets¶

    Setup → Setup → Project management définit les valeurs par défaut :

    • Utilisateurs sans autocomplétion des unités de travail.
    • Heures de travail par jour (8).
    • Autocomplétion des unités de travail en jours (0).
    • Temps par défaut des unités simples (4 h) et multiples (4 h).
    • Devise (€).
    • Jours de congés (22).
    • Désactiver l'ajout de tickets et d'unités de travail aux tâches en attente ou vérifiées.
    • Utilisateur qui reçoit les notifications de demande de congés.
    • Avis hebdomadaire des unités de travail (40 h).

    Les détails sont dans 6.1 Projets et tâches et 7.1 Gestion du temps.

    Intégrations¶

    • Pandora RC : active la gestion distante.
    • ChatBot : serveur et canaux.
    • GitLab : jeton d'accès pour lire les tickets d'un projet.

    Les chapitres d'intégration sont dans la Partie 11.

    Outils d'administration¶

    • File manager : envoie et organise les fichiers dans attachment, attachment/downloads, images et images/custom_logos.
    • Diagnostic info : version, PHP, base, système, performance, logs, pièces jointes et date du serveur.
    • News board : actualités globales par groupe et avec expiration ; prend en charge _lastlogin_.
    • DB Manager : console SQL pour superadministrateurs ou profil DM ; un mauvais usage est irréversible.
    • Links : liens externes ou internes du menu ; les internes utilisent des chemins comme wiki/operation/wiki/wiki.
    • System events : cron, rapports programmés et échecs.
    • Audit log : actions utilisateur, recherche par texte et date, export CSV.
    • Error log : pandora_itsm.log, avec option d'effacement.
    • Translate strings : traductions personnalisées sur l'anglais d'origine.
    • Console extensions : registre, installation et activation des extensions de console ; voir 12.3 Extensions de console.

    Bonnes pratiques¶

    • Changez un bloc à la fois et cliquez sur Update.
    • Testez les changements dans un environnement de test avant la production.
    • Documentez qui a changé chaque option et pourquoi.
    • Vérifiez HTTPS, courriel et authentification après tout changement d'infrastructure.
    • Sauvegardez avant de toucher aux anciennes données ou au gestionnaire de base.
    • N'utilisez pas Reset all data comme outil de nettoyage.

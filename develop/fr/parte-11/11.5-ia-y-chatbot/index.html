    IA et chatbot¶

    Le chatbot de Pandora ITSM n'est pas une fenêtre qui dit « bonjour » puis attend. C'est un système d'assistance composé de deux pièces : un serveur de chat avec son client web et, en option, un moteur d'intelligence artificielle qui apprend de la base de connaissances et des dialogues pour proposer des réponses.

    Sans IA, le chat fonctionne quand même : les utilisateurs ouvrent une conversation et un opérateur répond. Avec l'IA, le système peut répondre seul, assister l'opérateur ou faire les deux selon le mode. La différence entre « avoir un chat » et « avoir un chatbot » tient à cette seconde pièce, et à son entraînement.

    L'architecture comporte trois éléments : le client de chat, avec lequel interagit l'utilisateur ; le serveur de chat, avec lequel travaille l'opérateur ; et le moteur de prédiction, qui génère les réponses. Le client et le serveur sont fournis avec Pandora ITSM ; le moteur de prédiction s'installe à part.

    Serveur de chat¶

    La configuration globale se trouve dans Setup → Setup → ChatBot, sous Chat Global Options.

    Les principaux champs sont :

    • Enable chat : active le service.
    • Ws url, Ws port et Ws password : adresse, port et mot de passe du web service du chat.
    • Ws channel by default : canal utilisé par défaut.
    • Check chat server : vérifie la connexion ; un point vert indique qu'il répond.
    • General chat : Disabled, Only IA ou Manual.
    • Ticket chat : Disabled ou Enabled pour le chat dans les tickets.
    • Enable SSL : active HTTPS et affiche les chemins du certificat et de la clé.

    Ws url doit être l'URL publique de l'installation de Pandora ITSM —la même que celle affichée dans Public access to server du setup général—, et non une adresse interne que le navigateur de l'utilisateur ne peut pas atteindre. Si le chat ne se connecte pas, vérifiez cette URL avant de toucher à Node.js.

    Si l'IA est active, les boutons les boutons de mise à jour du modèle de la base de connaissances et du modèle conversationnel apparaissent en dessous ; ils réentraînent les modèles avec les informations actuelles.

    HTTPS et Node.js¶

    Pour servir le chat hors de la console, utilisez HTTPS. Activez Enable SSL, remplacez les certificats d'exemple par les vôtres, enregistrez avec Update et vérifiez que Check chat server reste au vert.

    Le serveur de chat est une application Node.js située dans extras/chat_server. Une installation typique sur un système yum est :

    curl -fsSL https://rpm.nodesource.com/setup_lts.x | bash -
yum install -y nodejs
npm i -g pm2
cd /var/www/html/pandoraitsm/extras/chat_server
npm update
pm2 start server.js

    Utilisez une version de Node.js compatible avec les dépendances actuelles —le serveur utilise Express 5, il faut donc une version moderne— et non la 12 des anciens manuels. Si npm se plaint de la version, le chat ne démarrera pas même si la configuration est correcte.

    Pour qu'il démarre avec le système, créez /etc/systemd/system/pandoraitsm-chat.service :

    [Unit]
Description=Pandora ITSM Chat Server
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/node server.js
Restart=always
User=root
Environment=NODE_ENV=production
WorkingDirectory=/var/www/html/pandoraitsm/extras/chat_server

[Install]
WantedBy=multi-user.target

    Puis activez-le :

    systemctl daemon-reload
systemctl enable --now pandoraitsm-chat.service

    La connexion à la base de données se configure dans extras/chat_server/config/config.js. Les valeurs par défaut conviennent à une installation standard ; modifiez-les si la base est sur un autre serveur ou utilise d'autres identifiants.

    Moteur d'IA et configuration par canal¶

    Le moteur de prédiction s'installe en root et écoute sur le port 6000/tcp :

    yum install -y python3 python36-Cython
wget http://<serveur>/prediction_engine-latest.tgz
tar xvzf prediction_engine-latest.tgz
cd prediction_engine
./install.sh
systemctl restart prediction_engine.service

    L'IA se configure par canal, pas globalement : Support → Chat → Channel Manage, cliquez sur le nom du canal puis sur Enable Chat IA.

    Deux modes d'IA existent :

    • Pandora ITSM AI : utilise le moteur de prédiction local. Indiquez IA url —l'URL du web service, par exemple http://192.168.1.10—, IA port —6000 par défaut— et Mode IA :
    • Manual : l'IA ne répond pas ; l'opérateur mène la conversation.
    • Semi-auto : l'IA propose des réponses et l'opérateur choisit.
    • Full-auto : l'IA répond seule.
    • ChatGPT (OpenAI) : utilise l'API d'OpenAI. Renseignez API Key, Model (gpt-4 ou gpt-3.5-turbo), Max tokens, Context time, Temperature, Avatar, Title, Subtitle et Context.

    Full-auto affiche aussi les temps de réponse et le seuil de certitude :

    • Initial response time : secondes avant la première réponse.
    • Response time between conversations : attente entre une question et la suivante.
    • Progress bar timeout : temps dont dispose l'opérateur pour choisir une réponse avant que l'IA réponde seule.
    • Certainty threshold : confiance minimale, entre 0 et 1, pour accepter une réponse. Une valeur basse répond à tout ; une valeur haute préfère se taire.

    Dans ChatGPT, Context est le message système envoyé au début. Pandora ITSM y ajoute la consigne de répondre dans la langue de l'utilisateur —ou dans la langue par défaut du canal si celle de l'utilisateur n'est pas disponible—. Temperature va de 0 à 1 : plus elle est basse, plus la réponse est prévisible ; plus elle est haute, plus elle est créative.

    Avant de changer de modèle ou d'entraîner, faites une copie :

    cp -r /opt/prediction_engine/models /opt/prediction_engine/models.bak

    Pour restaurer :

    cp -f /opt/prediction_engine/models.bak/* /opt/prediction_engine/models/

    Entraînement des modèles¶

    Le chemin normal passe par les boutons botón de actualización de la base de conocimiento et Update conversational model du Setup. L'entraînement manuel est avancé et n'a de sens que si vous voulez contrôler le corpus.

    Le modèle de questions-réponses s'entraîne avec un CSV au format suivant :

    lang;question;answer
"es";"¿Cómo abro un ticket?";"En Support → Create new ticket."
"en";"How do I open a ticket?";"In Support → Create new ticket."

    Vous pouvez le générer depuis la base de données de Pandora ITSM :

    SELECT id_language AS lang, title AS question, data AS answer
FROM tkb_data
INTO OUTFILE '/opt/prediction_engine/data/pandoraitsm_kb.csv'
FIELDS TERMINATED BY ';' ENCLOSED BY '"'
LINES TERMINATED BY '\n';

    Compressez le CSV, placez-le dans /opt/prediction_engine/data/ et entraînez :

    cd /opt/prediction_engine/src
python kb_train.pyc

    Les dialogues conversationnels se définissent en YAML par langue :

    categories:
  - Support
  - Facturation
conversations:
  - - Bonjour
    - Comment puis-je vous aider ?
  - - Je veux ouvrir un ticket
    - Allez dans Support et cliquez sur Create new ticket

    Les fichiers vont dans /opt/prediction_engine/data/chat_es ou chat_en, selon le code ISO de la langue, et s'entraînent avec :

    cd /opt/prediction_engine/src
python chat_train.pyc

    En plus des fichiers YAML, Support → Chat → Conversations → Data management permet d'ajouter des éléments conversationnels par catégorie et par langue et de les rechercher par mot-clé.

    Utilisation du chat et des canaux¶

    Les canaux définissent les lieux de conversation. Support → Chat → Channel Manage liste les canaux et permet de créer, modifier, supprimer et générer le code pour les intégrer.

    Chaque canal a besoin d'au moins un opérateur. Avec Edit users, vous ajoutez des utilisateurs et définissez leur description, avatar et langues. L'opérateur peut avoir un avatar différent de celui de sa fiche et plusieurs langues d'assistance.

    Les opérateurs travaillent depuis Support → Chat → Chat View. L'écran affiche les conversations avec leur état, l'utilisateur, le canal, la langue, le temps actif, l'opérateur et le ticket associé. Pour recevoir des notifications sonores, il faut rester sur cet écran ; le chat n'avertit pas depuis une autre section.

    Si un utilisateur interne ouvre le chat, la conversation indique de qui il s'agit. Si un visiteur anonyme l'ouvre depuis l'extérieur, il apparaît comme utilisateur externe.

    Pour utiliser le chat hors de Pandora ITSM, cliquez sur Generate Bundle dans le canal. L'icône en forme d'étoile affiche le snippet JavaScript à intégrer dans le site ou l'application. L'URL du snippet est l'URL publique configurée sur le serveur de chat ; elle doit être accessible depuis le lieu où se trouvent les utilisateurs, généralement Internet.

    Bonnes pratiques et problèmes fréquents¶

    • Utilisez HTTPS si le chat est destiné à l'extérieur de la console. L'avertissement du navigateur fait fuir n'importe quel visiteur.
    • Consacrez un canal à chaque usage —support interne, site public, avant-vente— et ne mélangez pas opérateurs et langues sans raison.
    • Avant d'entraîner, copiez /opt/prediction_engine/models. Un corpus mal préparé emporte le modèle précédent avec lui.
    • Si le chat ne se connecte pas, vérifiez dans cet ordre : Ws url, le service Node.js, Check chat server et les certificats.
    • Si l'IA ne répond pas, vérifiez le mode du canal, l'URL et le port du moteur, et que le service prediction_engine écoute sur le port 6000.
    • Renouvelez la clé API OpenAI si vous la partagez ou soupçonnez une fuite.

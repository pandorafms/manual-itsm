    Installation¶

    Installing Pandora ITSM has an easy part and a part that gets complicated the moment someone decides to improvise. The official script does almost everything: it installs the dependencies, creates the database, loads the schema and leaves the console ready. What it does not do is guess whether the server is short on memory, whether the database lives somewhere else or whether someone will keep the default password until audit day.

    The point of this chapter is simple: installations rarely fail because of the software; they fail because of haste. With two gigabytes of RAM, ten gigabytes of disk and a clear decision about the database, the rest is following the order. Without that, the script stops, and it is right to do so.

    The default installation is the online installation: an official script that runs as root, installs the dependencies, creates the database, loads the schema and the initial data and leaves the console at http://<IP-or-FQDN>/pandoraitsm. For environments without Internet access there is the offline installation.

    What is installed¶

    The installer leaves these components on the server:

    • Web console in /var/www/html/pandoraitsm.
    • Apache web server and PHP-FPM.
    • MySQL or Percona database, local or external.
    • Pandora ITSM schema and initial data.
    • Cron every five minutes for internal tasks.
    • Chat server and its Node.js dependencies.
    • Configuration in include/config.inc.php.

    It is not a managed service or a desktop installation. The whole product is used from the browser, and the server remains the responsibility of whoever administers it: patching, backing up and monitoring are not included in the package.

    Before you start¶

    Before running the installer, check these points:

    • You have root or sudo access on the server.
    • The server has a resolvable hostname or FQDN.
    • The time zone is correct; the installer sets it with TZ.
    • There is Internet access and connectivity to packages.pandorafms.com.
    • Ports 80 and 443 are free. If the database is external, port 3306 must also be reachable from the server.
    • SELinux and the firewall allow web traffic.
    • You have decided whether the database will be local or external.
    • If you have decided to install the database externally, you have its passwords ready and they meet the MySQL password policy.
    • If you are reinstalling, you have a backup or a snapshot of the machine.

    The installer stops if it finds Pandora ITSM packages, the /var/www/html/pandoraitsm directory or a database with the same name. It does not clean up a previous installation on its own. If your plan was "we will see", the installer has another one: stop.

    Online installation¶

    The online installation runs with a single command, whatever the distribution. Run it as root:

    curl -SsL https://pfms.me/deploy-pandora-itsm | bash

    The script detects the system and downloads the matching installer. The rest of this chapter explains what it does, which variables it accepts and how to check the result.

    System requirements¶

    Hardware¶

    Requirement Minimum Recommended
    CPU 2.4 GHz, dual core Four cores or more depending on concurrent users
    RAM 2 GB 4 GB
    Disk 10 GB free 20 GB or more, depending on history and attachments
    Network 100 Mbps 1 Gbps

    The installer checks memory and disk space before changing anything. On EL9 and EL10 it requires 9 GB free in /var and 1 GB in /usr. If the server does not meet the minimum, the script stops. This is not a suggestion: it is a condition.

    Operating systems¶

    System Supported versions
    RHEL, Rocky Linux or AlmaLinux EL 9 and EL 10
    Ubuntu Server 22.04 and 24.04

    Software¶

    Component Version
    PHP 8.2 or 8.4
    MySQL or Percona 8.0 or 8.4 depending on the distribution
    Web server Apache with PHP-FPM
    Browser Current Chrome, Edge, Firefox or Safari; minimum resolution 1280 × 720

    EL10 only accepts MySQL/Percona 8.4. EL9 and Ubuntu accept 8.0 and 8.4. The installer sets the PHP and MySQL versions with the PHPVER and MYVER variables. There is no prize for using the version that is no longer supported.

    PHP extensions¶

    The console needs the mysqli, gd, session, mbstring, ldap, gettext, imap, phar and zip extensions. The installer adds them with the PHP packages; if you install manually, check that they are enabled before opening the console. An extension error disguises itself as a blank screen, and a blank screen never brings good news.

    Database¶

    Pandora ITSM needs a MySQL or Percona database. It can run on the same server or on a dedicated one. A shared database is valid, but performance depends on the server capacity and the volume of history: tickets, their attachments and the audit log grow with use.

    If the database is external, prepare the host, port, user and permissions first. The installer can create the database and user, or use existing ones with SKIP_DATABASE_INSTALL=1.

    Installation modes¶

    Mode When to use it Needs Internet
    Online New installation on a server with Internet access Yes
    Offline Isolated or restricted servers No
    Manual web installer Debugging or a piece-by-piece installation with install.php Depends

    The manual web installer is not the recommended path for production. It helps you understand each step and works for tightly controlled environments; the online script is the supported procedure. Do not confuse "I can do it by hand" with "I should do it by hand".

    Online installation step by step¶

    Run the script¶

    The generic script takes its configuration from environment variables and detects the system to download the matching installer. These are the values you can adjust:

    Variable Default Purpose
    TZ Europe/Madrid System time zone
    MYVER 84 MySQL/Percona version: 80 or 84
    PHPVER 8.4 PHP version: 8.2 or 8.4
    DBHOST 127.0.0.1 Database host
    DBNAME pandoraitsm Database name
    DBUSER pandoraitsm Database user
    DBPASS P4ndor4.itsm Database user password
    DBPORT 3306 MySQL port
    DBROOTPASS P4ndor4.itsm MySQL root password
    DBROOTUSER root MySQL administrator user
    SKIP_PRECHECK 0 Skips the previous-installation check
    SKIP_KERNEL_OPTIMIZATIONS 0 Skips kernel tuning
    SKIP_DATABASE_INSTALL 0 Uses an existing database
    POOL_SIZE Calculated from RAM PHP-FPM pool size

    Always replace the example passwords. If you use MySQL 8 with the password policy enabled, P4ndor4.itsm may not meet the requirements; choose a longer password with upper and lower case letters, numbers and symbols. Today's convenience is tomorrow's incident.

    EL10 example¶

    env TZ='Europe/Madrid' \
    MYVER='84' \
    PHPVER='8.4' \
    DBHOST='127.0.0.1' \
    DBNAME='pandoraitsm' \
    DBUSER='pandoraitsm' \
    DBPASS='ChangeThisPassword' \
    DBPORT='3306' \
    DBROOTPASS='ChangeThisRootPassword' \
    DBROOTUSER='root' \
    SKIP_PRECHECK=0 \
    SKIP_KERNEL_OPTIMIZATIONS=0 \
    SKIP_DATABASE_INSTALL=0 \
    bash itsm_deploy_enterprise_entrypoint.sh

    The generic script detects EL10 and downloads the EL10 installer. To use PHP 8.2, change PHPVER='8.2'. On EL10 the installer only accepts MYVER=84; on EL9 you can use MYVER='80' if your database is MySQL 8.0.

    What the script does¶

    1. Checks the operating system, memory, disk and permissions.
    2. Adds the Pandora and Remi repositories for PHP.
    3. Installs Apache, PHP-FPM, MySQL or Percona, Node.js and the extensions.
    4. Creates the database and user, or reuses existing ones.
    5. Loads integria_db.sql and integria_dbdata.sql.
    6. Writes include/config.inc.php with the connection details.
    7. Sets up the integria_cron.php cron job every five minutes.
    8. Installs and starts the chat server.
    9. Applies kernel and PHP-FPM tuning.
    10. Prints the access URL and the initial credentials.

    The script writes the details to /tmp/pandoraitsm-deploy-enterprise-el9-YYYY-MM-DD.log (or the name for your system). If something fails, that log is the first thing to read. Guessing the error costs more than opening the file.

    Result¶

    When it finishes, the script prints an address similar to:

    http://192.0.2.10/pandoraitsm

    and the initial credentials. Open that address from a browser with access to the server.

    Offline installation¶

    The offline installation uses a package with the dependencies and a local script. The flow is:

    1. Download the dependency package and the script for your distribution.
    2. Copy them to the isolated server.
    3. Unpack the package.
    4. Run itsm_deploy_enterprise_local_el10.sh as root, with the same variables as in the online installation.

    Offline installation is not supported on Ubuntu with the current scripts.

    First access¶

    Console URL¶

    The console is available at:

    http://<IP-or-FQDN>/pandoraitsm

    If you have configured TLS, use https://. The /pandoraitsm path is what the installer writes in config.inc.php; do not change it without updating the Apache configuration.

    Licence and login¶

    If you use the manual web installer, the first screen asks you to accept the licence. With the online script, the first access is the login screen directly.

    The initial credentials are:

    User Password
    admin pandoraitsm

    Change the password on first access

    The admin account is an installation user. Change its password before connecting the console to the production network and create your own users afterwards. Do not share the admin account between several people.

    A default password is a welcome, not a security policy. The sooner it disappears, the better.

    Change the password¶

    Log in as admin, open the user menu and change the password. Then create a user with your name, assign the profile and group it needs and keep admin for administration tasks.

    Initial data and "Reset all data"¶

    The installation loads integria_dbdata.sql, which includes sample data: companies, contacts, tickets and other records that let you see the console with content from day one.

    If you want to start with a clean system:

    1. Open Setup → Setup → Old data maintenance.
    2. Click Reset all data.
    3. Confirm twice in the dialogs.

    Reset all data deletes data and attachments

    The option deletes the database data and the attachment files. It keeps the current admin user and some configuration settings. There is no undo: make a backup first if you need to keep anything.

    Sample data is great for a demo and a liability in production. The button exists so you do not have to delete it by hand, table by table.

    Verification and post-installation¶

    Services¶

    Check that the web server, PHP-FPM and the database are running:

    # RHEL, Rocky Linux and AlmaLinux
systemctl status httpd php-fpm mysqld

# Ubuntu
systemctl status apache2 php8.4-fpm mysql

    Adjust the PHP-FPM name to the installed version (php8.2-fpm or php8.4-fpm). A service you do not check is a service that fails on Monday.

    Cron¶

    The installer leaves three scheduled tasks, all every five minutes:

    */5 * * * * root php /var/www/html/pandoraitsm/include/integria_cron.php
*/5 * * * * php /var/www/html/pandoraitsm/include/crm_cron.php
*/5 * * * * php /var/www/html/pandoraitsm/include/campaign_cron.php

    Each one has its job:

    Task What it does
    integria_cron.php Core: daily checks (calendar, projects, tasks, changes, autowu, automatic ticket closing, cleanup and notifications), mail queue, CRM and inventory task reminders, Enterprise cron, SLAs and time workflow rules.
    crm_cron.php CRM: Gmail sent and inbox, contact and deal workflows, overdue schedules, due-task emails, activity notifications, Google Meet transcripts and Zadarma calls.
    campaign_cron.php Campaigns: runs pending campaigns and checks email bounces.

    Inventory also has its own script, inventory_cron.php: it syncs inventory from Pandora FMS nodes, expires overdue schedules and cleans orphan objects. The current installer does not add it to /etc/crontab; add its entry if you need it:

    */5 * * * * php /var/www/html/pandoraitsm/include/inventory_cron.php

    Check that the tasks are active and the files exist:

    grep pandoraitsm /etc/crontab
ls -l /var/www/html/pandoraitsm/include/*_cron.php

    If a task is missing, check /etc/crontab and the application log. A cron that does not run does not warn you; it simply stops doing its job.

    Logs¶

    Log Content
    /var/www/html/pandoraitsm/pandora_itsm.log Application errors
    /var/log/php-fpm/www-error.log PHP and PHP-FPM errors
    /tmp/pandoraitsm-deploy-enterprise-<system>-YYYY-MM-DD.log Installation

    If PHP does not start or the console returns a 500 error, start with /var/log/php-fpm/www-error.log: the real error is there, not in the generic message the browser shows.

    Minimum security¶

    • Change the admin password.
    • Create your own users and remove or disable the sample ones.
    • Decide whether to keep the sample data.
    • Review the firewall: only 80/443 should be open to the Internet.
    • Configure TLS if the console is reachable outside the internal network.
    • Make sure the database is not exposed to the Internet.
    • Schedule backups before loading real data.

    Reinstallation and cleanup¶

    The installer does not overwrite an existing installation. If it finds packages, /var/www/html/pandoraitsm or the database, it stops. To reinstall from scratch, remove first:

    • The Pandora ITSM packages.
    • The /var/www/html/pandoraitsm directory.
    • The database and the database user.
    • The cron entry.
    • The Apache and PHP-FPM configuration if you customised it.

    There is no automatic uninstaller. If you only want to start over with the data, use Reset all data instead of reinstalling. If you need to keep anything, back up the database and the attachments before deleting.

    Common problems¶

    Symptom Likely cause Check
    The script says the system is not supported Distribution or version other than EL9, EL10 or Ubuntu 22.04/24.04 Check /etc/os-release and use the right script
    Memory or disk check fails Less than 2 GB RAM or less than 10 GB free Increase the server or free space
    Cannot reach packages.pandorafms.com No Internet access or DNS Test ping and check the proxy
    PHP or MySQL not supported Version outside 8.2/8.4 or 8.0/8.4 Adjust PHPVER and MYVER
    MySQL rejects the password MySQL 8 password policy Use a stronger password
    The installer finds a previous installation Existing packages, directory or database Clean up or use another machine
    The console does not respond after the script Apache, PHP-FPM or SELinux Check services and logs
    The console opens but does not load data Database or configuration Check config.inc.php and the application log

    If the problem is not in this table, see Part 14 (FAQ) and attach the installation log when opening an issue. An "it does not work" without a log is a conversation that starts badly.

    Next steps¶

    With the console running, the recommended order is:

    1. Review the licence and the version policy (1.3 and 1.4).
    2. Configure users, groups and profiles (Part 02).
    3. Set up email (Part 03).
    4. Schedule backups and review the advanced configuration (Part 12).
    5. Only when you have a stable version, plan the update (1.2).

    Installing is the beginning, not the end. The installation gets the engine running; what comes next depends on how you configure it and how much you respect the data it will store.

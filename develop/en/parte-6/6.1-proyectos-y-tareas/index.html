    Projects and tasks¶

    A project is not a list of tasks with colours: it is a contract of time, cost and responsibility. Pandora ITSM lets you plan that contract, book hours against it and check whether reality matches what was promised. Everything else —the Gantt chart, the board, the reports— are ways of looking at the same problem from different angles.

    The idea behind this chapter is simple: a project is managed with people, tasks and hours, not with good intentions. If hours are not booked against a task, the cost is fiction; if tasks have no owner, the Gantt chart is decoration.

    What a project is¶

    Project management combines projects, tasks, roles and people. Tasks can have subtasks and be organised hierarchically. A task can also have associated tickets and work units where each person's time is recorded.

    The entry point is Projects → Project list. From there you create projects, check their status, filter by group or type and open the overview.

    A project has a Project manager —the creator by default—, a project group, a team of people with different roles, and a set of tasks. The project does not do the work: it organises it. The people and the work units do the work.

    Creating a project¶

    In Projects → Project list → Create project you define the basic data:

    Field What it means
    Name Project name.
    Project manager Responsible user. The creator by default.
    Project group Logical group the project belongs to.
    CC Email address that receives project notifications.
    Start and End Start and end dates.
    Status template Task status template.
    Tag template Task tag template.
    Company and Contract Associated company and contract, if applicable.
    Description Descriptive text.
    Project Types Project type and its custom fields.
    Replicate tasks from other project into this Copies tasks from another project.

    Replicating tasks is convenient for projects that repeat, but it copies the original dates: every task must be readjusted afterwards. It is not a clone with a mind of its own.

    A project can be linked to a company or a contract only if none of its tasks is already linked to a company or contract, and vice versa. The restriction prevents the same work from being charged to two different customers.

    Overview and editing¶

    Clicking a project name opens Project overview. The Details section can be edited directly; Quick edit changes the main fields, such as the project group, the status template and the tag template.

    The main tabs are:

    • Task planning: task planning and task list.
    • Board view: board by status.
    • Gantt chart: time diagram.
    • Milestones: project milestones.
    • Full edit: the same interface used to create the project.

    At the bottom you find Notes, Tracker, Attachments, Members and Budget. These are not decorative tabs: each one answers a different question about the project.

    Statistics, distribution and activity¶

    Statistics summarises people involved, total work hours, planned hours, billable hours and project duration. Workload distribution and Task distribution show the percentage split of work and tasks. Activity shows what happened and when.

    The Budget tab calculates profitability and compares estimated cost, total cost, amount charged and average cost per hour. It also breaks cost down by role. If hours are not booked properly, this report is a work of fiction with a table layout.

    Tracker records project operations: opening, closing, changes and additions of information. It is the history that answers "who changed this, and when?".

    People and roles¶

    In Members you add or remove project users with Add role people. A user can have a global role in the project and a different role in each task. Permissions depend on the role: from full modification to simply reporting work.

    Roles are managed in People → Roles management. Pandora ITSM includes these default roles:

    • Project manager.
    • Systems engineer.
    • Junior consultant.
    • Junior programmer.
    • Senior programmer.
    • Analyst.
    • Senior consultant.
    • Support engineer.

    The Project manager role can only be edited, not deleted. Each role has an hourly cost used to calculate task and project costs. Additional costs —expense invoices or other charges— are booked directly against the task.

    Tasks¶

    Planning is done in Project overview → Task planning. The list shows tasks with their status, dates, progress, hours worked, deviation, priority and tags. You can sort by any column.

    The Hours worked column opens a summary of the task's work units: cost, hours, breakdown and filters by date, milestone or person. Filtered information can be exported to CSV.

    The Op. column groups the actions:

    • Members: people taking part in the task.
    • Issues: associated tickets.
    • Work units: add work units.
    • Edit: edit the task.
    • Delete: permanently delete the task.

    For a ticket's work units to be booked against the task and project, you must assign a role and enable Add to project's cost when creating them.

    Creating and editing a task¶

    With Create at the bottom of the list you create a task with its basic data: name, priority, parent task, start and end dates, owner and estimated hours. You can also enable email notifications at start and end, the overtime notice and recurrence.

    Recurrence —weekly, monthly or annual— keeps an hour counter per period. The counter resets at the end of each interval, but booked hours remain in the task total. The recurrence interval cannot exceed total hours.

    After creating it, edit it to assign people in Add users to task, set costs, tags, priority, task type and custom fields.

    The edit form also includes:

    • Estimated cost and Fixed cost.
    • Related company and Related contract/s.
    • Progression based on hours: calculates progress from work units. If disabled, moving the progress bar does not change the task status.
    • Task links: time relationships with other tasks.

    Task links¶

    Links define the chronological order:

    Link What it enforces
    Start to start Linked tasks cannot start before this task starts.
    Finish to start Linked tasks cannot start before this task ends.
    Finish to finish Linked tasks cannot end before this task ends, although they may end later.

    Tracking and moving¶

    Pandora ITSM records the opening, closing, changes and additions of information for each task, including work units and attached files. If a task moves to another project or parent task, its work units stay linked to it.

    Work units¶

    Project work units can be created from the task planner —the recommended option— or from People → Work unit → Add work unit.

    There are two paths that should not be confused:

    • A ticket's work units book the ticket time when it is assigned to a task, has a role and Add to project's cost is enabled.
    • Manual work units book exactly the time entered.

    The manual form can split a work unit into blocks of hours —four by default— forward or backward in time, keeping the content and changing the date. It is useful for booking a week of work without creating ten records by hand.

    There are two special cases: Work from home and work units without a project or task. They are computed as special tasks inside a special project. Holidays and sick leave have their own section in People → Work unit → Vacations and sick leave.

    Task custom fields¶

    In Projects → Tasks types you create task types. Each type can have custom fields: numeric, text, date, true/false, list or linked. When editing a task you choose the type and its fields appear.

    The behaviour is similar to ticket custom fields: they classify, filter and report. A task type with twenty fields nobody fills in does not improve planning.

    Milestones¶

    A milestone is a zero-duration task that represents an important date: end of a phase, report delivery, customer review. It is managed in Project overview → Milestones and can be used to filter reports and searches.

    Milestones support custom fields with Milestone fields:

    • Name: mandatory; names can repeat.
    • Field visibility: shows the field in the milestone list.
    • Type: text, text area, combo or checkbox.

    Attachments¶

    In Project overview → Attachments you can upload, download and delete project files. Each file can have a description and can be searched by keyword, location —project, tickets or work units— and date.

    Source code files such as .php or .pl are not allowed; compress them before uploading. Only an administrator or the file creator with project administration permissions can delete it.

    Gantt chart¶

    In Project overview → Gantt chart you see tasks and their chronological relationships. It can be opened full screen, and you can add tasks and subtasks and link them by dragging from the end of one task to the start of the next.

    Unlinked tasks can be moved in time. Linked tasks follow the logical restriction: one does not start before the previous one ends. Show real planning compares the plan with the work actually done and can be viewed by month, week or day.

    Archiving and deletion¶

    When a project ends it can be archived from Projects → Project list → Options → Archive. The project moves to the archive view and keeps all its information.

    An archived project can be unarchived or deleted. Deleting it removes its tasks and leaves work units orphaned: they still exist, but without a project or task. Archived projects do not send automatic notifications for task, project or milestone closure.

    To see active and archived projects, open Filters, set Active to Any and apply. The list returns to the default filters when refreshed.

    Board view¶

    Board view organises tickets and tasks in columns by status. The horizontal bar at the bottom scrolls through all columns. The filter section lets you filter by users, completion percentage, tags and other values.

    Each column can be collapsed or expanded. Each task has quick actions to edit, create a work unit, move it, copy it or delete it. Tasks are collapsed by default and can be expanded.

    With Ctrl you can select several tasks and move them as a block to another column. It is the fastest way to reorganise a project without opening each task.

    Task status templates¶

    In Projects → Task status templates you define task statuses. The default template includes four statuses —Pending, In process, Completed and Verified— with their colour and visibility.

    The default template and its four statuses cannot be deleted. Creating a new template copies those four statuses, which also cannot be deleted. If a template in use is deleted, the project returns to the default template. Changing a project's template clears the current status, so you must assign one from the new template.

    Task tag templates¶

    In Projects → Task tag templates you define task tags. The default template includes Low, Medium and High.

    You can create templates per project and add your own tags. Changing a project's template deletes tags already assigned to tasks. It is one of those operations best tested on a toy project before doing it on the important one.

    Exporting to CSV¶

    The board view exports selected tasks to CSV. The file includes, among others, these columns:

    ID, Project, Parent Task, Task name, Description, Completion,
Work units hours, Status, Priority, Start, End, Estimated hours,
Cost, Periodicity, Start period, Interval hours, CC, Send email,
Set hours, Involved people, Tags

    Over HTTPS the download starts automatically; over HTTP you may need to authorise it in the browser. The export contains the selected tasks, not a complete copy of the project with its statuses and tickets.

    Notes¶

    The Notes tab stores internal messages as a logbook. They can be searched by keyword and linked to a task; by default they are not linked to any task.

    Notes are excluded from system reports, so they are not the place to record hours or costs. In the current interface they can be edited and deleted; do not treat them as an immutable record.

    Workflow rules¶

    In Projects → Workflow rules you define automatic rules for projects and tasks. They are independent of ticket workflow rules and ship with four sample rules disabled.

    Each rule has an execution mode:

    • Cron: evaluated periodically.
    • Real time: evaluated when the user performs an action.

    Conditions are created in the Conditions tab and can combine project and task fields. The default relationship is OR; AND, AND NOT, OR NOT and XOR are also available. Conditions can be ordered with Up and Down.

    Actions are created in the Actions tab: send an email to one or more users, change the project manager, and so on.

    Email templates can use these macros:

    Macro Value
    _next_milestone_ Date and time of the next milestone.
    _project_completion_ Project completion percentage.
    _project_cost_deviation_ Project cost deviation.
    _project_costs_ Project cost.
    _project_end_date_ Project end date.
    _project_estimated_costs_ Estimated project cost.
    _project_estimated_hours_ Estimated project hours.
    _project_manager_ Project manager.
    _project_name_ Project name.
    _project_pending_hours_ Pending project hours.
    _project_start_date_ Project start date.
    _project_used_hours_ Hours worked on the project.
    _project_users_ Users involved in the project.
    _task_completion_ Task completion percentage.
    _task_end_date_ Task end date.
    _task_estimated_hours_ Estimated task hours.
    _task_name_ Task name.
    _task_pending_hours_ Pending task hours.
    _task_recurrence_ Task recurrence.
    _task_start_date_ Task start date.
    _task_used_hours_ Hours worked on the task.
    _task_users_ Users involved in the task.
    _workflow_content_ Summary of hours, recurrence and other data.

    Project groups and types¶

    Project groups are managed in Projects → Project groups. They group projects that share characteristics. The name can repeat and the icon is optional. Then assign each project to its group and filter by it in the list.

    Projects types are managed in Projects → Projects types. A project type can have custom fields: text, numeric, date, true/false, lists, hierarchically linked lists and URL with description. Those fields can be filtered in the project list.

    Each project type custom field has three common options:

    • Show in the projects list: displays it as a column in the list.
    • Global field: adds it to all existing and future types.
    • Required: forces a value to be set.

    Be careful with global fields: once created they can only be deleted, not edited. If they are also marked Show in the projects list, as many columns appear as project types exist. A project without a type uses the first one in the list when edited, so check the type before saving.

    Best practices¶

    • Define a clear owner and project group from the start.
    • Assign roles and costs before booking hours.
    • Use types and custom fields only if they will be filtered or reported.
    • Keep estimates and actual hours up to date.
    • Use milestones for the dates that really matter.
    • Archive finished projects instead of deleting them.
    • Review status and tag templates before changing them.
    • Read the project reports after booking hours, not before any exist.

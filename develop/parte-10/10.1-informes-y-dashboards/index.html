    Informes y dashboards¶

    Un informe no sirve para llenar una reunión: sirve para responder una pregunta. Pandora ITSM reúne en Reports los informes de personas, soporte, proyectos y consultas SQL, y añade dashboards para mirar lo importante sin abrir cinco pantallas distintas. El problema nunca es que falten datos; el problema es confundir un gráfico bonito con una decisión bien tomada.

    Este capítulo explica cómo se construyen los dashboards, cómo se programan los informes y qué mide cada informe. Los informes de proyectos se mantienen aquí, junto al resto, porque comparten menú, plantillas y programador.

    Dónde viven los informes¶

    El menú Reports agrupa:

    • Dashboards → Manage Dashboard: tableros visuales.
    • Report manager: plantillas, programación y biblioteca de informes.
    • People management: tiempo, vacaciones, personas y rendimiento de equipos.
    • Support: soporte, tickets, resoluciones, operadores y clientes.
    • Project management: informes de proyectos.
    • Custom SQL report: consultas propias.

    Los permisos se basan en los bits Report Reader (RR) y Report Manager (RM) del perfil, además de la visibilidad de grupo. Un usuario puede ver un informe y no poder crearlo, o crear una consulta SQL y no poder ver los datos de otro grupo.

    Dashboards¶

    Los dashboards son tableros de mando. Cada usuario puede tener los suyos y elegir cuál ve al iniciar sesión.

    En Reports → Dashboards → Manage Dashboard se listan los dashboards, se buscan por palabra clave y se crean con Create. Cada uno tiene Update para cambiar nombre y grupo, y Delete para borrarlo. El Default dashboard incluye todos los widgets disponibles y sirve de demostración.

    Crear y editar¶

    Al crear un dashboard se indica un Name único, sin espacios al principio ni al final, y un Group. El nombre se puede cambiar después con Update.

    Para editar el contenido se abre el dashboard y se activa el botón de edición. Aparece Add cell para añadir una celda y New widget para elegir el tipo de widget. Cada widget se configura con el icono de engranaje y se borra con la papelera. Se puede arrastrar por su título y redimensionar desde los bordes.

    Widgets¶

    Customized links¶

    Añade un enlace funcional que abre en la misma ventana o en una pestaña nueva. La URL debe empezar por http:// o https://; si no, se interpreta como enlace interno. También hay que elegir una imagen: ambos campos son obligatorios.

    Ejemplo de enlace interno a la lista de cambios:

    • URL: changes/operation/changes/changes_list
    • Open new tab: activado
    • Image: ticket.svg

    El resto de campos —texto, título, fuente y colores— son opcionales.

    Message board¶

    Es un editor de texto enriquecido para incrustar tablas, enlaces, imágenes, listas o documentos completos. Trae un mensaje de bienvenida que desaparece cuando se añade contenido propio.

    Predefined links¶

    Añade enlaces internos con etiqueta e icono:

    • Knowledge base: base de conocimiento.
    • Downloads: soporte y descargas.
    • Create ticket: alta de tickets.
    • Wiki: wiki interna.
    • Time tracker: registro de actividad.
    • My tickets: tickets del usuario.

    Search box¶

    Añade una caja de búsqueda por palabra clave. Se debe seleccionar al menos un área: base de conocimiento, Wiki, tickets, proyectos, personas, contactos, contratos, empresas, facturas o leads.

    Support Activity Graph¶

    Muestra un gráfico de actividad en uno o varios calendarios a partir de un filtro guardado de tickets. Cada usuario solo puede elegir sus propios filtros.

    Support Evolution Graph¶

    Muestra tickets abiertos y cerrados a partir de un filtro guardado, con una tasa de refresco configurable. También usa solo los filtros del usuario.

    Support SLA¶

    Con un filtro guardado muestra un gráfico de tarta con el porcentaje de SLA cumplido e incumplido.

    Support statistics¶

    Agrupa los tickets de un filtro guardado por prioridad, estado, tipo o estadísticas generales. Hay que elegir una opción en Statistic.

    Ticket list¶

    Muestra una lista paginada de tickets —cinco por defecto— con los campos y el orden que se elijan. Usa un filtro guardado y un periodo de refresco para mantener la información al día.

    Gestor de informes¶

    En Reports → Report manager se crean plantillas y programaciones. Los informes programados se guardan en la biblioteca y se pueden enviar por correo. El cron del sistema debe estar activo; sin cron no hay magia, solo una cola esperando.

    Plantillas para informes¶

    En Reports → Report manager → Templates se define la portada, la cabecera y el pie de los informes en PDF. La portada admite imágenes, enlaces, formato y márgenes. Las macros disponibles son:

    • _fullname_: usuario que genera o solicita el informe.
    • _date_: fecha de generación.
    • _time_: hora de generación.
    • _reportname_: nombre del informe.

    Las macros también funcionan en la cabecera, donde se puede cambiar el logotipo. Portada, cabecera y pie se pueden desactivar por separado.

    Programador de informes¶

    En Reports → Report manager → Report schedule se programa un informe para que se ejecute una vez, cada semana o cada mes. Se elige plantilla, se guarda en la biblioteca y se puede enviar una notificación o el propio informe por correo.

    Asignar una empresa al informe programado permite que los usuarios de esa empresa lo vean y editen. Según el tipo de informe aparecen sus filtros; Custom SQL solo muestra los informes SQL creados. Se pueden crear tantas programaciones como se necesiten.

    Biblioteca de informes¶

    En Reports → Report manager → Report library se consultan los informes generados y se buscan por tipo o por nombre.

    Informes de personas¶

    Pandora ITSM permite fichar la actividad laboral, las pausas, el trabajo remoto o presencial y las vacaciones. Los informes de esta área se pueden programar de forma semanal o mensual.

    Control de tiempo¶

    Reports → People management → Time tracking muestra la actividad diaria, semanal o mensual registrada por un usuario con el Time tracker. Hay periodos predefinidos —esta semana, este mes, los últimos tres meses— y se puede pedir uno personalizado.

    Debe existir al menos un registro diario para que el informe muestre datos; el resto de días aparecerán vacíos. Exporta a CSV, pantalla completa y PDF.

    Los tres informes de vacaciones comparten menú, pero no permisos: el detalle exige HR y, en la práctica, UM para llegar desde el menú; el calendario y la exportación dependen del acceso a Reports.

    Informe de vacaciones detallado¶

    Reports → People management → Detailed vacation report presenta el informe con dos modos: Show vacation report y el informe de unidades de trabajo. Los filtros son usuario, grupo y fecha de creación (Created from y Created to); se aplican al pulsar Search.

    El resultado muestra usuarios, total de días de vacaciones, días disfrutados y días restantes. Se puede ver a pantalla completa o exportar a PDF. Si se elige el informe de unidades de trabajo, añade los días sin justificar, los días no laborados justificados por enfermedad, las vacaciones y las vacaciones extra. Exporta a pantalla completa y PDF; no a CSV.

    Calendario de vacaciones general¶

    Reports → People management → General vacation calendar muestra las vacaciones aprobadas en vista mensual, semanal o diaria. Se puede avanzar y retroceder por mes y volver a hoy con Today. El buscador de usuario limita el calendario a una persona y los días no laborables aparecen resaltados. Solo se visualiza por pantalla.

    Informe de personas¶

    Reports → People management → People report selecciona por defecto al usuario actual y los últimos tres meses de todos los proyectos, con resumen de tickets. Muestra actividad del proyecto y porcentaje, gráficos de tickets por grupo y por grupo creador, tabla de tickets —si Show only summary está desactivado— y un resumen de tickets y tiempo trabajado.

    Exporta a CSV, pantalla completa y PDF.

    UT mensuales¶

    Reports → People management → People monthly WU muestra todos los usuarios del mes actual con el total de horas y la valoración media. Se puede cambiar de mes y filtrar por usuario.

    El botón de informe de cada usuario abre un diálogo para editar sus unidades de trabajo, una a una o de forma masiva. Solo las unidades de trabajo de tareas (Work Unit Tasks) admiten edición masiva. Según los privilegios, cada unidad se puede editar, borrar o bloquear.

    Informe de usuario detallado¶

    Reports → People management → Detailed user report exige fechas de inicio y fin. Ofrece tres opciones:

    • Project: agrupa por usuario y proyecto.
    • Role and task: agrupa por usuario y tarea.
    • Role and task (details): añade descripciones y totales de tickets, horas y costes.

    Se seleccionan usuario, periodo, roles, tareas y proyectos. No exporta a CSV, pantalla completa ni PDF.

    Informe de vacaciones¶

    Reports → People management → Vacation report selecciona todos los usuarios activos por defecto. Se eligen grupo, usuarios y fechas (Date from y Date to); las fechas son obligatorias. View muestra la tabla en pantalla y Export descarga el resultado. El filtrado por nombre se aplica al pulsar View, no mientras se escribe. Exporta a CSV, pero no a pantalla completa ni PDF.

    Rendimiento de equipos¶

    Reports → People management → Team performance muestra el funcionamiento semanal del personal de una empresa. Se filtra por grupo, fecha y área de Pandora ITSM: proyectos, soporte, cambios o control de tiempo.

    Con los valores por defecto no devuelve datos, y eso es normal:

    • El filtro principal es la empresa.
    • La interfaz de filtros se abre con Ctrl + f.
    • El día de inicio de semana se toma de la configuración general; por defecto, lunes.

    Exporta a pantalla completa, PDF y Microsoft Excel; no a CSV.

    Informes de soporte¶

    Los informes de soporte se basan en el ticketing registrado. Sirven para evaluar costes, calidad, tiempos, esfuerzo, perfiles de personal y perfiles de cliente.

    Informe de soporte¶

    Reports → Support → Support report genera un PDF con decenas de gráficas, resúmenes, listados y parámetros. Para elegir los filtros rápido conviene partir de una búsqueda personalizada guardada.

    El informe tiene dos partes:

    • Show statistics: información estadística con gráficos.
    • Show list: información tabular de tickets.

    Hay que seleccionar una o ambas. En Issue fields se eligen los campos de la tabla sin afectar a los gráficos. Incluye ocho gráficos de tarta generales con agrupaciones Top-N —tickets con más actividad, clientes más activos, operadores, abiertos, cerrados— y listados y gráficas de tendencia.

    Exporta a pantalla completa y PDF; no a CSV.

    Informe detallado del ticket¶

    Reports → Support → Detailed ticket report muestra todos los detalles de un ticket: fechas, participantes, descripción, campos personalizados, SLA y, opcionalmente, unidades de trabajo, ficheros, seguimiento y estadísticas.

    Se escriben al menos dos letras en Select issues, se elige el ticket y se pulsa Report. Las opciones adicionales son:

    • Stats: estadísticas generales, de unidades de trabajo, actividad por usuario y por estado, grupo, propietario y empresa.
    • Tracking: cambios del ticket, filtrables por usuario.
    • Files: ficheros adjuntos.
    • Work Units: unidades de trabajo, con opción de editar el tiempo.

    Los privilegios del usuario limitan lo que se ve y se edita. Exporta a pantalla completa y PDF; no a CSV.

    Informe de resolución¶

    Reports → Support → Resolution report lista tickets cerrados y muestra el impacto en tiempo, pausas muertas, personas implicadas y resolución, incluido el feedback del cliente. Se filtra por fecha de creación y cierre, creador y empresa. Exporta a pantalla completa y PDF.

    Informe de tipo de ticket¶

    Reports → Support → Ticket type report agrupa los tickets por empresa y tipo en un intervalo de tiempo. Se filtra por creador, empresa y grupo. Exporta a CSV, pantalla completa y PDF.

    Informe de operadores¶

    Reports → Support → Operator report mide la calidad del soporte por operador: tiempo dedicado, tiempo medio de resolución, feedback del cliente y tickets totales. Se filtra por empresa, usuario, estado y franja temporal.

    Exporta a CSV, pantalla completa y PDF.

    Informes de incidencias de los clientes¶

    Reports → Support → Customer tickets muestra incidencias creadas, resueltas y en progreso, agrupadas por usuario, año y mes. Company es obligatorio; Users permite seleccionar uno o varios usuarios de esa empresa.

    Opciones:

    • Show section state: tabla de estados por mes y usuario.
    • Show section type tickets: tabla de tipos por mes y usuario.
    • Show section total: total global.
    • Created from Pandora FMS: separa los tickets creados desde Pandora FMS y desde Pandora ITSM.

    Exporta a pantalla completa y PDF; no a CSV.

    Informes de proyectos¶

    Los informes de proyectos están en Reports → Project management. Permiten planificar tiempos y costes y ver la evolución del proyecto con las horas imputadas por las personas que colaboran.

    General project report¶

    Reports → Project management → General project report → Select project muestra un proyecto seleccionado. Al entrar sin proyecto aparece un mensaje de error; es normal y no indica un fallo.

    Opciones:

    • Show project: información básica, personas, resumen de trabajo y coste, distribución de tareas, carga de trabajo, actividad y resumen de tareas.
    • Show task activity: para las tareas seleccionadas, horas, costes, estimados y gráficas de distribución y actividad.
    • Show task work unit: fecha, duración, personas y descripción de cada unidad de trabajo de las tareas seleccionadas.
    • Show in table: todas las tareas según filtros de fecha, hito o personas.

    Se puede filtrar por hitos, tareas, fechas, personas y empresa relacionada. Exporta a CSV, pantalla completa y PDF.

    All projects report¶

    Reports → Project management → All projects report filtra por texto en nombre o descripción, propietario, personas implicadas, fecha, grupo, proyectos archivados y campos personalizados del proyecto.

    El listado muestra identificador, grupo, nombre, propietario, personas implicadas y progreso de tareas. Exporta a CSV, pantalla completa y PDF.

    Project expense report¶

    Reports → Project management → Project expense report muestra los proyectos del último mes. Se filtra por fecha de inicio o fin y porcentaje de realización. Show task breakdown desglosa cada tarea. Al seleccionar un proyecto se puede filtrar por hitos. Exporta a CSV, pantalla completa y PDF.

    Project bundle of hours report¶

    Reports → Project management → Project bundle of hours report selecciona un proyecto y un mes. Muestra un resumen por tarea y tickets, con horas consumidas y horas restantes. Se puede filtrar por empresa y contratos relacionados. Exporta a pantalla completa y PDF; no a CSV.

    Informe SQL personalizado¶

    Reports → Custom SQL report permite crear consultas propias que devuelven una tabla exportable a hoja de cálculo o PDF.

    Solo un superadministrador o un usuario con permiso RM puede crear, modificar y borrar informes SQL. Para verlos hace falta RR y pertenecer al mismo grupo del informe.

    Una consulta sencilla:

    SELECT id, name, country FROM tcompany ORDER BY country;

    Los campos se pueden renombrar con alias:

    SELECT
  id AS `Identification number`,
  name AS Name,
  country AS `Country origin`
FROM tcompany ORDER BY country;

    Por seguridad están prohibidos DELETE, DROP, ALTER, TRUNCATE, CREATE, UPDATE, INSERT INTO, EXEC y MERGE. Exporta a CSV, pantalla completa y PDF.

    Consejos para informes SQL¶

    • En las plantillas se puede sustituir _reportname_ por el nombre real del informe SQL e insertar imágenes propias.
    • Al crear un informe SQL se le asigna el grupo None; conviene asignarle un grupo concreto.
    • Para conocer tablas y campos se pueden crear informes con SHOW TABLES; y DESCRIBE <table_name>;. Así no hace falta crear usuarios de base de datos: el ACL se gestiona en Pandora ITSM.

    Buenas prácticas¶

    • Define la pregunta antes de elegir el informe.
    • Guarda búsquedas de tickets reutilizables para los dashboards.
    • Revisa los permisos RR/RM y la visibilidad de grupo antes de publicar.
    • Mantén el cron activo si usas el programador.
    • Usa plantillas para que los PDF sean legibles, no para esconder datos.
    • No conviertas un dashboard en un álbum de gráficos sin dueño.
    • Documenta qué informe responde a cada pregunta y quién lo revisa.

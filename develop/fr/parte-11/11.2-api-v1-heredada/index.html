    API v1 (héritée)¶

    L'API 1.0 de Pandora ITSM reste disponible pour des raisons de compatibilité. Ce n'est pas une API REST : c'est un appel HTTP au fichier include/api.php avec une opération (op) et une liste de paramètres séparés par des virgules. Elle renvoie du CSV par défaut, du XML sur demande et, pour certains appels, du JSON.

    Si vous démarrez une intégration, utilisez l'API v2 du chapitre 11.1. Cette API n'est maintenue que pour les anciens scripts et les intégrations qui parlent déjà son dialecte. La source de vérité est include/api.php et include/functions_api.php ; ce qui n'est pas dans le répartiteur n'existe pas, quelle que soit la documentation ancienne qui le mentionne.

    Ce que c'est et comment l'appeler¶

    L'URL de base est celle de la console suivie de include/api.php :

    https://<Console_web_URL>/pandoraitsm/include/api.php?<paramètres>

    Les paramètres communs sont :

    Paramètre Obligatoire Rôle
    user Oui Utilisateur Pandora ITSM qui exécute l'appel et sur lequel s'appliquent les ACL.
    user_pass Oui, sauf bearer token Mot de passe de l'utilisateur.
    pass Seulement si api_password est configuré Mot de passe spécifique de l'API.
    op Oui Opération à exécuter.
    params Selon l'opération Paramètres de l'opération, séparés par token.
    token Non Séparateur de params ; virgule (,) par défaut.
    return_type Non csv (par défaut), xml ou json selon l'opération.
    info Non info=version renvoie la version sans authentification.

    L'appel d'information ne nécessite ni utilisateur, ni mot de passe, ni adresse IP autorisée :

    …/include/api.php?info=version

    Il renvoie une chaîne semblable à :

    Pandora ITSM Enterprise Edition 5.0.109 Build 260603 MR109

    Une opération inconnue ne renvoie pas d'erreur descriptive : le répartiteur attend 15 secondes puis termine sans corps. Si un script se bloque, vérifiez d'abord le nom de op.

    Authentification¶

    L'API 1.0 enchaîne plusieurs contrôles. Tous les appels, sauf info=version, passent par la liste d'IP et l'authentification de l'utilisateur.

    Liste d'IP¶

    La liste se configure dans Setup → Setup → General setup, champ List of IP with access to API (token api_acl). Par défaut, elle n'autorise que 127.0.0.1.

    Elle accepte des adresses séparées par des virgules, des espaces ou des retours à la ligne, ainsi qu'un astérisque comme joker : 192.168.7.* ou *. Le code utilise une expression régulière, donc le joker peut aussi correspondre à une partie d'une adresse. Ouvrir l'API à * est pratique pour tester et une mauvaise idée en production.

    Mot de passe de l'API¶

    Si api_password n'est pas vide, il faut l'envoyer dans le paramètre pass. S'il est vide, le contrôle est ignoré.

    Le mot de passe circule sans chiffrement. Si vous utilisez cette méthode, l'appel doit passer par HTTPS ; en HTTP, quiconque écoute le réseau le voit.

    Utilisateur et mot de passe¶

    user et user_pass sont obligatoires dans tous les appels qui n'utilisent pas de bearer token. Il n'existe aucun moyen de désactiver ce contrôle : le mot de passe de l'API est un second facteur, pas un remplacement.

    Bearer token¶

    L'authentification peut aussi se faire avec l'en-tête HTTP :

    Authorization: Bearer <token>

    Le token est comparé au champ api_key de l'utilisateur indiqué dans user. La liste d'IP s'applique toujours. Si l'en-tête est présent, l'API n'utilise ni user_pass ni pass ; si le token ne correspond pas, la réponse est 401.

    Exemple avec curl :

    curl -k \
  -H "Authorization: Bearer $PITSM_API_TOKEN" \
  "https://192.0.2.10/pandoraitsm/include/api.php?user=admin&op=get_groups&return_type=xml"

    Si l'authentification échoue, l'API répond 401 sans corps. Il n'y a pas de message distinct pour un utilisateur absent, un mot de passe incorrect ou une IP non autorisée.

    Format des appels¶

    params est une liste ordonnée. Le séparateur par défaut est la virgule, mais il peut être changé avec token :

    …&op=create_workunit&params=1,Description,0.5,0,1,1
…&op=create_workunit&token=|&params=1|Description|0.5|0|1|1

    Deux conventions reviennent dans les appels de tickets :

    • Une virgule dans une valeur s'écrit :::.
    • Un espace se code %20 dans l'URL.

    Par exemple, Doe, John s'envoie comme Doe:::%20John. Toutes les fonctions ne font pas la substitution inverse ; celles qui la prennent en charge l'appliquent au titre, à la description ou au nom, selon le cas.

    return_type accepte csv (par défaut), xml et, uniquement dans les appels qui l'implémentent, json : tickets, unités de travail, états, groupes, utilisateurs, priorités, champs, types et comptage de tickets.

    Les réponses correctes ne valent pas toujours 1 : beaucoup d'appels renvoient l'identifiant créé, un 0 ou un -1. Les ACL sont vérifiées dans chaque fonction et peuvent journaliser une entrée d'audit avant de sortir sans corps.

    Fonctions¶

    Chaque appel possède sa propre fiche. Les paramètres sont indiqués dans l'ordre exact de params ; un paramètre marqué comme obligatoire doit toujours être présent, même s'il peut être vide selon le format.

    get_login¶

    Vérifie que les identifiants sont valides. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_login

    Renvoie : 1 si l'authentification est correcte. En cas d'échec, l'appel a déjà renvoyé 401 avant d'arriver ici.

    create_user¶

    Crée un utilisateur et l'affecte à un groupe et un profil. Paramètres : utilisateur (obligatoire), groupe (obligatoire), profil (obligatoire), e-mail (facultatif), mot de passe (facultatif ; s'il est vide, le nom de l'appelant est utilisé), description (facultatif), nom réel (facultatif), externe (0 ou 1).

    …/api.php?user=admin&user_pass=adminpass&op=create_user&params=jorge,3,4,jorge@example.com,userpass,description,Jorge%20Surname,1

    Renvoie : 1 en cas de succès, 0 en cas d'échec. Exige le droit UM. external=1 crée le niveau -1 (Standalone) ; external=0 crée le niveau 0 (groupé).

    get_incidents¶

    Liste les tickets visibles pour l'utilisateur. Paramètres : chaîne de recherche, état, groupe (obligatoire ; 1 pour tous), priorité, inventaire, propriétaire, créateur, id de ticket et id d'inventaire Pandora.

    …/api.php?user=user&user_pass=userpass&op=get_incidents&params=day,-10,1,-1,0,admin,user1

    États : 0 tous, 1 nouveau, 2 non confirmé, 3 assigné, 4 rouvert, 5 en attente de clôture, 6 en attente d'un tiers, 7 fermé, -10 tous sauf fermés. Priorités : 10, 0, 1, 2, 3, 4, -1.

    Renvoie : CSV, XML ou JSON. Limite interne de 5 000 tickets. Un non-administrateur ne voit que les tickets dont il est propriétaire ou créateur.

    user_exists_in_group¶

    Vérifie si un utilisateur appartient à un ou plusieurs groupes. Paramètres : utilisateur, groupe1, groupe2…

    …/api.php?user=user&user_pass=userpass&op=user_exists_in_group&params=test,4,5

    Renvoie : 1 ou 0. Un administrateur renvoie 1 sans consulter les groupes.

    get_incident_details¶

    Renvoie le détail d'un ticket. Paramètre : id de ticket.

    …/api.php?user=user&user_pass=userpass&op=get_incident_details&params=2

    Renvoie : CSV ou XML avec les champs du ticket.

    create_incident¶

    Crée un ticket. Paramètres : titre (obligatoire), groupe (obligatoire), priorité, description, inventaires séparés par :, type de ticket, e-mail en copie, propriétaire, ticket parent, état (obligatoire), extra_data, résolution, extra_data2, extra_data3, extra_data4 et les champs personnalisés du type à partir de la position 15.

    …/api.php?user=user&user_pass=userpass&op=create_incident&params=Title,2,1,Description%20of%20the%20incident,1:2:3,1,copy@example.com,admin,0,1

    Renvoie : l'id du ticket créé ou -1 en cas d'échec. Exige le droit IW. Un titre vide annule l'appel. Une virgule dans le titre ou la description s'envoie comme :::.

    update_incident¶

    Met à jour un ticket. Paramètres : id, titre, description, épilogue, groupe, priorité, résolution, état, propriétaire, parent, type, extra_data, extra_data2, extra_data3, extra_data4 et champs personnalisés à partir de la position 15.

    …/api.php?user=user&user_pass=userpass&op=update_incident&params=4,new%20title,new%20description,new%20epilog,4,2,1,3,admin,0,6

    Renvoie : résultat de la mise à jour. Si le ticket est fermé, la résolution est enregistrée ; sinon, elle est forcée à 0. Seuls le propriétaire, le créateur ou un administrateur peuvent le modifier.

    delete_incident¶

    Supprime un ticket. Paramètre : id de ticket.

    …/api.php?user=user&user_pass=userpass&op=delete_incident&params=3

    Renvoie : 1. Exige l'accès au ticket.

    add_inventory_to_ticket¶

    Associe un objet d'inventaire à un ticket. Paramètres : id de ticket, id d'inventaire.

    …/api.php?user=user&user_pass=userpass&op=add_inventory_to_ticket&params=1,2

    Renvoie : 1 ou 0. Exige le droit VW.

    get_incident_tracking¶

    Renvoie l'historique de suivi du ticket. Paramètre : id de ticket.

    …/api.php?user=user&user_pass=userpass&op=get_incident_tracking&params=2

    Renvoie : CSV ou XML avec les enregistrements de suivi.

    get_incidents_resolutions¶

    Renvoie le catalogue des résolutions. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_resolutions

    Renvoie : CSV ou XML avec id et name de chaque résolution.

    get_incidents_status¶

    Renvoie le catalogue des états. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_status

    Renvoie : CSV, XML ou JSON avec id et name de chaque état.

    get_incident_priorities¶

    Renvoie le catalogue des priorités. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_incident_priorities

    Renvoie : CSV, XML ou JSON avec id et name de chaque priorité.

    get_incident_fields¶

    Renvoie les champs personnalisés d'un type de ticket et, si un ticket est indiqué, ses valeurs. Paramètres : id de type, id de ticket (facultatif).

    …/api.php?user=user&user_pass=userpass&op=get_incident_fields&params=4,32

    Renvoie : CSV, XML ou JSON avec les champs. Sans ticket, seul le type est renvoyé.

    get_types¶

    Renvoie le catalogue des types de ticket. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_types

    Renvoie : CSV, XML ou JSON avec id et name de chaque type.

    get_tickets_count¶

    Compte les tickets regroupés par colonne et période. Paramètres : colonne, nombre maximum de jours.

    …/api.php?user=user&user_pass=userpass&op=get_tickets_count&params=id_grupo,30

    Renvoie : JSON avec le comptage par groupe. C'est le seul appel qui répond toujours en JSON, même si un autre return_type est demandé.

    get_incident_workunits¶

    Liste les unités de travail d'un ticket. Paramètre : id de ticket.

    …/api.php?user=user&user_pass=userpass&op=get_incident_workunits&params=3

    Renvoie : CSV, XML ou JSON avec les unités.

    create_workunit¶

    Ajoute une unité de travail à un ticket. Paramètres : id de ticket, description, heures, coût (0 ou 1), public (0 ou 1), id de profil.

    …/api.php?user=user&user_pass=userpass&op=create_workunit&params=1,Description,0.5,0,1,1

    Renvoie : 0 ou un message d'erreur. N'accepte pas les tickets fermés et ne duplique pas une unité portant la même description sur le même ticket.

    get_incident_files¶

    Liste les pièces jointes du ticket. Paramètre : id de ticket.

    …/api.php?user=user&user_pass=userpass&op=get_incident_files&params=1

    Renvoie : CSV ou XML avec les pièces jointes.

    download_file¶

    Télécharge une pièce jointe. Paramètre : id de pièce jointe.

    …/api.php?user=user&user_pass=userpass&op=download_file&params=32

    Renvoie : contenu du fichier en Base64.

    attach_file¶

    Joint un fichier à un ticket. Paramètres : id de ticket, nom, taille, description, contenu en Base64.

    …/api.php?user=user&user_pass=userpass&op=attach_file&params=1,example.txt,234,File%20of%20example,aW50ZWdyaWEgcm9ja3M=

    Renvoie : 0 en cas de succès, -1 s'il ne peut pas écrire. Si le fichier existe déjà sur le ticket, renvoie 0 sans le dupliquer.

    delete_file¶

    Supprime une pièce jointe. Paramètre : id de pièce jointe.

    …/api.php?user=user&user_pass=userpass&op=delete_file&params=32

    Renvoie : 0 en cas de succès, -1 si le contrôle de permission échoue, -2 s'il ne peut pas supprimer le fichier physique.

    validate_user¶

    Vérifie l'utilisateur et le mot de passe. Paramètres : utilisateur, mot de passe.

    …/api.php?user=user&user_pass=userpass&op=validate_user&params=jorge,jorge_pass

    Renvoie : 1 si correct, 0 si l'utilisateur n'existe pas ou est désactivé, -1 si le mot de passe est incorrect.

    delete_user¶

    Supprime un utilisateur. Paramètre : utilisateur.

    …/api.php?user=user&user_pass=userpass&op=delete_user&params=pepe

    Renvoie : 1 ou 0. N'autorise pas la suppression de admin. Exige le droit UM.

    user_exists¶

    Vérifie si un utilisateur existe. Paramètre : utilisateur.

    …/api.php?user=user&user_pass=userpass&op=user_exists&params=pepe

    Renvoie : 1 ou 0.

    get_users¶

    Liste les utilisateurs visibles pour l'appelant. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_users

    Renvoie : CSV, XML ou JSON avec les identifiants.

    get_groups¶

    Liste les groupes visibles. Paramètre facultatif : params=1 pour inclure le groupe 1.

    …/api.php?user=user&user_pass=userpass&op=get_groups
…/api.php?user=user&user_pass=userpass&op=get_groups&params=1

    Renvoie : CSV, XML ou JSON avec id et name de chaque groupe.

    get_stats¶

    Renvoie une métrique de tickets. Paramètres : métrique, chaîne, état, utilisateur, groupe, entreprise, inventaire, priorité.

    …/api.php?user=user&user_pass=userpass&op=get_stats&params=sla_compliance
…/api.php?user=user&user_pass=userpass&op=get_stats&params=opened,,1

    Métriques : total_incidents, opened, closed, avg_life, sla_compliance, avg_scoring et avg_worktime. Si aucun groupe n'est indiqué, le groupe 1 est utilisé.

    Renvoie : une valeur CSV ou XML.

    get_incidents_summary¶

    Renvoie le résumé par état. Paramètre facultatif : new, unconfirmed, assigned, reopened, verified, pending_third_person, closed, not_closed ou total.

    …/api.php?user=user&user_pass=userpass&op=get_incidents_summary
…/api.php?user=user&user_pass=userpass&op=get_incidents_summary&params=not_closed

    Renvoie : tous les compteurs ou seulement le champ demandé, en CSV ou XML.

    get_last_cron_execution¶

    Renvoie les minutes depuis la dernière exécution du cron. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_last_cron_execution

    Renvoie : minutes, ou -1 s'il n'y a pas d'enregistrement.

    get_previous_cron_execution¶

    Renvoie les minutes depuis l'exécution précédente du cron. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_previous_cron_execution

    Renvoie : minutes, ou -1 s'il n'y a pas d'enregistrement.

    get_num_queued_emails¶

    Renvoie les e-mails en attente dans la file. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_num_queued_emails

    Renvoie : nombre d'e-mails.

    get_last_invoice_id¶

    Renvoie le dernier bill_id d'une facture soumise. Aucun paramètre.

    …/api.php?user=user&user_pass=userpass&op=get_last_invoice_id

    Renvoie : l'identifiant ou une valeur vide.

    get_invoice¶

    Renvoie les données d'une facture. Paramètre : bill_id.

    …/api.php?user=user&user_pass=userpass&op=get_invoice&params=140601_0071

    Renvoie : CSV ou XML avec la facture.

    create_invoice¶

    Crée une facture. Paramètres : utilisateur, tâche, entreprise, bill_id, concept, montant, taxe, devise, description, verrouillage, utilisateur verrouillant, date de création, date de paiement, état, référence, note interne, type (Submitted ou Received), langue.

    …/api.php?user=user&user_pass=userpass&op=create_invoice&params=admin,,1,140601_0082,paso,3.00,,EUR,,,,,,paid,,,Submitted,

    Renvoie : état et message, par exemple 1,"invoice created" ou 0,"invalid billing id". Exige le droit CW.

    create_company¶

    Crée une entreprise. Paramètres : nom, adresse, identifiant fiscal, rôle, pays, manager, entreprise parente.

    …/api.php?user=user&user_pass=userpass&op=create_company&params=Artica,AlbertoAguilera,12312312,1,Spain,admin,0

    Renvoie : id de l'entreprise créée. Exige le droit CW ; le manager doit exister ou être vide.

    mark_created_incident¶

    Marque l'enregistrement de création d'un ticket avec des informations supplémentaires. Paramètres : id de ticket, texte.

    …/api.php?user=user&user_pass=userpass&op=mark_created_incident&params=10,External%20origin

    Renvoie : résultat brut de la mise à jour, sans CSV ni XML.

    mark_updated_incident¶

    Marque l'enregistrement de mise à jour d'un ticket. Paramètres : id de ticket, texte.

    …/api.php?user=user&user_pass=userpass&op=mark_updated_incident&params=10,Updated%20by%20API

    Renvoie : résultat brut de la mise à jour.

    ovo_manager¶

    Intégration OVO spécifique. Paramètres : titre, groupe, priorité, description, inventaire, type, information supplémentaire, message de groupe.

    …/api.php?user=user&user_pass=userpass&op=ovo_manager&params=Title,2,2,Description,10626,10,extra,msg

    Utilise le groupe 11 et l'utilisateur ovo de façon fixe. Renvoie : un résultat variable selon les mises à jour appliquées. Ce n'est pas un appel général.

    reset_double_factor¶

    Réinitialise l'authentification à deux facteurs. Paramètre : hash chiffré au format de la console (pour les administrateurs).

    …/api.php?user=admin&user_pass=adminpass&op=reset_double_factor&params=<hash>

    Renvoie : JSON avec status. Un utilisateur normal ne peut réinitialiser que son propre facteur.

    Étendre l'API¶

    L'API 1.0 n'a pas de routeur automatique. Ajouter un appel demande deux pièces :

    1. Une fonction dans include/functions_api.php qui reçoit $return_type et les paramètres, puis renvoie ou imprime le résultat.
    2. Un case dans le switch ($op) de include/api.php qui l'invoque.

    Le squelette minimal est :

    function api_my_call($return_type, $user, $params)
{
    // Contrôles ACL et validation.
    $result = 1;

    switch ($return_type) {
        case 'xml':
            echo xml_node($result);
            break;
        default:
            echo $result;
            break;
    }
}

    Et dans le répartiteur :

    case 'my_call':
    $params = explode($token, $params);
    echo api_my_call($return_type, $user, $params);
    break;

    Conservez le format de sortie et les contrôles ACL dans la fonction. L'API v1 ne fournit rien de tout cela à votre place.

    Time management¶

    Clocking in is not an administrative punishment. It is the raw material of the reports: if the time record is fiction, the report is fiction too. Pandora ITSM records the working day, breaks, location and vacations, and then turns that data into calendars, reports and automatic rules.

    This chapter covers both halves of time management: daily time tracking and absence management. The agenda and calendar close the loop, because an hour booked without context is just a number.

    Time tracking¶

    The entry point is People → Time tracking. Superadministrator profiles see everything; everyone else depends on their permissions and the configured menu visibility. In current versions there is no separate module to unlock: if the profile has access to People and the menu is visible, the entry appears.

    Activity¶

    People → Time tracking → Activity shows the summary for the day and the controls for the working day. There are three actions:

    • Start time: starts the timer. Before it starts, it asks for the location: Office, Work from home or Clients.
    • Pause time: stops the timer without closing the working day.
    • Stop time: closes the working day and leaves the record available for reports.

    After starting, the start button is disabled and pause and stop are enabled. To resume after a pause, press the start button again and choose the location. The screen shows worked time, paused time, current status and location, plus a table with the day's intervals: status, location, time range and worked time.

    Automatic stop is enabled by default. It is configured under Setup → Setup, with the Active automatic time tracking stop checkbox and the Stop time tracking after field, which accepts hours between 0 and 23 in steps of 0.05. The initial value is 8.5 hours. If it is disabled, the timer runs until someone stops it; if it is enabled, the system closes the interval when the limit is exceeded. The check runs in the console: if the browser is closed, the interval may remain open until the next connection.

    Team¶

    People → Time tracking → Team is the supervision view. It shows each team member's avatar, name, email, phone, location and status.

    The filters are:

    Filter What it does
    Search by keyword Searches by name, email address or phone.
    Location Filters by Office, Work from home or Clients.
    Status Filters by Stopped, Active, Paused, Vacations or Sick leave.
    Company Administrators only; limits the list to one company.

    Status is read by colour:

    Colour Status
    Green Active, with the timer running.
    Blue Paused.
    Red Stopped, with no working day open.
    Orange On vacation.
    Purple On sick leave.

    Vacation and sick leave take precedence over time tracking: if the user has a vacation or sick leave work unit on that day, the list shows that colour even if the timer is stopped.

    Weekly and monthly time tracker¶

    People → Time tracking → Week and People → Time tracking → Month show activity day by day. By default they show the user running the query; profiles with HR permission can choose another person with the user search.

    The header summarises worked time and paused time for the period. Each day shows the start and end time, the break, the location and a timeline with the intervals. The previous and next week or month buttons move through periods; the next button is disabled while the period has not ended yet.

    With HR permission, Edit entry appears on each day. It opens the activity editor, which lets you add an interval, change the time or location of an existing one and delete it. A manual edit is marked with the warning icon (Alter activity) so the report does not confuse a corrected entry with an original clock-in. A standard user sees their week and month, but cannot edit from these views.

    For the full history there is Reports → People management → Time tracking, available to HR. It filters by user, period (This Week, This Month, Last Month, Last 3 Months or Custom), start and end dates and report type (Daily, Weekly, Monthly or Monthly Detailed). It offers CSV report and Full screen.

    Workflow rules¶

    People → Time tracking → Workflow automates notices and stops based on what the team records. Only profiles with HR permission or administrators can enter. An HR user is limited to their group in the conditions; the company is chosen separately. An administrator can choose any group.

    Clicking Create a workflow creates a rule with a description. In the list you can disable, enable or delete it. Opening the rule name gives access to its conditions and actions.

    Conditions filter users by company or group and check four values:

    Condition What it measures
    Time worked (or more) Accumulated worked time.
    Paused time (or more) Accumulated paused time.
    Exceeded time of day Time exceeded during the day.
    Effective weekly time (hours:minutes) Weekly hour limit, calculated from the configured first day of the week.

    The global condition decides how checks are combined: Match all fields, Match any field or No match. Each condition can be related to the others with AND, OR, AND NOT, OR NOT or XOR, and reordered with Up and Down.

    Actions always send email:

    • Send email to affected user: notifies the user affected by the rule.
    • Send email to: sends to a list of comma-separated addresses.
    • Automatic stop and send email to affected user: also stops the time record.

    The system cron runs the rules. In the standard installation it is include/integria_cron.php, every five minutes. If the cron does not run, the rules are not evaluated, no matter how active they are.

    Agenda and calendar¶

    The calendar in the side menu is the quick view; Full calendar opens the full agenda. The Calendar entry requires agenda access permission (AR), and adding an entry requires write permission (AW).

    The full agenda can show or hide entries, work units, projects, tasks, customers and inventory, and navigate by month, week or day. Creating an entry asks for a title, public visibility, duration (One hour, Two hours, Four hours or One day), alarm, date, time and description. The same form updates or deletes it.

    The vacation calendar is another view: it lives under Reports → People management → General vacation calendar and is explained below, because it only paints approved absences, not the work agenda.

    Vacation management¶

    Vacations are not an email to the boss. They are special work units that go through approval and, once accepted, appear in the calendar and in reports. The flow has three parts: request, approval and reporting.

    Vacation request¶

    People → Work Unit → Vacations and sick leave opens the request form.

    The fields are:

    Field What it does
    Username Affected user. Defaults to the requester. HR, UM, VCM and administrators can choose another person.
    Task Absence type: Vacations, Not working for disease, Not justified or Visit to the doctor.
    Extra vacation Marks the request as extra vacation. The approval queue keeps it and shows it in the Extra vacation column.
    Start date First day of the period.
    Days used Working days covered.
    Description Reason or comment.
    Add row date Adds another period to the same request.

    Only Vacations goes through the approval flow and creates a pending record. The other three options create work units directly, without approval.

    When you click Add, the system checks that there are no approved vacations in the same range. If there are, the request is rejected with a warning. If everything is correct, it stays pending and an email is sent to the person configured for vacation notices.

    Vacation approval¶

    People → Work Unit → Vacation Management is the approval queue. It requires the VCM (Manage Vacations) permission or administrator status.

    The Vacation Request tab shows user, dates, days, whether it is extra vacation and the status. The status changes between Pending, Accept and Reject and is saved with Submit.

    On acceptance, the console creates one work unit for each working day in the period, skipping holidays. If approved vacations already exist in that range, the operation fails and warns. On rejection, only the status changes. In both cases an email is sent to the user.

    The Vacation Request List tab is the history: same table, with the final status of each request.

    Vacation reports are documented in 10.1 Reports and dashboards.

    Time management ends where real work begins: with data someone can read, compare and correct. If time tracking is taken seriously, reports help you decide; if not, they only decorate a meeting.

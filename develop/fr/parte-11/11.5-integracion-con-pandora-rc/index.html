    Intégration avec Pandora RC¶

    Pandora RC n'est pas un simple bureau à distance : c'est un système de gestion à distance dans le cloud. L'agent se connecte vers le portail, pas l'inverse ; l'équipement peut donc changer d'adresse IP, rester derrière un pare-feu ou passer par un réseau domestique sans interrompre la session. Pandora ITSM se contente d'ouvrir la porte depuis l'objet d'inventaire.

    L'intégration comporte deux parties : configurer les identifiants du portail et préparer l'objet d'inventaire qui pointe vers l'agent. Si l'une des deux manque, l'onglet d'accès distant n'apparaît pas ou la connexion échoue.

    Ce que c'est¶

    Pandora RC est un service SaaS de gestion à distance des équipements. Chaque appareil possède un agent installé et un identifiant ; la console Pandora ITSM utilise cet identifiant pour demander un token et ouvrir une session dans un onglet de l'inventaire.

    La session s'affiche dans un iframe avec les vues suivantes :

    Onglet Rôle
    Information Résumé de l'agent et état de la connexion.
    Terminal Terminal distant.
    Display Bureau distant.
    Processes Processus de l'équipement.
    Services Services système.
    Files Explorateur de fichiers.

    Les onglets ne fonctionnent que si l'agent Pandora RC a activé les modules correspondants. L'intégration ne les active pas à sa place.

    Configuration¶

    Le point d'entrée est Setup → Setup → Pandora RC. Seuls les administrateurs ou les profils disposant du droit FM peuvent y accéder ; l'intégration n'est pas disponible dans les installations SaaS.

    Le formulaire comporte deux blocs enregistrés séparément :

    1. Enable Pandora RC : sélectionnez Yes et cliquez sur le bouton Update gris de cette ligne. Ce bouton n'enregistre que l'activation.
    2. Pandora RC API : renseignez l'utilisateur, le mot de passe, le hostname, le port et le timeout, puis enregistrez avec le bouton Update vert en bas à droite.

    Si vous enregistrez les identifiants avant d'activer l'intégration, le formulaire des identifiants ne s'affiche même pas. Activez d'abord, configurez ensuite.

    Les champs de l'API sont :

    Champ Valeur par défaut Ce qu'il attend
    User Vide Utilisateur Pandora RC.
    Password Vide Mot de passe de l'utilisateur.
    API Hostname portal.ehorus.com Hôte du portail, sans protocole ni port.
    API Port 443 Port HTTPS du portail.
    Request timeout 30 Attente maximale en secondes ; 0 désactive la limite.

    Les valeurs sont stockées dans la configuration avec les tokens ehorus_enabled, ehorus_hostname, ehorus_port, ehorus_req_timeout, ehorus_user et ehorus_pass. Le mot de passe est stocké dans la configuration ; il n'est pas affiché en clair en dehors du formulaire.

    L'activation initiale crée le champ global PandoraRCID pour les types d'objet Pandora FMS et migre les anciennes valeurs eHorus Id. Sur les installations issues de versions précédentes, il est normal de voir encore le libellé eHorus Id ; la valeur est conservée et se retrouve dans le nouveau champ.

    Tester la connexion¶

    Le bouton Test (libellé Start) teste les valeurs présentes dans le formulaire, sans les enregistrer. Il envoie une requête au portail et affiche une icône de succès ou d'échec avec l'un de ces messages :

    Message Signification
    Empty user or password L'utilisateur ou le mot de passe manque.
    User not found Le portail ne reconnaît pas l'utilisateur.
    Invalid password Le mot de passe est incorrect.
    Connection timeout Le portail ne répond pas dans le délai imparti.

    Un test réussi n'enregistre rien : cliquez ensuite sur le bouton Update vert. Si le test échoue, vérifiez le hostname, le port, les identifiants et l'accès réseau avant de toucher au reste de l'intégration.

    Préparer l'objet d'inventaire¶

    Avant de connecter, le serveur Apache de Pandora ITSM doit autoriser l'intégration de la console dans un iframe de même origine :

    Header always set X-Frame-Options "SAMEORIGIN"

    Sans cet en-tête, le navigateur peut bloquer l'iframe et la session distante reste vide.

    L'objet d'inventaire doit avoir une valeur dans le champ PandoraRCID — ou dans l'ancien eHorus Id —. Cette valeur est l'identifiant de l'agent Pandora RC.

    1. Allez dans Inventory → Create new object, saisissez un nom et cliquez sur Create.
    2. Ouvrez le lien Click here to continue working with Object #XXX pour ouvrir l'objet créé.
    3. Dans Object type, choisissez Computer ou Pandora agents, selon le type d'équipement.
    4. Dans Custom fields, renseignez PandoraRCID avec l'identifiant de l'agent. Sur les installations anciennes, le champ apparaît comme eHorus Id.
    5. Cliquez sur Update changes pour l'enregistrer.

    Le champ est global pour les types d'objet Pandora FMS. S'il n'apparaît pas, vérifiez que l'intégration est activée et que le type d'objet fait partie de ceux qui reçoivent le champ ; sur une installation ancienne, il peut encore s'afficher sous le nom eHorus Id.

    Connexion distante¶

    Une fois l'objet prêt, ouvrez sa fiche d'inventaire. Si l'intégration est activée et que le champ a une valeur, l'onglet Pandora RC apparaît avec l'icône du produit.

    À l'entrée, la console affiche Remote management of this device with Pandora RC et le bouton Launch. Lorsque vous cliquez, Pandora ITSM demande un token au portail, charge l'iframe et affiche les onglets de la session. Si l'agent a un mot de passe, la session elle-même le demande à la connexion ; gardez-le à portée de main.

    Le token de session expire. Lorsque cela arrive, l'iframe est retiré et le message The connection was lost and the authorization token was expired. Reload the page to request a new authorization token. apparaît. Rechargez la fiche pour en demander un nouveau.

    Prérequis et problèmes fréquents¶

    • Le serveur Pandora ITSM doit pouvoir joindre https://<hostname>:<port> du portail. Le port habituel est 443.
    • Le certificat du portail doit être valide : la vérification TLS n'est pas désactivée.
    • L'intégration exige un administrateur ou le droit FM, et n'est pas disponible en SaaS.
    • L'agent doit avoir activé les modules terminal, bureau, processus, services ou fichiers dont vous avez besoin.
    Symptôme Cause probable Que faire
    Pandora RC is not enabled L'intégration est désactivée. Activez-la dans Setup → Setup → Pandora RC.
    Missing eHorus Id L'objet n'a pas d'identifiant d'agent. Renseignez PandoraRCID ou eHorus Id et enregistrez.
    There was an error retrieving an authorization token Identifiants, hôte, port ou TLS incorrects. Utilisez Test et vérifiez l'accès réseau.
    There was an error retrieving the agent token L'identifiant n'existe pas ou l'utilisateur n'a pas accès à l'agent. Vérifiez la valeur du champ et les droits dans Pandora RC.
    There was an error retrieving the agent data L'agent ne répond pas ou le portail ne le renvoie pas. Vérifiez que l'agent est connecté.
    L'iframe reste vide X-Frame-Options: SAMEORIGIN manque ou le navigateur le bloque. Ajoutez l'en-tête dans Apache et rechargez.
    The connection was lost and the authorization token was expired Le token de session a expiré. Rechargez la fiche de l'objet.
    Connection timeout Le portail ne répond pas dans le délai configuré. Augmentez le timeout ou vérifiez la connectivité.

    L'intégration ne stocke pas la session distante dans Pandora ITSM : le token est éphémère et la conversation réelle se fait entre le navigateur et l'agent Pandora RC. Si l'accès échoue, le problème vient généralement du réseau, du certificat ou de l'agent, pas de l'objet d'inventaire.

    AI and chatbot¶

    The Pandora ITSM chatbot is not a window that says "hello" and then waits. It is a support system with two parts: a chat server with its web client and, optionally, an artificial intelligence engine that learns from the knowledge base and from conversations to suggest answers.

    Without AI, the chat still works: users open a conversation and an operator answers. With AI, the system can answer on its own, assist the operator or do both depending on the mode. The difference between "having chat" and "having a chatbot" is that second part, and in training it.

    The architecture has three elements: the chat client, which the user interacts with; the chat server, which the operator works with; and the prediction engine, which generates the answers. The client and server ship with Pandora ITSM; the prediction engine is installed separately.

    Chat server¶

    Global configuration is in Setup → Setup → ChatBot, under Chat Global Options.

    The main fields are:

    • Enable chat: turns the service on.
    • Ws url, Ws port and Ws password: address, port and password of the chat web service.
    • Ws channel by default: channel used by default.
    • Check chat server: checks the connection; a green dot means it responds.
    • General chat: Disabled, Only IA or Manual.
    • Ticket chat: Disabled or Enabled for chat inside tickets.
    • Enable SSL: enables HTTPS and shows the certificate and key paths.

    Ws url must be the public URL of the Pandora ITSM installation —the same one shown in Public access to server in general setup—, not an internal address the user's browser cannot reach. If the chat does not connect, check that URL before touching Node.js.

    If AI is enabled, the the buttons to update the knowledge base model and the conversational model buttons appear below; they retrain the models with the current information.

    HTTPS and Node.js¶

    Serving the chat outside the console should use HTTPS. Enable Enable SSL, replace the sample certificates with your own, save with Update and check that Check chat server stays green.

    The chat server is a Node.js application under extras/chat_server. A typical installation on a yum system is:

    curl -fsSL https://rpm.nodesource.com/setup_lts.x | bash -
yum install -y nodejs
npm i -g pm2
cd /var/www/html/pandoraitsm/extras/chat_server
npm update
pm2 start server.js

    Use a Node.js version compatible with the current dependencies —the server uses Express 5, so it needs a modern version— not the Node 12 from old manuals. If npm complains about the version, the chat will not start even if the configuration is correct.

    To start it with the system, create /etc/systemd/system/pandoraitsm-chat.service:

    [Unit]
Description=Pandora ITSM Chat Server
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/node server.js
Restart=always
User=root
Environment=NODE_ENV=production
WorkingDirectory=/var/www/html/pandoraitsm/extras/chat_server

[Install]
WantedBy=multi-user.target

    And enable it:

    systemctl daemon-reload
systemctl enable --now pandoraitsm-chat.service

    The database connection is configured in extras/chat_server/config/config.js. The default values work for a standard installation; change them if the database is on another server or uses other credentials.

    AI engine and per-channel configuration¶

    The prediction engine is installed as root and listens on port 6000/tcp:

    yum install -y python3 python36-Cython
wget http://<server>/prediction_engine-latest.tgz
tar xvzf prediction_engine-latest.tgz
cd prediction_engine
./install.sh
systemctl restart prediction_engine.service

    AI is configured per channel, not globally: Support → Chat → Channel Manage, click the channel name and Enable Chat IA.

    There are two AI modes:

    • Pandora ITSM AI: uses the local prediction engine. Set IA url —the web service URL, for example http://192.168.1.10—, IA port —6000 by default— and Mode IA:
    • Manual: the AI does not answer; the operator runs the conversation.
    • Semi-auto: the AI suggests answers and the operator chooses.
    • Full-auto: the AI answers on its own.
    • ChatGPT (OpenAI): uses the OpenAI API. Set API Key, Model (gpt-4 or gpt-3.5-turbo), Max tokens, Context time, Temperature, Avatar, Title, Subtitle and Context.

    Full-auto also shows the response times and the certainty threshold:

    • Initial response time: seconds before the first answer.
    • Response time between conversations: wait between one question and the next.
    • Progress bar timeout: time the operator has to choose an answer before the AI answers on its own.
    • Certainty threshold: minimum confidence, between 0 and 1, to accept an answer. A low value answers everything; a high one prefers silence.

    In ChatGPT, Context is the system message sent at the start. Pandora ITSM adds the instruction to answer in the user's language —or the channel's default language if the user's is not available—. Temperature ranges from 0 to 1: the lower it is, the more predictable; the higher, the more creative.

    Before changing models or training, make a backup:

    cp -r /opt/prediction_engine/models /opt/prediction_engine/models.bak

    To restore:

    cp -f /opt/prediction_engine/models.bak/* /opt/prediction_engine/models/

    Training the models¶

    The normal path is the the buttons to update the knowledge base model and the conversational model buttons in Setup. Manual training is advanced and only makes sense if you need control over the corpus.

    The question-and-answer model is trained with a CSV in this format:

    lang;question;answer
"es";"¿Cómo abro un ticket?";"En Support → Create new ticket."
"en";"How do I open a ticket?";"In Support → Create new ticket."

    You can generate it from the Pandora ITSM database:

    SELECT id_language AS lang, title AS question, data AS answer
FROM tkb_data
INTO OUTFILE '/opt/prediction_engine/data/pandoraitsm_kb.csv'
FIELDS TERMINATED BY ';' ENCLOSED BY '"'
LINES TERMINATED BY '\n';

    Compress the CSV, place it in /opt/prediction_engine/data/ and train:

    cd /opt/prediction_engine/src
python kb_train.pyc

    Conversational dialogues are defined in YAML per language:

    categories:
  - Support
  - Billing
conversations:
  - - Hello
    - How can I help you?
  - - I want to open a ticket
    - Go to Support and click Create new ticket

    The files go in /opt/prediction_engine/data/chat_es or chat_en, depending on the ISO language code, and are trained with:

    cd /opt/prediction_engine/src
python chat_train.pyc

    Besides the YAML files, Support → Chat → Conversations → Data management lets you add conversational items by category and language and search them by keyword.

    Using the chat and channels¶

    Channels define where conversations happen. Support → Chat → Channel Manage lists the channels and lets you create, edit, delete and generate the code to embed them.

    Each channel needs at least one operator. With Edit users you add users and set their description, avatar and languages. The operator can have a different avatar from their user record and several support languages.

    Operators work from Support → Chat → Chat View. The screen shows conversations with status, user, channel, language, active time, operator and associated ticket. To receive sound notifications you must be on that screen; the chat does not notify you from another section.

    If an internal user opens the chat, the conversation shows who it is. If an anonymous visitor opens it from outside, it appears as an external user.

    To use the chat outside Pandora ITSM, click Generate Bundle on the channel. The star icon shows the JavaScript snippet to embed in the website or application. The snippet URL is the Public URL configured on the chat server; it must be reachable from where the users are, usually the Internet.

    Good practices and common problems¶

    • Use HTTPS if the chat will be outside the console. The browser warning scares away any visitor.
    • Dedicate one channel per use —internal support, public website, presales— and do not mix operators and languages without a reason.
    • Before training, copy /opt/prediction_engine/models. A badly prepared corpus takes the previous model down with it.
    • If the chat does not connect, check in this order: Ws url, the Node.js service, Check chat server and the certificates.
    • If the AI does not answer, check the channel mode, the engine URL and port, and that the prediction_engine service is on port 6000.
    • Rotate the OpenAI API key if you share it or suspect it has leaked.

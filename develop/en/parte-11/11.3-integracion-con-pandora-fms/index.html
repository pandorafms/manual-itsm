    Pandora FMS integration¶

    Pandora FMS monitors; Pandora ITSM responds. The integration exists so that the alert and the ticket do not live in separate worlds: a monitoring alert can open a ticket, and the technician who resolves it can see the asset that triggered it.

    The integration runs in two directions. From Pandora FMS, tickets in Pandora ITSM are created, closed, viewed and edited, either by hand or automatically through alerts and event responses. In the other direction, Pandora ITSM receives the inventory of the Pandora FMS agents and turns it into Computer objects with their hardware, software and extended information.

    Everything relies on the Pandora ITSM API v2. There is no shared database and no special agent: FMS calls the API with a token, and the API does the rest.

    Requirements and permissions¶

    Before configuring anything, check these points:

    • Pandora FMS and Pandora ITSM can reach each other over the network, preferably over HTTPS.
    • The Pandora FMS version is 783 or later if you are going to use the joint installation from its console.
    • The Pandora FMS IP is allowed in Setup → Setup → General setup → List of IP with access to API in Pandora ITSM. By default only localhost is allowed.
    • You have an API v2 token generated in Pandora ITSM. Chapter 11.1 explains how to create one.
    • The token user has the IM (ticket management) and VW (inventory write) permissions. Without them, the API rejects FMS calls.

    The token is the integration credential. Do not share it with other users or reuse it for a second tool; if it leaks, delete it and create another.

    Configuring the communication¶

    There are two steps in Pandora ITSM: allow the IP and create the token.

    1. Add the Pandora FMS IP or range in Setup → Setup → General setup → List of IP with access to API.
    2. Generate a token in People → Edit my user → Create Token API v2, with a label such as Pandora FMS and an expiration date.
    3. Check that the token user can manage tickets (IM) and write inventory (VW).

    In Pandora FMS, the integration is configured in its incident management section, setting the Pandora ITSM URL and the token. The detailed procedure lives in the Pandora FMS manual; it is not repeated here because it changes with the monitoring console and is not Pandora ITSM documentation.

    When the communication works, FMS can create and close tickets in ITSM and show existing tickets. The quickest test is to open a ticket from FMS and check that it appears in Support → Tickets in Pandora ITSM.

    Inventory synchronisation¶

    Synchronisation turns Pandora FMS agents into Pandora ITSM inventory objects. It is configured in Setup → Setup, tab Pandora FMS Inventory.

    The screen has three blocks:

    • Clean objects: days after which objects marked as Missing and without a parent are deleted. 0 disables the cleanup.
    • Remote inventory: default values for the objects created by the synchronisation. Default owner is mandatory; associated companies and users decide their visibility.
    • Nodes connected: the Pandora FMS servers that have successfully connected to Pandora ITSM.

    The node table shows the node name, the connection path —for example, http://172.16.0.1:90/pandora_console/api/v2—, the progress of synchronised agents, the connection status and the delete operation. A green dot means the node responds.

    The node is not added by hand in Pandora ITSM: Pandora FMS registers it when the communication works. If it does not appear, the problem is in the FMS configuration, the URL or the token, not on this screen. To restart a connection, delete the node and configure it again from Pandora FMS.

    Each synchronised object type sets its pace with Sync interval: Never, Weekly, Every 15 days, Monthly or First time only. The option only appears when nodes are configured and the type is associated with a Pandora FMS schema. Type, field and stock details are in chapter 4.1.

    Synchronised objects are of type Computer and are linked to the agent through id_pandora. Their record shows the Hardware, Software and Extended Info tabs with the information collected by Pandora FMS.

    Synchronisation is not immediate: the inventory cron, include/inventory_cron.php, runs it, usually every five minutes. On each run it records the inventory_crontask mark, synchronises the nodes, expires overdue schedules and removes Missing objects that no longer have a parent.

    Joint installation from the Pandora FMS console¶

    Pandora FMS can install a Pandora ITSM instance from its own console. It is a quick way to test the integration, not the recommended path for production.

    In Pandora FMS, go to Management → Settings → System Settings → ITSM and click Install ITSM.

    Before installing, Pandora FMS checks three things:

    • That the itsm database does not exist; if it does not, it is created.
    • That the Pandora FMS user —usually pandora— has permission to create it.
    • That the /var/www/html/pandora_console/itsm directory does not exist; it will be created during the installation.

    If the database user lacks permissions, the MySQL administrator must grant them before continuing:

    GRANT ALL PRIVILEGES ON `itsm`.* TO `pandora`;

    The installation downloads the required packages from the official Pandora FMS repository and creates the ITSM directory inside the Pandora FMS console. The progress shows the steps and, at the end, a link to access the Pandora ITSM console for the first time.

    When it finishes, check that you can access Pandora ITSM and that Pandora FMS can see the tickets. If the joint installation fails, review the MySQL permissions and disk space before repeating it.

    Good practices and common problems¶

    • Use a dedicated token for the integration, with a label and an expiration date. If something leaks, you know what to delete.
    • Allow only the Pandora FMS IP, not an open range.
    • Check that the token user keeps IM and VW; a profile change breaks the integration without warning.
    • If the node does not appear, check the URL and token in Pandora FMS. If it appears but does not progress, look at the cron and the connection status.
    • Do not delete a node while it is synchronising. Wait until it finishes or the progress stops.
    • The joint installation is for testing. For production, install Pandora ITSM separately and configure the integration through the API.

    For API and token details, go back to chapter 11.1. For object types, fields and stock control, to chapter 4.1. For tickets coming from FMS, to chapter 3.1.

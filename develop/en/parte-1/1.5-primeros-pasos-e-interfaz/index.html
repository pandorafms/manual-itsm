    First steps and interface¶

    The Pandora ITSM console has changed more than the continuity of its name suggests. The first login no longer leaves the user in front of a greeting and a search box: it opens a tactical dashboard, a notifications bell with its own centre and a side menu that can be collapsed. Anyone coming from the old documentation will recognise the product; the screen, not so much.

    This chapter covers the first day: signing in, understanding what you are looking at and not mistaking a feature that has changed for one that is broken. Each module is covered in its own chapter; this is the map.

    Login screen¶

    The console opens at http://<IP-or-FQDN>/pandoraitsm, or at the path used by your installation. On a first start, read chapter 1.1 first: the initial connection screen may include steps that do not appear in a normal login.

    The form asks for two things and hides neither: the user (Nick) and the password. The eye icon shows what you have typed; the LOG IN button sends it. The Docs and Support links are at the top left; the version appears at the bottom unless the administrator hides it.

    The initial load creates an installation account:

    User Password
    admin pandoraitsm

    The historical integria password is no longer the one shipped with the initial load. If you use it, login fails and the error message will not tell you that you are mixing up manuals.

    The admin account is not for everyday use

    Sign in as admin, change the password and create the named accounts the team needs. Sharing admin between several people is an expensive way to lose track of who did what. Account creation and permissions are explained in chapter 2.1.

    On a new Enterprise installation, the licence agreement may appear before the form. You must accept it to continue; without acceptance there is no console.

    If two-factor authentication is enabled, a second field appears after the user name and password: Double factor authentication code. The code is requested once per login. An administrator can reset it from the login screen with Reset auth code; a standard user must ask their administrator for a reset. Security configuration is covered in chapter 2.2.

    Forgot your password? The Forgot your password? link opens the recovery flow: enter the user name, the console sends an email with a validation code and, once the code is entered, shows a new password. If the user has no email address configured or email delivery is unavailable, the form itself refers you to the administrator. The new password is shown only once; copy it before closing the window.

    Pandora ITSM home page¶

    After login, the console decides what to show on the home page. There are two scenarios, and it is worth knowing which one applies to you:

    • Tactical welcome view: shown by default when the user has no dashboard assigned. It displays Welcome back <name> !👋, the sentence This is the latest data in your default tactical view. and the link Change to a custom dashboard →.
    • Dashboard: if the administrator has defined a global dashboard, or the user has one assigned and has report read permission (RR), the home page loads that dashboard instead of the tactical view.

    The Change to a custom dashboard link opens the profile, at the Dashboard (welcome screen) field. There you can choose Global dashboard or one of your own. The profile is detailed in chapter 2.1 and dashboards in 9.1.

    A dashboard is made of widgets: welcome message, search box, ticket lists, evolution and SLA charts, statistics, links and custom SQL. It is not a copy of the tactical view; it is a screen you assemble and arrange.

    The tactical view is not decoration: it summarises activity for the configured period, 21 days by default (Welcome view field, on the Setup page). These are its blocks:

    Block What it shows
    Open / Closed tickets Tickets opened and closed in the period, with the total and percentage.
    Tickets activity Ticket activity trend.
    Tickets statistics Total tickets, work units, average lifetime, average work time, positive ratings, SLA compliance and total time.
    Top 5 companies by creator The five companies that opened the most tickets.
    Top 5 assigned users The five users with the most assigned tickets.
    Top 5 ticket submitters The five users who submitted the most tickets.
    Top 5 active tickets The tickets with the most work unit hours.
    Tickets by status Ticket distribution by status.
    Tickets by priority Ticket distribution by priority.
    Latest tickets Latest tickets with title, date, owner, status and priority.
    Logged in users Users connected at that moment.
    Tickets general report Time series of tickets for the period.

    When there is no data, the block says No data to show; this is not a loading error. A user without IR permission does not see real statistics: the blocks appear empty. That is ACL behaviour, not a broken screen.

    The home page is not the only place to search. Global search is in the header and covers every area you can access: tickets, projects, people, knowledge base, contracts, invoices and wiki, plus deals, quotes, deal registrations, notes, tasks and CRM meetings. The old search box on the home page still exists, but as a dashboard widget (Search box), with check boxes for Knowledge Base, Wiki, Ticket management, Project management, People, Contacts, Contracts, Companies and Invoices. If you do not see it, it is not missing: it is not on the dashboard.

    The result limit per area is configured under Setup → Visual (global_search_limit, 10 by default). CRM blocks show five and a Search more button when there are more results.

    Three optional notices may appear before you are fully in: a window with your last login if the administrator enables it, News board updates once per session and a browser reminder if you are not using Firefox, Chrome or Safari. None of them blocks your work; close them and continue.

    Console elements¶

    The console has three fixed areas and one floating guest: header, side menu, workspace and chatbot.

    The header groups the global actions:

    Element What it is for
    Logo and title Return to the home page. The title and subtitle are customised under Setup → Visual.
    Search Global search across every permitted area.
    Autorefresh Automatic refresh; it only appears in All tickets.
    Bell Opens the notification centre and shows pending notices.
    Chat notifications Internal chat status, if the module is active and you have permission.
    Help Documentation, support portal, feedback form (Enterprise) or community forum.
    Setup Console configuration; administrators or profiles with management permission only.
    User Opens your profile and shows the identifier in brackets.
    Sign out Ends the session.

    The title, subtitle and light and dark theme logos are changed under Setup → Visual. A group can have its own banner, which replaces the general logo in the side menu.

    The bell is not decoration. It opens a list with search by subject, type or source, a type filter and actions to mark as read or unread and delete, one by one or in bulk. In the profile, on the Notifications tab, you choose the channel for each type of notice: Email, Notification or Both. The configurable sources are Support, Projects, Changes, CRM, People and Inventory; personal notices are shown in the centre but are not configured per channel. System notices (PHP, MySQL, cron, licence, database, files, Chromium, API and Warp) are managed by the administrator and only appear if the console supervisor has enabled that group. The bell updates without reloading the page and each notice links to the ticket, task, change or note that originated it.

    Mentions are written as @user in a note, work unit or comment. The mentioned user receives a Mention in a ticket, Mention in a work unit or Company note mention notification, depending on the source, and can open the item from the bell.

    The chat icon in the header shows internal chat notifications and its status. Do not confuse that chat with the chatbot in the bottom-right corner: the first is a conversation between users; the second is the AI assistant, configured in chapter 11.6.

    The side menu has two modes: classic, with labels visible, and collapsed, with icons only and fly-out submenus. The button at the end of the menu switches between them and the preference is stored in the browser. The menu logo returns to the home page.

    The menu includes two quick navigation aids: Go to User, under People, and Go to Inventory #, under Inventory. They only appear with permission and accept the identifier or the name, depending on the field.

    The theme is chosen in the profile: Light, Dark or System. System follows the operating system theme. If the user chooses nothing, the global theme from Setup → Visual applies.

    The calendar in the side menu shows the current month and, with permission, opens the full calendar or adds an entry. Chapter 7.1 explains time management.

    The User info entry groups personal shortcuts. The options change with the user type and permissions:

    Option What it opens
    Name and avatar Your profile.
    Workunit report The monthly work unit report.
    My tickets Tickets owned by the user.
    Workunit Quick creation of a work unit.
    Full graph report The people graph report.
    My project tasks Assigned project tasks.
    My tasks Assigned CRM tasks.
    My inventory tasks Assigned inventory tasks.
    Notifications The notification centre, with the number of unread notices.

    About ITSM closes the menu. It shows version information and, for administrators, the License Info and System Info tabs, plus the System report button. Licensing is explained in chapter 1.4.

    Menu map¶

    The menu order is not arbitrary, but it is not universal either: it depends on permissions, configured menu visibility and active modules. This is the default list for an administrator:

    Menu What it contains Chapter
    Projects Projects, tasks, Gantt, milestones, boards, project and task types and workflow rules. 6.1
    Changes Changes, teams, templates, statuses, types, priorities, risks, impacts and task statuses. 5.1
    Support Tickets, CSV import, ticket types, ticket templates, work order templates, tags, teams, SLA, workflow rules, knowledge base, downloads and chat. 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7
    Wiki Pages, search, file upload, administration, history, permissions and syntax. 3.6
    Inventory Dashboard, lists, search, stock, CSV import, tasks, types, statuses, tags and catalogue. 4.1
    Reports Dashboards, report manager, templates, scheduler, library, support, people, project and custom SQL reports and time tracking. 10.1
    CRM Contacts, companies, contracts, invoices, deals, quotes, products, workflows and tasks. 8.1, 8.7, 8.8
    Marketing Forms, templates, campaigns, mail servers and contact lists. 9.1
    People Users, groups, profiles, roles, teams, work units and time tracking. 2.1, 7.1
    Setup General, visual, authentication, mail, file manager, news board, database, links, events, audit, logs, translations, backups, menu visibility and console extensions. 12.1, 12.3
    Warp update Online and offline updates, options, journal and licence. 1.2, 1.4
    Calendar Monthly calendar, full calendar and entry creation. 7.1
    User info Profile and personal shortcuts for work, tickets, projects, CRM, inventory and notifications. 2.1, 3.1, 7.1
    Links Links configured under Setup → Links, including the documentation link. 12.1
    About ITSM Version, licence and system information. 1.4, 12.1

    A Standalone user sees a subset: essentially their own tickets. The Setup and Warp update menus and the licence and system tabs in About ITSM are administrative. Chat and Marketing only appear if the module or integration is active and the user has permission.
